# DepScan v3.0.1

This patch release fixes Windows MSI PATH registry-type preservation and updates
noyalib to 0.0.64 following incoming PR #96. CLI commands, public Rust time types,
JSON schema 4, Rust 1.96.0 support and the five-target/16-file artifact contract remain.

## Windows MSI lifecycle

- Preserve `REG_SZ` and `REG_EXPAND_SZ` when installation, repair, upgrade, uninstall
  or rollback changes PATH entries. The v3.0.0 MSI could change `REG_EXPAND_SZ` to
  `REG_SZ` even when uninstall restored the text exactly (DS-127).
- Keep PATH entry management in Windows Installer. A small native helper captures
  only the original type and restores it over current raw bytes, with no PATH
  snapshot, executable command or registry key supplied by MSI action properties.
  The deferred and rollback exports write only the fixed machine PATH value.
- Sequence old-product removal after `InstallExecute`, retaining component identities,
  so successful and failed upgrades preserve the installed binary and environment.
- Add native registry fixtures, compiled-MSI action/order checks, lifecycle and forced
  rollback tests to the existing Windows quality job. Exercise both registry types,
  Unicode and expandable references. Keep fault injection in test packages only.
- Build the helper independently of cargo-dist's executable staging directory and
  check the maintained WiX definition's version and upgrade identities explicitly.

The immutable v3.0.0 MSI remains unchanged. This release preserves the PATH type
present when an operation begins; it cannot infer an earlier type already changed
by a legacy installer. Existing affected installations may need administrator review
of their original environment baseline.

## Dependencies and compatibility

Upgrade noyalib 0.0.63 → 0.0.64, retaining the `std`-only feature selection.
Its upstream patch improves printable-ASCII scalar performance without changing
the public API or parser acceptance. Refresh the compatible lockfile to
async-compression 0.4.53 and Hyper 1.13.0. DepScan already requires patched `url` 2.5.9;
the optional noyalib validator feature is not enabled. Retain eMudhra distrust
protections and patched Tokio/Rustls requirements.

## Verification and provenance

Preparation requires the release gate, strict Clippy, current dependency/advisory
checks and the exact artifact plan. Required protected-main CI includes the MSRV
and native Windows MSI tests. Publication is followed by checksum/API-digest and
source/tag/workflow-bound attestation verification, native archives and the published
tagged action on all five targets, and installation of the published MSI on Windows.
Exact commits, tag object, run IDs and native results are recorded on the protected
integration PR and linked from the published notes. Local test candidates establish
preparation evidence; they are not the public release assets.
