# DepScan v2.0.5

This maintenance and security-hardening release includes DS-116–DS-121 from
`develop`, following dependency PRs #74–76. JSON schema version 4, Rust 1.96.0,
and the five-platform, 16-file release contract remain unchanged.

## Security and dependencies

- Require Rustls 0.23.46 for native downstream consumers. The previous checked-in
  lockfile and v2.0.4 binary already used that version; the new production constraint
  also prevents older downstream locks from resolving Rustls 0.23.44.
- Retain the eMudhra distrust protections, removed bundled roots, and patched Tokio
  introduced in v2.0.4. Platform trust stores and CI runners still need OS updates.
- Refresh the complete compatible dependency graph, including noyalib 0.0.60,
  TOML 1.2.1, ZIP 9.5.0, and AWS-LC. Preserve upstream-constrained parallel versions
  and intentionally vulnerable scanner fixtures.

## Correctness and maintenance

- Classify prereleases using the SemVer prerelease field. Stable versions with
  hyphens in build metadata, including WASI package versions, now remain eligible
  for registry selection instead of causing a soft failure.
- Upgrade checksum-verified cargo-dist to 0.34.0 and refresh SHA-pinned artifact
  actions while retaining publication permissions and immutable-tag boundaries.
- Require fresh stable-requirement, complete-lockfile, and advisory checks before
  every push; document ownership-scoped post-push cleanup.
- Compact historical issue records to the 500-word soft cap with links to complete
  immutable evidence. Preserve issue IDs, status, and historical source records.

## Verification and provenance

Release preparation, protected-main integration, publication, and native acceptance
are separate gates. Exact commits, tag object, run IDs, downloaded asset digests,
attestation checks, and platform-native results are recorded on the protected
integration PR and linked from the GitHub release notes. MSI packaging and provenance
verification do not establish native MSI installation behavior.
