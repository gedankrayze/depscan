# DepScan v2.0.3

Publication status and artifacts are tracked on
[GitHub Releases](https://github.com/gedankrayze/depscan/releases).

This corrective release hardens security-policy evaluation, dependency identity,
provider inputs, and report interoperability. No CLI or report-schema break is
intended; JSON schema version 4 and the Rust 1.96.0 support floor are unchanged.

## Fixes

- Suppression expiry uses the real UTC scan date. Reproducible report timestamps
  cannot reactivate expired exceptions or prematurely expire active ones.
- Pipenv index/source metadata controls public enrichment; source-only packages
  and custom categories remain visible with conservative classification.
- pnpm private tarballs, mismatched public tarballs, Git, and directory sources
  cannot be queried as unproven public npm coordinates.
- SARIF omits unavailable help links and emits encoded source URIs, including
  Windows paths. Empty advisory summaries retain a valid rule description.
- PyPI latest/range matching excludes releases without downloadable non-yanked files.
- Registry and OSV JSON reads enforce a 64 MiB decompressed response limit.
- Patched ZIP, rustls, and quinn-proto dependencies remove the audited RustSec
  findings; ZIP 9 archive-name handling preserves existing safety budgets.

## Maintenance

Rust 1.99.1 is coordinated across native CI, release-quality commands, and the
digest-pinned static builder. Reviewed dependency updates include sha2 0.11.1 and
Tokio 1.54.0. The five-platform, 16-file GitHub release contract is unchanged.

## Qualification boundary

[DS-111](../issues/DS-111.md) records candidate qualification. Hosted integration,
immutable publication, checksums, attestations, and native released-binary/action
acceptance must be verified separately before this candidate is called released.
