# DepScan v3.0.0

This release removes the unmaintained Chrono dependency, updates the dependency
graph and Rust toolchain, and establishes a major-version boundary for the changed
public Rust time types. CLI commands, exit codes, JSON schema 4, report/cache UTC
encoding, Rust 1.96.0 support, and the five-target/16-file artifact contract remain.

## Rust API migration

Consumers of the workspace crates must update their time types:

| Previous type | Replacement from `depscan_core` |
|---|---|
| `chrono::DateTime<chrono::Utc>` | `Timestamp` |
| `chrono::NaiveDate` | `Date` (Jiff civil date) |
| `chrono::Duration` | `Duration` (Jiff signed duration) |

`ScanDocument::generated_at`, `ScanDocument::at`, suppression expiry, and provider
cache policy now use these types. Construct instants with `Timestamp::now()`,
`Timestamp::parse(...)`, or `Timestamp::from_timestamp(seconds, nanoseconds)`;
construct dates with `Date::new(year, month, day)` and fixed durations with
`Duration::from_secs(...)` or `Duration::from_hours(...)`.

Serde timestamps and advisory revision keys retain UTC `Z` and 0/3/6/9 fractional
digits. `Timestamp::to_rfc3339()` retains the explicit `+00:00` report spelling;
`to_rfc3339_z()` provides the canonical `Z` form. Pre-epoch Unix-second flooring,
inclusive cache TTL boundaries, and real-clock suppression expiry are preserved.

## Timestamp validation

Inputs require seconds and an explicit RFC 3339 offset. Leap seconds, fractional
precision beyond nine digits, and years outside Jiff's supported range now fail
validation instead of silently normalizing or truncating. Unsupported cache
timestamps are non-reusable; invalid provider timestamps remain visible failures.
`SOURCE_DATE_EPOCH` outside the supported range remains a usage error (exit 10).
Reproducible report time never changes the actual UTC suppression-policy date.

## Dependencies and security maintenance

- Replace Chrono with Jiff 1.0.2 using only `std` and Serde. RustSec
  [RUSTSEC-2026-0543](https://rustsec.org/advisories/RUSTSEC-2026-0543.html) marks
  Chrono unmaintained, with no patched version; this is not a demonstrated exploit
  in DepScan.
- Refresh current stable requirements and the compatible lockfile, including
  const-oid 0.10.3, rustls-pki-types 1.16.0, rustls-webpki 0.103.17,
  webpki-root-certs 1.0.12, noyalib 0.0.63, TOML 1.2.2, and ZIP 9.8.2.
- Coordinate Rust 1.100.0 across native CI, release quality, and the digest-pinned
  static builder. Preserve the Rust 1.96.0 minimum and remove new Cargo metadata
  warnings and the Windows executable-validation lint without suppressions.
- Retain eMudhra distrust protections and patched Tokio/Rustls. Operating-system
  and runner trust stores still need their own updates.

## Verification and provenance

Preparation requires the release gate, strict Clippy, retained-MSRV tests, fresh
dependency/advisory checks, and the exact artifact plan. Publication follows green
protected-main integration. Public acceptance independently verifies immutable
assets, paired/aggregate checksums, API digests, source-bound attestations, and
native binaries plus the tagged action on all five supported targets. Exact
commits, tag and run identifiers are recorded on the integration PR and linked
from the published notes. MSI packaging/provenance do not prove MSI installation.
