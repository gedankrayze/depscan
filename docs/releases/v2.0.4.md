# DepScan v2.0.4

Publication status and artifacts are tracked on
[GitHub Releases](https://github.com/gedankrayze/depscan/releases).

This security release addresses compromised eMudhra certificate chains and the
yanked Tokio 1.54.0 interval race. Users of older binaries should upgrade;
publishing a new release does not update existing installations automatically.
JSON schema version 4 and the Rust 1.96.0 support floor are unchanged.

## Security fixes

- `rustls-webpki 0.103.16` explicitly distrusts the compromised intermediate keys
  ([RUSTSEC-2026-0382](https://rustsec.org/advisories/RUSTSEC-2026-0382.html)).
  All 14 public direct, cross-signed, and no-CT TLS chains are rejected even with
  their old roots explicitly trusted; an unrelated valid chain still verifies.
- `webpki-root-certs 1.0.11` removes affected trust roots and exceeds the patched
  floor for [RUSTSEC-2026-0383](https://rustsec.org/advisories/RUSTSEC-2026-0383.html).
  The bundled-root production edge is WASM-only; native clients retain their
  platform-verifier behavior and Linux uses the patched WebPKI backend.
- Tokio 1.54.1 fixes
  [RUSTSEC-2026-0384](https://rustsec.org/advisories/RUSTSEC-2026-0384.html).
  A multithreaded tick/cancellation/recreation regression covers 1,024 interval cycles.
- Explicit dependency floors prevent downstream locks from retaining the vulnerable
  verifier, bundled roots, or Tokio release.

## Dependency maintenance

Updated stable workspace requirements and the complete compatible dependency graph,
including capability crates, clap/completions, serde_json, js-semver, sha2, toml,
thiserror, insta, AWS-LC, Hyper, Rustls platform/native verification, and Tokio adapters.
Prereleases and incompatible overrides of upstream-constrained transitive versions
are excluded. Existing scanner fixtures and the five-platform, 16-file release
contract are unchanged.

## Operational guidance

Keep OS trust stores and CI runners patched. macOS/Windows native verification and
the shell/PowerShell release downloaders depend on platform facilities; the new
Linux verifier protects against the compromised intermediate keys even if an old
trust anchor remains installed. Dependency exposure alone is not evidence that
an installation was attacked.

## Qualification boundary

[DS-115](../issues/DS-115.md) records local preparation. Exact-head hosted checks,
immutable publication, downloaded checksums/attestations, and native released-binary
and tagged-action acceptance must complete before release delivery is called complete.
