# DS-046: Deliver and verify genuinely static Linux artifacts

- **Status:** Closed
- **Priority:** P2
- **Scope:** Release binaries / static-linking contract

_Closed-record excerpts; original dates and versions apply._

## Evidence

- `Cargo.toml:58` configures `x86_64-unknown-linux-gnu`, which does not by itself satisfy the specification's single-static-binary constraint.

- Audit binary inspection found dynamic linkage to `liblzma`, `libbz2`, and `libiconv` in the current release build.

- Major upgrades such as `zip`/compression libraries can change native linkage, so this needs an artifact-level gate.

## Historical resolution

- Replaced the GNU Linux release target with explicit `x86_64-unknown-linux-musl` and `aarch64-unknown-linux-musl` targets. Linux releases therefore have a static-musl contract and do not require glibc, a distribution package manager, or language/package-manager runtimes.

- Added a least-privilege static-Linux workflow with native x86-64 and ARM64 runners. It builds inside the official Rust 1.97.1 Alpine multi-architecture image pinned by digest, so each artifact is produced natively against musl rather than relying on an accidental host linker configuration.

- Added `scripts/verify-static-linux.sh`. The gate requires an executable ELF reported as statically linked or static PIE, rejects every `readelf` `NEEDED` entry, and executes the shipped binary's version and help paths. It therefore inspects the release artifact itself rather than inferring linkage from Cargo features.

## Historical verification

- Immutable v1.2.0 acceptance run
  [32382623588](https://github.com/gedankrayze/depscan/actions/runs/32382623588) downloaded the
  checksum- and attestation-bound musl archives on their native runners. Linux x86-64 job
  `96469635920` and Linux ARM64 job `96469635949` both passed `file`/`readelf` static-link
  inspection, exact version/help checks, and the four-package offline scan inside a networkless,
  read-only `scratch` container.

- The public archives are `depscan-cli-x86_64-unknown-linux-musl.tar.xz` with GitHub-recorded
  SHA-256 `d297acf730aac589921b00872d4d3a811c740d9e734bd470289c51665597d437` and
  `depscan-cli-aarch64-unknown-linux-musl.tar.xz` with SHA-256
  `eb01a6bc937e2732a128d9586e157c627ebdb328b647a796d478596cca932bc8`; the acceptance jobs
  independently verified their paired records and tag-bound attestations before execution.
