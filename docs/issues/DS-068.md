# DS-068: Run pinned GitHub Actions on supported Node 24 runtimes

- **Status:** Closed
- **Priority:** P2
- **Scope:** GitHub Actions dependencies / hosted-runner compatibility

_Closed-record excerpts; original dates and versions apply._

## Evidence

- Protected CI runs warn that the pinned `actions/checkout` v4.3.1 and
  `actions/upload-artifact` v4.6.2 bundles target Node 20 and are being forcibly executed on Node
  24 by GitHub-hosted runners.

- The current official replacements are `actions/checkout` v7.0.1 and
  `actions/upload-artifact` v7.0.1. Their official `action.yml` metadata declares `node24`.

- Leaving older bundles in CI, live-provider, and static-Linux workflows keeps a deprecation
  warning active and relies on an implicit runtime override rather than an action version built
  and supported for that runtime.

## Historical verification

- Live official refs resolve checkout v7.0.1 to
  `3d3c42e5aac5ba805825da76410c181273ba90b1` and upload-artifact v7.0.1 to
  `043fb46d1a93c77aae656e7c1c64a875d1fc6a0a`; both official `action.yml` files declare
  `using: node24`.

- Checkout v7's privileged fork-checkout restriction does not affect these workflows: they run on
  ordinary `pull_request`, `push`, `schedule`, or `workflow_dispatch` events, not
  `pull_request_target` or `workflow_run`. Every upgraded compile/execute checkout already sets
  `persist-credentials: false`. Static Linux retains upload-artifact's default archived multi-file
  behavior and does not opt into its new direct single-file mode.

- `actionlint .github/workflows/*.yml` passes. A complete workflow inventory finds no obsolete
  checkout/upload revision and requires every non-local `uses:` reference to end in exactly 40
  lowercase hexadecimal characters.
