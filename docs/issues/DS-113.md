# DS-113: Remove the yanked Tokio interval race release

- **Status:** Closed
- **Priority:** P1
- **Scope:** Async-runtime dependency security and interval regression coverage

## Evidence

The 2026-10-23 fresh audit resolves yanked `tokio 1.54.0` and reports
[RUSTSEC-2026-0384](https://rustsec.org/advisories/RUSTSEC-2026-0384.html).
The affected multithreaded `Interval` path can race with the timer driver and
cause use-after-free. `Sleep` and `Timeout` alone are not affected. The stable
patched floor is Tokio 1.54.1. This records the vulnerable resolution, not a
claim that every DepScan timer path triggers the race.

Incoming [PR #71](https://github.com/gedankrayze/depscan/pull/71), reviewed head
`aa4ed1c65e4b5071d2324a2baac8b797fb4b871e`, proposes 1.54.1 and has green
current-head CI/MSRV/static/release-plan checks. Its lockfile also resolves six
Windows-binding edges from 0.61.2 to 0.52.0; the local coordinated refresh will
resolve the graph independently instead of copying that unrelated churn.
The subsequent user authorization covers merging this PR before delivering the
coordinated security refresh and publishing v2.0.4.

## Acceptance criteria

- Raise the declared Tokio floor and resolved version to the latest compatible stable release.
- Exercise interval tick/cancellation/recreation on a multithreaded runtime.
- Retain provider timeout, retry, streaming, lock, and cancellation regression coverage.
- Remove the advisory and yanked-package warning from a fresh audit.

## Resolution

- Raised the workspace Tokio requirement to **1.54.1**, the current latest stable
  release, and resolved that version throughout the refreshed graph.
- Added a dedicated runtime regression: 16 tasks on four runtime workers perform
  64 interval tick/cancellation/recreation rounds each (**1,024 cycles**) and
  then prove ordinary ticks continue advancing. The test is bounded by a generous
  timeout and requires every task to finish without panic or hang.
- This is bounded concurrency regression coverage, not a sanitizer proof that
  all possible schedules are race-free; the upstream patched floor removes the
  known unsafe release.

## Verification

- The focused interval regression passes, as do all 143 provider tests.
- The full gate, exact strict Clippy command, and locked all-target suites pass:
  **457 passed / 1 intentionally excluded** on Rust 1.99.1 and Rust 1.96.0,
  natively on macOS arm64.
- A fresh `cargo audit --json` reports **zero vulnerabilities and zero warnings**;
  the Tokio advisory and yanked warning are gone.
- PR #71's reviewed head has successful canonical runs:
  [CI 39690913191](https://github.com/gedankrayze/depscan/actions/runs/39690913191),
  [static 39690913285](https://github.com/gedankrayze/depscan/actions/runs/39690913285),
  and [release quality/plan 39690913307](https://github.com/gedankrayze/depscan/actions/runs/39690913307).
  These are evidence for that remote head, not this unpublished local refresh.
