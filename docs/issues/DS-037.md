# DS-037: Distinguish direct and transitive Pipfile.lock packages

- **Status:** Closed
- **Priority:** P1
- **Scope:** Pipenv parser / CLI filters

## Evidence

- `crates/depscan-parsers/src/lib.rs:459-480` marks every entry in `Pipfile.lock`'s `default` and `develop` maps as `direct = true`.
- Lock maps contain resolved transitive packages; directness must come from the corresponding `Pipfile`, not mere lockfile membership.
- `--direct-only` consequently retains transitives and reports a false direct-dependency set.

## Acceptance criteria

- Read the associated `Pipfile` sections to identify direct default/develop dependencies and join them to locked packages using PEP 503 names.
- Preserve `dev` classification without assuming every locked package is direct.
- If the manifest is missing/malformed, represent directness as unknown/best-effort rather than true.

## Verification

- Add Pipfile/Pipfile.lock pairs with direct and transitive default/develop dependencies, name normalization, extras, and missing manifests.
- Exercise `--direct-only` and `--no-dev` at process level.

## Resolution

- `Pipfile.lock` packages now derive directness from the adjacent `Pipfile`: `[packages]` maps to the lock's `default` section and `[dev-packages]` maps to `develop`. Locked entries absent from the corresponding manifest section remain known transitives instead of being labeled direct.
- Manifest and lock identities are joined with the shared PEP 503 normalization used by the core model, including case and repeated `-`, `_`, and `.` separators. Extended Pipfile declarations with extras remain direct declarations of their package key.
- Development scope still comes from the resolved lock section and remains known independently of directness. When the Pipfile is absent, unreadable, invalid TOML, or contains an invalid dependency-section shape, every locked package uses `direct = false` and `direct_known = false`; conservative CLI filtering therefore retains these unknowns rather than silently dropping dependencies.
- Added a realistic Pipenv fixture containing direct and transitive production/development packages, normalized identities, extras, hashes, and lock metadata. Parser tests also cover missing, syntactically malformed, and semantically malformed manifests.
