# DS-092: Add a SECURITY.md vulnerability disclosure policy

- **Status:** Closed
- **Priority:** P2
- **Scope:** Repository hygiene

## Evidence

- The 2026-08-21 review found no `SECURITY.md` in a repository that ships a security tool with
  hardened release, attestation, and capability-safety machinery. There is no documented private
  reporting channel or supported-version statement.

## Acceptance criteria

- `SECURITY.md` names the private reporting channel (GitHub private vulnerability reporting or a
  maintainer address), expected response window, and which release lines receive fixes; the
  README links to it.

## Verification

- GitHub's Security tab picks up the policy; `bash scripts/dev-gate.sh quick` for repository
  checks.

## Resolution

- Added `SECURITY.md`: private reporting via GitHub private vulnerability reporting, a
  seven-day acknowledgement window, a scope section naming the classes this codebase cares
  about (untrusted-input parsing, filesystem confinement, `--allow-tools` execution surface,
  false-clean results, release integrity), and a latest-minor support statement. The README
  links to it from a new Security section.
- GitHub private vulnerability reporting is enabled, so the documented report link has its
  required repository setting. GitHub only picks up the policy file once it reaches the default
  branch.

## Local verification evidence

- `bash scripts/dev-gate.sh quick` passes with the new files.
- GitHub's private-vulnerability-reporting endpoint returned `{"enabled":true}` on 2026-08-21.

## Remote verification evidence

- Protected-main merge `31a694d679294d7e707190e8e9d89a07c869a966` publishes root
  `SECURITY.md` with blob `fe2db34a7d9e4896b552447449adb1bf8a6cbf6f`; GitHub's public
  `/security/policy` page returns HTTP 200 and renders the repository Security Policy.
- GitHub private vulnerability reporting remains enabled, so the policy's private report link is
  backed by the required repository control.
