# DS-057: Reject malformed npm v2/v3 package records

- **Status:** Closed
- **Priority:** P1
- **Scope:** npm `package-lock.json` v1-v3 parser / false-clean prevention

## Evidence

- The v2/v3 `packages` loop previously used `continue` for non-object values, malformed `node_modules` locations, and records with missing, empty, or non-string versions. A lock could therefore retain valid records, silently discard malformed ones, and produce a partial report that appeared clean.
- The realistic v2 fixture contained a `node_modules/missing-version` record, while the v3 fixture contained a non-object package record and malformed install locations. Their passing snapshots demonstrated that the omissions were accepted behavior rather than rejected input.
- npm v2/v3 package maps distinguish package locations from the legacy v1 recursive dependency tree. Treating arbitrary invalid locations as possible local metadata made that structural boundary ineffective.

## Acceptance criteria

- For lockfile versions 2 and 3, reject non-object entries, malformed installed-package locations, invalid field types, missing or empty registry versions, and registry-like versions that are not valid SemVer. A positively identified non-registry package without a version may retain its non-empty resolved source coordinate instead.
- Skip only the root plus existing local descriptor objects referenced by validated `link` and `resolved` records. Keep an installed `node_modules` target scannable, and do not reinterpret arbitrary unknown paths as harmless workspace metadata.
- Keep explicit Git, file, and URL packages visible and non-enrichable; skip local link/workspace metadata rather than inventing public npm coordinates for it. Hoisting must not erase non-registry provenance, and alternate or ambiguous registry origins must not be sent to the public registry or OSV.
- Validate npm alias declarations against the installed entry's canonical `name`, including bare alias targets whose version defaults to `*`; missing or mismatched alias identity is invalid.
- Preserve each active registry declaration's version constraint. A non-root dependency must not fall back to an ancestor workspace link whose version does not satisfy that constraint, and a link record must not carry package dependency/name/version metadata that belongs on its target descriptor.
- Match root workspace patterns with bounded npm-minimatch semantics. Syntax that cannot be evaluated safely must fail closed instead of proving an attacker-selected link target to be a workspace.
- Keep legacy lockfile version 1 explicitly best-effort and document the version-specific boundary.
- A mixed valid and malformed lock must exit `10`, emit no report, and stop before provider access.

## Verification

- Add table-driven v2/v3 parser tests for non-object records, missing or wrong versions, invalid SemVer, malformed scoped locations, unreferenced local paths, wrong `dev`, `link`, or `resolved` types, and missing or installed-package link targets.
- Retain valid root/workspace/link controls plus registry, alias, Git, URL, no-version source, and alternate-registry records, asserting that only trustworthy public-registry coordinates are enrichable across hoisting.
- Add a checked-in mixed valid/malformed fixture and process test proving exit `10`, no stdout report, source-qualified context, and no provider hard-failure path.

## Resolution

- `parse_package_lock` now validates the complete v2/v3 package map before extraction. Every entry must be an object; optional `link` and `dev` fields are typed; and every link must name an existing descriptor object without carrying package dependency/name/version metadata. Installed-package targets remain scannable, while local descriptors are skipped only after link and workspace identity validation. Registry-looking links are rejected unless the target is a proven workspace with the same stable identity; npm's protected root workspace edge may override a later root alias, but non-root declarations must agree and their constraints must accept the linked workspace version.
- Dependency declarations are parsed with npm Arborist's effective group order and bound to concrete install locations using Node ancestor lookup. This preserves hoisted source provenance, rejects incompatible alias/plain identities coalesced onto one record, requires active root/workspace dependency edges, validates local-source declarations against the selected link target, and ignores inactive dependency graphs from disconnected external file-link descriptors. A bounded matcher with exact Unicode general-category handling covers npm workspace wildcards, globstars, dot rules, classes, POSIX classes, brace ranges, extglobs, comments, literal fallbacks, separator normalization, double negation, ordered exclusions, and the implicit `node_modules` exclusion. Pattern size, expansion, nesting, AST, candidate, and matching-work caps fail closed; deliberately unsupported unsafe extglob combinations return a parse error.
- Registry records require SemVer. Only an explicit, credential-free `registry.npmjs.org` HTTP(S) origin whose tarball path matches the package identity and version is publicly enrichable. Explicit Git, file, URL, alternate-registry, configured-registry, and omitted-origin records stay visible with `enrichable=false`; unknown or credential-shaped `resolved` strings fail closed. Missing-version and non-SemVer coordinates are retained only for a positively identified non-registry source, with credentials, queries, fragments, and opaque credential-like forms removed before reporting.
- `npm:` aliases accept exact, ranged, tagged, bare, and trailing-empty targets, but the installed entry must contain the selected canonical package `name`; unexplained identity changes fail closed. Deduplication treats provider eligibility existentially, so a canonical-public occurrence remains queryable even when the same coordinate also occurs through a non-public source.
- The malformed sentinel entries were removed from the realistic v2/v3 fixtures. Table-driven malformed-record cases exercise both schema versions; focused tests cover link relabeling and metadata, alias identity, effective group precedence, concrete workspace binding, non-root constraint compatibility, npm minimatch behavior, external links, install-location containment, public tarball identity, source sanitization, ambiguous origins, and mixed-provenance deduplication. Checked-in npm 11 fixtures cover a hoisted URL, bare aliases, and alias/source collisions, while the mixed malformed fixture proves that a valid record before an error cannot produce a partial CLI report.
- Version 1 remains the separately named best-effort structural path. Only a canonical public `resolved` origin paired with valid SemVer is enrichable; known Git, file, URL, alias, configured, alternate, omitted, invalid-version, and raw source coordinates are retained without public enrichment and sanitized before reporting.
