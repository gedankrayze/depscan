# DS-013: Fail closed on malformed OSV batch responses

- **Status:** Closed
- **Priority:** P1
- **Scope:** Online OSV provider / response integrity

## Evidence

- `crates/depscan-providers/src/lib.rs:286-313` converts a missing or non-array `results` field into an empty list.
- `crates/depscan-providers/src/lib.rs:371-391` zips requested packages with returned lists without verifying equal counts, silently omitting trailing packages.
- Malformed result entries also default to no vulnerabilities, creating false-clean outcomes.

## Acceptance criteria

- Validate the response object, result count, per-result shape, vulnerability IDs, and package-to-result alignment.
- A malformed response envelope, result-count mismatch, or response with no trustworthy usable package result becomes an explicit provider hard failure.
- A malformed result that is still aligned to one package becomes an explicit package-scoped error when another aligned package has a trustworthy complete result. The malformed result is never cached as clean, and the overall query is a hard failure when no package result is usable.
- Valid empty vulnerability arrays remain distinguishable from invalid/missing data.

## Verification

- Add `wiremock` cases for missing `results`, wrong type, too few/many results, malformed `vulns`, invalid IDs, and valid empty results.
- Assert malformed envelopes and cardinality mismatches exit through the hard provider-failure path without creating query cache entries.
- Assert an aligned malformed result becomes a package-scoped error and receives no cache entry while a fully validated aligned sibling may succeed and cache normally.

## Resolution

- Added one fail-closed OSV batch decoder that requires a top-level object, a `results` array with exactly one entry per query, object-shaped results, array-shaped `vulns` when present, object-shaped vulnerability entries, and database-scoped OSV IDs.
- Preserved both valid clean encodings emitted by OSV: the live protobuf JSON empty result `{}` and an explicit `{"vulns": []}`. Any non-empty result without `vulns` is rejected instead of being interpreted as clean.
- Envelope and cardinality validation completes before the caller writes any `osv/query` cache entry. Those whole-response failures return the typed, user-visible `ProviderError::InvalidResponse` and leave every package in the chunk uncached.
- Aligned result entries are validated independently under the partial-failure contract introduced by [DS-035](DS-035.md). A malformed entry receives a package-scoped error and no query cache entry, while a fully validated sibling may complete and cache normally. The provider still fails hard if no eligible package has a trustworthy usable result.
- Added a 15-case Wiremock matrix covering missing/wrong response structure, shorter and longer result lists, malformed results and vulnerability entries, missing/non-string/invalid IDs, and a malformed later result after a valid prefix. The assertions distinguish whole-response cache rejection from per-package rejection without allowing malformed data to become a clean result.
- Added a valid two-package Wiremock batch proving that `{}` and `{"vulns": []}` remain aligned, create two explicit empty map entries, and cache two empty arrays. A live OSV probe on 2026-08-19 confirmed that an unknown package is encoded as `{"results":[{}]}`.
