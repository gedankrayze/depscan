# DS-011: Make Cargo manifest parsing workspace- and rename-aware

- **Status:** Closed
- **Priority:** P1
- **Scope:** Cargo parser / manifest-only mode / directness

## Evidence

- `crates/depscan-parsers/src/lib.rs:692-716` treats dependency table keys as crate names, so `{ package = "real-name" }` renames are marked incorrectly.
- `crates/depscan-parsers/src/lib.rs:745-770` parses only the detected root `Cargo.toml`; it does not traverse workspace members or resolve `{ workspace = true }` dependencies.
- The detector at `crates/depscan-parsers/src/lib.rs:678-682` returns one root source.

## Acceptance criteria

- Resolve workspace members/excludes and all dependency sections across member manifests.
- Resolve `[workspace.dependencies]` inheritance and renamed dependencies using the `package` field.
- Preserve source/git/path provenance, direct/dev/build classification, and the declaring manifest.
- Manifest-only ranges are marked degraded without inventing a resolved version.

## Verification

- Add fixtures for virtual workspaces, member globs/excludes, inherited dependencies, target-specific tables, renamed crates, and path/git sources.
- Snapshot normalized packages and assert directness in the corresponding `Cargo.lock` fixture.

## Resolution

- Cargo manifest parsing now resolves virtual and package workspaces from the root manifest, an explicit `package.workspace` pointer, or Cargo's parent-directory discovery. Member globs, explicit excludes, and in-tree path dependencies are traversed deterministically; excluded and unused workspace templates are not treated as direct dependencies.
- Dependency declarations are collected from normal, development, build, and every target-specific dependency table in every member. A member's `workspace = true` declaration inherits the workspace definition by its local alias, while `package` supplies the actual crates.io identity used for lockfile directness and enrichment.
- Manifest-only packages retain the declaring member's `Cargo.toml`, the verbatim version requirement, direct/dev classification, and `resolved_from_range = true`. Versioned path, Git, and alternate-registry coordinates remain visible but non-enrichable; versionless path/Git declarations are used for workspace/directness discovery without inventing registry scan coordinates.
- `Cargo.lock` remains the preferred detected source. Its resolved packages now use rename-aware workspace metadata for direct/dev marking, while lockfile source metadata continues to disable enrichment for Git, path, and non-crates.io registry packages.
- Invalid dependency shapes, non-string `package` fields, missing workspace inheritance, conflicting sources, malformed workspace lists/patterns, and missing member/path manifests return actionable parse errors instead of being silently skipped.
