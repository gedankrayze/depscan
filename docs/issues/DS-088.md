# DS-088: Tighten numeric conversions and remove infallible expect noise

- **Status:** Open
- **Priority:** P2
- **Scope:** Small correctness-hygiene sweep

## Evidence

- The 2026-08-21 code review found a lossy `f64 -> f32` cast on the CVSS score in
  `crates/depscan-providers/src/osv/scoring.rs`; the value drives `Severity::from_cvss` and
  therefore the exit code (harmless for 0.0-10.0 today, but the narrowing is unnecessary).
- `crates/depscan-providers/src/osv/sync/identity.rs` performs `metadata.len() as usize` for an
  allocation, guarded only by a size check several lines earlier.
- `crates/depscan-report/src/markdown.rs` carries six `.expect(...)` calls on `fmt::Write` into
  a `String`, which cannot fail; `unreachable!` sites in `crates/depscan-cli/src/app/commands.rs`
  and `crates/depscan-core/src/version.rs` guard invariants the type system could carry.

## Acceptance criteria

- The CVSS pipeline stays `f64` end to end (or documents the narrowing); casts use
  `try_into`/checked forms; infallible writes drop their `expect`s.

## Verification

- Existing report and scoring tests pass unchanged.
- `bash scripts/dev-gate.sh full`
