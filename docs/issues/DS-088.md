# DS-088: Tighten numeric conversions and remove infallible expect noise

- **Status:** Closed
- **Priority:** P2
- **Scope:** Small correctness-hygiene sweep

## Evidence

- The 2026-08-21 code review found a lossy `f64 -> f32` cast on the CVSS score in
  `crates/depscan-providers/src/osv/scoring.rs`; the value drives `Severity::from_cvss` and
  therefore the exit code (harmless for 0.0-10.0 today, but the narrowing is unnecessary).
- `crates/depscan-providers/src/osv/sync/identity.rs` performs `metadata.len() as usize` for an
  allocation, guarded only by a size check several lines earlier.
- `crates/depscan-report/src/markdown.rs` carries six `.expect(...)` calls on `fmt::Write` into
  a `String`, which cannot fail; `unreachable!` sites in `crates/depscan-cli/src/app/commands.rs`
  and `crates/depscan-core/src/version.rs` guard invariants the type system could carry.

## Acceptance criteria

- The CVSS pipeline stays `f64` end to end (or documents the narrowing); casts use
  `try_into`/checked forms; infallible writes drop their `expect`s.

## Verification

- Existing report and scoring tests pass unchanged.
- `bash scripts/dev-gate.sh full`

## Resolution

- The CVSS pipeline is `f64` end to end: `Severity::from_cvss`, `Vulnerability::cvss_score`, and
  the three scoring helpers dropped the narrowing cast. This is a breaking change to
  `depscan-core`'s public types and rides with the DS-083 semver-major boundary; rendered JSON
  is unchanged (CVSS scores are one-decimal values whose shortest representation is identical),
  which the existing report snapshot digests confirm.
- The sentinel read uses `usize::try_from(...).unwrap_or(0)` for its capacity hint instead of an
  unchecked `as usize`.
- Both `unreachable!` sites are gone: `classify_staleness` matches once per ecosystem with NuGet
  handled in its own arm, and the CLI dispatches `sync`/`cache`/`completions` through typed
  `run_sync`/`run_cache`/`run_completions` entry points instead of re-matching an already-routed
  `Command::Scan`.
- The Markdown renderer's six infallible `expect`s became a `push_line` helper that discards the
  `fmt::Write`-into-`String` result it documents as unfailable.

## Local verification evidence

- `cargo clippy --workspace --all-targets` clean; all 25 workspace test suites pass, including
  the report snapshot digests, which proves the `f64` switch did not change rendered output.
