# DS-027: Replace unmaintained `serde_yaml`

- **Status:** Closed
- **Priority:** P1
- **Scope:** Dependency maintenance / pnpm and Yarn parsing

## Evidence

- `Cargo.toml:33` declares `serde_yaml` 0.9 and `Cargo.lock:1759-1760` resolves `0.9.34+deprecated`.
- `crates/depscan-parsers/src/lib.rs:291-315` depends on it for pnpm YAML parsing; Yarn Berry support will also require YAML handling.
- The crate is explicitly deprecated/unmaintained, so there is no newer maintained version to select.

## Acceptance criteria

- Select a maintained YAML parser after evaluating compatibility, security posture, MSRV, duplicate-key behavior, aliases/resource limits, and API stability.
- Migrate pnpm and Yarn Berry parsing without accepting ambiguous duplicate keys or unbounded alias expansion from untrusted lockfiles.
- Remove `serde_yaml` from the full dependency graph.

## Verification

- Add valid and adversarial YAML fixtures for duplicate keys, anchors/aliases, deep nesting, large scalars, and format-specific schemas.
- Run `cargo tree -i serde_yaml` and confirm it is absent, then run all tests, strict Clippy, and `cargo audit`.

## Resolution

- Selected [`noyalib` 0.0.24](https://crates.io/crates/noyalib/0.0.24), the crates.io `max_stable_version` on 2026-08-19 (published 2026-08-18). Its [tagged manifest](https://github.com/sebastienrousseau/noyalib/blob/v0.0.24/Cargo.toml) declares Rust 1.86.0, and the upstream repository recorded current maintenance activity on 2026-08-19. Its [documented security posture](https://docs.rs/noyalib/0.0.24/noyalib/) includes pure-Rust parsing, `#![forbid(unsafe_code)]`, configurable resource budgets, duplicate-key policy, and per-scalar policies.
- Alternatives were not adopted: `serde_yml` 0.0.13 declares itself deprecated and unmaintained and is covered by RUSTSEC-2025-0068; `serde_yaml_ng` retains `unsafe-libyaml`; and `serde-saphyr` 1.1.0 has strong budgets and a 1.x API but does not declare a Rust version. `noyalib` provides the closest native `Value` integration, an explicit MSRV below this workspace's Rust 1.95.0 floor, and a built-in individual-scalar policy. The dependency enables only its `std` feature rather than the compatibility shim or broad defaults.
- Both pnpm and Yarn Berry now use one configured YAML entry point. It rejects duplicate and merge keys, accepts ordinary anchors while limiting alias expansions to 64 with an 8:1 alias/anchor heuristic, and caps depth at 64, input and cumulative scalar data at 64 MiB, individual scalars at 1 MiB, documents at one, mapping/sequence width at 100,000, events at 2,000,000, and materialized nodes at 1,000,000. Reads are bounded before the parser receives the document.
- Current pnpm v9 and Yarn Berry v10 behavior remains covered, including scoped packages, direct/development provenance, and a valid anchored mapping. The migration intentionally follows YAML 1.2 scalar semantics and rejects merge keys; hand-authored lockfiles relying on YAML 1.1 implicit booleans, merge keys, or values beyond the documented limits now fail closed. `noyalib` is pre-1.0, but Cargo's `0.0.24` requirement does not admit `0.0.25`, so future breaking-line upgrades remain explicit.
- `Cargo.lock` resolves `noyalib` 0.0.24 and removes `serde_yaml` 0.9.34+deprecated, `unsafe-libyaml` 0.2.11, and the now-unused `ryu` 1.0.23 entry.
