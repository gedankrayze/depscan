# DS-027: Replace unmaintained `serde_yaml`

- **Status:** Open
- **Priority:** P1
- **Scope:** Dependency maintenance / pnpm and Yarn parsing

## Evidence

- `Cargo.toml:33` declares `serde_yaml` 0.9 and `Cargo.lock:1759-1760` resolves `0.9.34+deprecated`.
- `crates/depscan-parsers/src/lib.rs:291-315` depends on it for pnpm YAML parsing; Yarn Berry support will also require YAML handling.
- The crate is explicitly deprecated/unmaintained, so there is no newer maintained version to select.

## Acceptance criteria

- Select a maintained YAML parser after evaluating compatibility, security posture, MSRV, duplicate-key behavior, aliases/resource limits, and API stability.
- Migrate pnpm and Yarn Berry parsing without accepting ambiguous duplicate keys or unbounded alias expansion from untrusted lockfiles.
- Remove `serde_yaml` from the full dependency graph.

## Verification

- Add valid and adversarial YAML fixtures for duplicate keys, anchors/aliases, deep nesting, large scalars, and format-specific schemas.
- Run `cargo tree -i serde_yaml` and confirm it is absent, then run all tests, strict Clippy, and `cargo audit`.
