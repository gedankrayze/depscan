# DS-027: Replace unmaintained `serde_yaml`

- **Status:** Closed
- **Priority:** P1
- **Scope:** Dependency maintenance / pnpm and Yarn parsing

_Closed-record excerpts; original dates and versions apply._

## Evidence

- `Cargo.toml:33` declares `serde_yaml` 0.9 and `Cargo.lock:1759-1760` resolves `0.9.34+deprecated`.

- `crates/depscan-parsers/src/lib.rs:291-315` depends on it for pnpm YAML parsing; Yarn Berry support will also require YAML handling.

- The crate is explicitly deprecated/unmaintained, so there is no newer maintained version to select.

## Historical resolution

- Selected [`noyalib` 0.0.24](https://crates.io/crates/noyalib/0.0.24), the crates.io `max_stable_version` on 2026-08-19 (published 2026-08-18). Its [tagged manifest](https://github.com/sebastienrousseau/noyalib/blob/v0.0.24/Cargo.toml) declares Rust 1.86.0, and the upstream repository recorded current maintenance activity on 2026-08-19. Its [documented security posture](https://docs.rs/noyalib/0.0.24/noyalib/) includes pure-Rust parsing, `#![forbid(unsafe_code)]`, configurable resource budgets, duplicate-key policy, and per-scalar policies.

- Alternatives were not adopted: `serde_yml` 0.0.13 declares itself deprecated and unmaintained and is covered by RUSTSEC-2025-0068; `serde_yaml_ng` retains `unsafe-libyaml`; and `serde-saphyr` 1.1.0 has strong budgets and a 1.x API but does not declare a Rust version. `noyalib` provides the closest native `Value` integration, an explicit MSRV below this workspace's Rust 1.95.0 floor, and a built-in individual-scalar policy. The dependency enables only its `std` feature rather than the compatibility shim or broad defaults.

## Historical verification

- New fixtures/tests cover current pnpm v9 schema and provenance, bounded anchor reuse, duplicate keys in pnpm and Yarn Berry, excessive alias expansion, deep nesting, and an oversized generated scalar. All five focused YAML safety tests passed on Rust 1.97.1 and 1.95.0; the three existing Yarn compatibility tests remained green.

- `cargo tree -i serde_yaml` and `cargo tree -i unsafe-libyaml` both reported that no matching package exists; `cargo tree -i noyalib` reports only `depscan-parsers` (and its `depscan-cli` consumer).

- A fresh `cargo audit` fetched 1,217 RustSec advisories and found no vulnerabilities in all 274 locked dependencies.
