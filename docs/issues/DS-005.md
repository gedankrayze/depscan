# DS-005: Correct shared OSV range evaluation and fix extraction

- **Status:** Open
- **Priority:** P0
- **Scope:** Core OSV logic / online and offline providers

## Evidence

- `crates/depscan-core/src/lib.rs:446-472` overwrites an already-active interval at each later `introduced` event and assumes event order.
- `crates/depscan-core/src/lib.rs:475-500` extracts fixes without checking the affected package identity or range type.
- `crates/depscan-providers/src/lib.rs:568-607` only checks `affected[].ranges[].events`; it ignores explicit `affected[].versions`, range `type`, `limit`, and ordering requirements.
- The online hydration and offline lookup therefore do not implement the complete OSV matching algorithm and can miss affected versions.

## Acceptance criteria

- One shared evaluator is used by both hydrated-online and offline paths.
- It validates package identity and ecosystem, supports explicit affected versions, understands supported range types, sorts/evaluates events correctly, and handles `introduced`, `fixed`, `last_affected`, and `limit` semantics.
- Multiple disjoint intervals cannot deactivate an earlier matching interval.
- Fixed-version extraction is restricted to the matching affected package/range and returns the smallest applicable fixes at or above the installed version.
- Unsupported range types fail safely and visibly instead of silently reporting clean.

## Verification

- Add the OSV schema's range examples plus fixtures for disjoint intervals, unsorted events, explicit versions, `limit`, `last_affected`, wrong package identity, and every supported ecosystem comparator.
- Run the same fixture suite through online hydration and `OsvOffline` and assert identical results.
- Run all tests and strict Clippy.
