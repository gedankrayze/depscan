# DS-101: Update base64 without enabling its SIMD unsafe default

- **Status:** Closed
- **Priority:** P2
- **Scope:** Bun integrity parsing dependency

## Evidence

- Renovate PR #37 proposes `base64 = "0.23.0"`; Cargo resolves that range to 0.23.1.
- The upstream 0.23 release makes the new `simd-unsafe` feature part of the default feature set.
- DepScan uses base64 only to decode bounded Bun integrity strings, so SIMD acceleration is not
  required for this parser path.

## Acceptance criteria

- The workspace uses base64 0.23.1 with default features disabled and only `std` enabled.
- The lockfile retains base64 0.22.1 where transitive dependencies still require it and binds
  `depscan-parsers` to 0.23.1.
- Bun parser tests, strict Clippy, the frozen architecture gate, and the release candidate gate
  pass without enabling the dependency's `simd-unsafe` feature.
- Renovate PR #37 is closed as superseded only after the hardened replacement is locally proven.

## Resolution

- Updated the workspace dependency to base64 0.23.1 with default features disabled and only
  `std` enabled. Cargo retains 0.22.1 for transitive consumers that still require it and binds
  `depscan-parsers` to 0.23.1.
- `cargo tree -p depscan-parsers -e features` shows only base64's `std` and `alloc` features; the
  new default-on `simd-unsafe` feature is absent.
- All 144 parser targets, strict parser Clippy, and the Rust architecture gate pass. The complete
  `bash scripts/dev-gate.sh release` also passes: exact strict all-target Clippy, all 434 local
  tests with the documented live-provider test ignored, all five package/verification passes,
  and the optimized `depscan-cli 2.0.1` build.
- Renovate PR #37 is superseded by this hardened replacement rather than merged unchanged.
