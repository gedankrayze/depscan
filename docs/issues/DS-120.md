# DS-120: Enforce a patched Rustls floor for downstream locks

- **Status:** Closed
- **Priority:** P1
- **Scope:** Native provider dependency constraints, not an affected current binary

## Evidence

The current lockfile already resolves safe Rustls 0.23.46. However, reqwest 0.13.5
allows Rustls from 0.23.4, and the existing WebPKI floor does not constrain Rustls
itself. A disposable resolver using the production reqwest features, patched
WebPKI 0.103.16, and an old Rustls 0.23.44 requirement resolved successfully.
RustSec flagged five Rustls advisories: 0285 and 0346–0349, with some conditions
dependent on optional features or application configuration.

These include [CVE-2026-123613](https://rustsec.org/advisories/RUSTSEC-2026-0285.html)
and [the four fixes requiring 0.23.46](https://github.com/rustls/rustls/releases/tag/v/0.23.46).
This demonstrates permitted downstream stale versions, not exploitation or a
vulnerable checked-in/public-release lockfile.

## Resolution

Added explicit Rustls 0.23.46 with defaults disabled and a production native
provider edge. WASM does not acquire a new TLS stack; existing WebPKI, root-store,
and Tokio floors remain. A deterministic manifest guard verifies all three
native TLS/runtime floors reach production rather than dev-only dependencies.

The patched resolver control rejects a dependent still forcing Rustls 0.23.44
with exit 101, rather than resolving a vulnerable parallel compatible version.
No forced transitive override or feature expansion is used.

## Verification

The production-floor guard and resolver controls pass. The final release gate
and MSRV suite each pass 460 tests; fresh audit and 321-package live self-scan
find no vulnerabilities. Root resolution remains 0.23.46, with no new WASM TLS
edge or default feature expansion. No published tag or asset is changed.
Full evidence is in the [review](../reviews/2026-11-10.md).
