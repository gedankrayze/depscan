# DS-078: Exit cleanly instead of panicking when stdout closes early

- **Status:** Closed
- **Priority:** P1
- **Scope:** CLI stdout contract

## Evidence

- The 2026-08-21 code review found every stdout write using `print!`/`println!` or
  `clap_complete::generate(..., &mut io::stdout())`. Rust ignores `SIGPIPE`, so
  `depscan | head` aborted with a write panic (exit 101 plus a panic backtrace on stderr)
  instead of the documented exit taxonomy.
- Reproduced deterministically pre-fix: spawning the CLI with the read end of its stdout pipe
  already closed panicked in `library/std/src/io/stdio.rs` for `scan` and `cache path`, and in
  `clap_complete .../shells/bash.rs` for `completions`.

## Acceptance criteria

- A closed stdout consumer never panics the CLI. The scan's threshold-derived exit code is
  preserved; informational commands exit 0.
- Other stdout write failures surface as ordinary CLI errors within the documented taxonomy,
  matching the existing `--output` file-write handling.
- Process-level tests cover the scan report, completions, and cache command paths with a closed
  stdout pipe.

## Verification

- `cargo test -p depscan-cli --test exit_codes broken_pipe`
- `bash scripts/dev-gate.sh full`

## Resolution

- Added `write_stdout` (`crates/depscan-cli/src/app/commands.rs`): a locked
  write-all-then-flush helper that suppresses `ErrorKind::BrokenPipe` with a debug diagnostic
  and maps every other write error to the usage/config exit path, consistent with `--output`
  file-write failures. The scan report, `sync`, and `cache` outputs route through it, and
  `completions` renders into a buffer before writing so `clap_complete` can no longer panic on
  a closed pipe.
- Added `crates/depscan-cli/tests/exit_codes/broken_pipe.rs`: three process-level tests spawn
  the binary with the stdout pipe's read end closed before startup (`std::io::pipe`), so the
  first write fails deterministically. An offline scan must keep exit 0 with no panic on
  stderr; `completions bash` and `cache path` must exit 0.

## Local verification evidence

- Pre-fix, all three new tests failed with exit 101 and `thread 'main' panicked` in the stdio
  and clap_complete write paths; post-fix all three pass.
- `bash scripts/dev-gate.sh full` passed on the frozen tree (architecture, verifiers,
  formatting, strict Clippy, full `--locked` workspace tests including the 72-test exit-code
  suite, action and release verifiers, `git diff --check`).
- Native evidence covers macOS. The tests are platform-neutral (`std::io::pipe` and Windows
  `ERROR_NO_DATA`/`ERROR_BROKEN_PIPE` both surface as `ErrorKind::BrokenPipe`); Linux and
  Windows proof lands with the next cross-platform CI quality run.
