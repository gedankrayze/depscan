# DS-072: Modularize provider architecture and isolate test suites

- **Status:** Closed
- **Priority:** P2
- **Scope:** `depscan-providers` module ownership, file size, and test organization

## Evidence

- `crates/depscan-providers/src/lib.rs` had grown to 11,875 lines and combined cache ownership,
  HTTP retry behavior, OSV query/offline/sync logic, registry clients, and their shared helpers.
- The provider unit suite was embedded in that same production file. Extracting it without further
  decomposition initially produced a single 6,921-line `src/tests/mod.rs`, retaining the same
  review and cognitive-complexity problem in a different path.
- Security-sensitive capability traversal, streaming publication, retry policy, cache CAS behavior,
  registry parsing, and vulnerability evaluation therefore shared one change and audit surface.

## Acceptance criteria

- Keep `lib.rs` as a small public façade and preserve the existing public provider API.
- Separate cache, HTTP, OSV, synchronization, and registry responsibilities into cohesive modules;
  split synchronization and registry internals further where one file would still own unrelated
  policy and mechanics.
- Move executable tests out of production files and organize them by domain, with reusable fixtures
  and race-test machinery in explicit test-support modules.
- Keep normal Rust source files at or below 400 lines. Any future exception must be explicit,
  reviewed, and justified rather than becoming an accidental aggregation point.
- Preserve all 129 provider unit tests and pass the workspace/all-target suite, exact Clippy,
  formatting, and diff checks without changing provider behavior.

## Verification

- Run `cargo +1.97.1 test -p depscan-providers --lib --locked`.
- Run `cargo +1.97.1 test --workspace --all-targets --locked`.
- Run `cargo clippy --all-targets -- -D warnings`.
- Run `cargo fmt --all -- --check` and `git diff --check`.
- Audit provider Rust file sizes and confirm no file exceeds 400 lines.

## Resolution and evidence (2026-08-20)

- `lib.rs` is now a 106-line public façade. Cache ownership/CAS, HTTP retry and bounded reads,
  OSV query/hydration/offline evaluation, sync download/validation/capability/publication, and
  registry selection/sparse/online/offline behavior each have explicit module ownership.
- Provider tests now live under `src/tests/` in cache, HTTP, offline, OSV, registry, and sync suites.
  Shared raw-server, archive, cache, registry-fixture, and namespace-swap machinery lives in named
  support modules. The OSV document validator's tests moved to `osv_document/tests.rs`.
- The largest provider Rust source is 380 lines; no file needs an exception to the 400-line ceiling.
  The former 11,875-line production file and intermediate 6,921-line test aggregation are gone.
- `cargo +1.97.1 test -p depscan-providers --lib --locked` passes all `129/129` tests. The Rust
  1.97.1 workspace/all-target suite, exact all-target Clippy, formatting, and diff checks also pass.
  The refactor changes module ownership and test placement without changing the public API.
