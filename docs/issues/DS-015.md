# DS-015: Revalidate OSV and registry caches

- **Status:** Closed
- **Priority:** P1
- **Scope:** OSV hydration and registry HTTP caches

## Evidence

- `crates/depscan-providers/src/lib.rs:314-326` caches advisory documents by ID for ten years.
- `crates/depscan-providers/src/lib.rs:286-313` discards querybatch vulnerability `modified` timestamps, retaining only IDs.
- `crates/depscan-providers/src/lib.rs:682-697` returns fresh registry entries, but after TTL expiry discards the cached ETag and performs an unconditional download; it never sends `If-None-Match` or handles `304 Not Modified`.
- Updated severity, affected ranges, fixes, or withdrawal state can therefore remain stale for years.

## Acceptance criteria

- Retain each querybatch advisory's `modified` value.
- Key or validate hydrated documents by `(id, modified)` and refetch whenever the query result is newer/different.
- Cache migration safely invalidates legacy ID-only entries.
- Withdrawal and range changes become visible after the next query refresh.
- Preserve registry ETags across freshness expiry, revalidate with `If-None-Match`, handle `304` by refreshing cache age without losing the value, and safely replace changed `200` responses.

## Verification

- Add mock tests where an advisory's `modified`, severity, affected range, and withdrawn state change between scans.
- Assert unchanged revisions reuse cache and changed revisions rehydrate exactly once.
- Add registry tests for ETag revalidation, `304`, changed ETag/body, missing ETag, and revalidation failure.

## Resolution

- OSV query caches now store strict `{id, modified}` revision records rather than ID-only strings. Pagination deduplicates by advisory ID while retaining the newest timestamp, malformed timestamps fail closed, and legacy query entries are ignored and refreshed.
- Hydrated advisories are keyed by the normalized `(id, modified)` pair and are validated for both fields before reuse. A changed query revision fetches the document again, an older or mismatched hydration response is rejected, and a server response newer than the query is cached under both the requested and actual revision keys. Publication is monotonic per key, so a delayed older document cannot replace a newer alias; alias entries omit representation-mismatched ETags.
- Registry cache lookup now retains stale values and ETags for revalidation. JSON metadata and crates.io sparse-index requests send `If-None-Match`, refresh the stored age without losing the validated body on `304`, atomically replace the entry after a changed `200`, refresh unconditionally when no valid ETag exists, and preserve the stale entry when revalidation fails. Compare-and-swap publication under the cache lock retries concurrent changes, preventing a late `304` or older refresh from overwriting a newer response, including during cache-bypass scans.
- Wiremock coverage exercises legacy OSV migration, severity/range/withdrawal changes, exact unchanged-revision reuse, timestamp-regression rejection, concurrent query and hydration publication, cache-bypass behavior, invalid batch timestamps, registry and sparse-index `304` races, changed body/ETag replacement, absent ETags, and failed revalidation. A live OSV querybatch probe on 2026-08-19 confirmed that current results include the required per-advisory `modified` timestamps.
- Verified with 136 workspace all-target tests on Rust 1.97.1 and locked Rust 1.95.0, formatting, `git diff --check`, and exact `cargo clippy --all-targets -- -D warnings`.
