# DS-010: Scan all .NET projects and central package versions

- **Status:** Closed
- **Priority:** P1
- **Scope:** .NET detection and XML parsing

## Evidence

- `crates/depscan-parsers/src/lib.rs:579-593` selects only the first `*.csproj`/`*.fsproj`/`*.vbproj` and never detects `Directory.Packages.props`.
- `crates/depscan-parsers/src/lib.rs:624-670` can parse `PackageVersion` only when name and version occur in the same file/event; it does not merge central versions with versionless `PackageReference`s.

## Acceptance criteria

- Detect every project under the selected solution/root and the applicable nearest central props files.
- Merge central `PackageVersion` values with per-project `PackageReference` entries, including `Include`/`Update` and nested `Version` elements.
- Preserve per-project source provenance and deduplicate coordinates correctly.
- Continue to prioritize resolved `packages.lock.json` data where present without silently ignoring sibling projects.

## Verification

- Add multi-project fixtures covering C#/F#/VB, central package management, overrides, nested XML version elements, and multiple target frameworks.
- Assert every project/package pair is represented and the correct central override is selected.

## Resolution

- NuGet detection now walks the complete selected tree (excluding generated/vendor directories), retains every C#/F#/VB project, legacy `packages.config`, default lock, and project-specific lock, and lets a lock supersede only the colocated project it resolves. A root lock no longer hides unlocked sibling projects.
- Project parsing resolves the nearest ancestor `Directory.Packages.props`, merges case-insensitive `PackageVersion` entries, applies `Update` metadata and project `VersionOverride`/inline `Version` precedence, supports attribute and nested XML metadata, and reports a versionless unmatched reference as an error.
- Manifest packages retain the project path as source provenance and distinguish exact versions from NuGet ranges/floating versions. `packages.config` preserves `developmentDependency`; resolved lock packages preserve Direct, Transitive, and CentralTransitive metadata while excluding project references.
- Lock versions 1-3, framework maps, package objects, dependency types, and resolved versions are validated fail closed. Malformed XML attributes/elements and incomplete central declarations likewise produce contextual parse errors.
- The checked-in fixture represents C#, F#, VB, a project more than five directories deep, root and project-local locks, multiple target frameworks, nearest central props, central and project updates, nested versions, ranges, a legacy development dependency, an unused central declaration, and malformed cases.
