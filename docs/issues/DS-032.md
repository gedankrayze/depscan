# DS-032: Reject malformed offline advisory documents

- **Status:** Open
- **Priority:** P1
- **Scope:** Offline OSV provider / data integrity

## Evidence

- `crates/depscan-providers/src/lib.rs:554-567` reads each ZIP JSON entry as text and silently `continue`s when JSON decoding fails.
- A corrupt or truncated dump can therefore omit vulnerabilities and produce a false-clean offline scan.

## Acceptance criteria

- Validate ZIP entries and OSV document shape before or during scan; malformed advisory JSON is never treated as absence of findings.
- Corruption identifies the archive and entry and yields a hard offline-data failure (or a clearly defined quarantined-dump policy).
- Enforce per-entry and aggregate decompression/resource limits.
- A failed new sync never replaces a previous valid dump (coordinated with DS-016).

## Verification

- Add archives containing malformed JSON, invalid UTF-8, truncated entries, schema-invalid OSV objects, zip bombs/oversized entries, and one valid empty ecosystem dump.
- Assert corrupt cases cannot exit clean.
