# DS-032: Reject malformed offline advisory documents

- **Status:** Closed
- **Priority:** P1
- **Scope:** Offline OSV provider / data integrity

## Evidence

- `crates/depscan-providers/src/lib.rs:554-567` reads each ZIP JSON entry as text and silently `continue`s when JSON decoding fails.
- A corrupt or truncated dump can therefore omit vulnerabilities and produce a false-clean offline scan.

## Acceptance criteria

- Validate ZIP entries and OSV document shape before or during scan; malformed advisory JSON is never treated as absence of findings.
- Corruption identifies the archive and entry and yields a hard offline-data failure (or a clearly defined quarantined-dump policy).
- Enforce per-entry and aggregate decompression/resource limits.
- A failed new sync never replaces a previous valid dump (coordinated with DS-016).

## Verification

- Add archives containing malformed JSON, invalid UTF-8, truncated entries, schema-invalid OSV objects, zip bombs/oversized entries, and one valid empty ecosystem dump.
- Assert corrupt cases cannot exit clean.

## Resolution

- Offline scans and pre-publication synchronization now use one streaming ZIP-document walker. Every non-directory entry must be an ID-named JSON document with the OSV schema's universally required, typed `id` and `modified` fields; parsing must consume complete valid UTF-8 JSON through EOF, while unknown optional fields remain forward-compatible.
- Validation failures are fail-closed. Offline diagnostics identify the archive and, whenever the ZIP exposes it, the entry; JSON decoding, schema validation, and shared range evaluation errors can no longer become an empty vulnerability result.
- Offline scans enforce the same 2 GiB compressed archive, 2,000,000-entry, 64 MiB per-entry, and 16 GiB aggregate uncompressed limits used by synchronization. Both ZIP-declared and actually decompressed byte counts are bounded, including forged-size and highly compressed inputs.
- A structurally valid archive containing no advisories is accepted as a valid empty ecosystem during a scan. Synchronization retains DS-016's stricter non-empty publication rule and continues to validate the temporary archive before replacing the previous archive and timestamp, so a failed refresh cannot displace known-good data.
- The offline age-marker validation from DS-030 remains ahead of document evaluation, and `RegistryOffline` remains a cache-only, network-free provider.
