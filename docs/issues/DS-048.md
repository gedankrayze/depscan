# DS-048: Make configuration and report file access capability-safe

- **Status:** Closed
- **Priority:** P1
- **Scope:** CLI configuration / report publication / filesystem integrity

_Closed-record excerpts; original dates and versions apply._

## Evidence

- `crates/depscan-cli/src/main.rs` inspects a configuration path with `symlink_metadata` and later reopens the same pathname with `read_to_string`.

- Implicit configured output containment and symlink checks run before provider work, while the final report is written later through the original pathname.

- A concurrent parent or final-component swap between validation and use can therefore make the process read or overwrite a different file than the one it validated.

## Historical resolution

- The CLI opens the scan root once. The same `cap_std::fs::Dir` capability is used to read an implicit `depscan.toml` and is moved into the configured report publisher, closing the former config-to-output handoff race.

- Implicit and explicit configuration files are opened as regular files without following their final component, read from that validated handle, and checked again against their containing capability and file identity.

- Implicit configured reports traverse parent directories with no-follow capability operations, retain the root and parent handles for the complete scan, and publish with a same-directory `cap_tempfile::TempFile`.

- Before publication, the temporary report is flushed, synced, assigned the existing target's portable permissions, and the root, parent, and target identities are rechecked. Replacement is atomic within the held parent directory.

## Historical verification

- Deterministic barrier tests replace the configuration file, output file, and output parent between validation and use. Additional tests cover the config-to-output root handoff, final and parent symlinks, missing targets, atomic replacement, and Unix `0600` preservation.

- [PR CI run 32352263513](https://github.com/gedankrayze/depscan/actions/runs/32352263513)
  passed the complete CLI secure-filesystem suite on native Ubuntu, macOS, and Windows. The Windows
  job exercised held-directory replacement denial-or-detection and completed the full test, release
  CLI, decoy, and dogfood sequence; this records the supported native outcome without claiming that
  the runner granted symlink privileges.
