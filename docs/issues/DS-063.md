# DS-063: Support suffix-aware npm extglobs safely

- **Status:** Closed
- **Priority:** P1
- **Scope:** npm workspace minimatch compatibility

## Evidence

- npm 11 accepts a version 3 lock whose root workspace pattern is `packages/pre!(bad).js` and emits the `packages/pregood.js` descriptor plus its link.
- The bounded Rust workspace matcher deliberately rejects a negative extglob combined with prefix or suffix tokens because a local span-only implementation can incorrectly prove attacker-selected paths as workspaces. For example, npm does not match `packages/ac` against `packages/!(a)*`, while a naive negative-token matcher does.
- Positive extglobs also have suffix-sensitive wildcard behavior: npm does not match `packages/a` against `packages/*@(a|b)` because the standalone `*` becomes non-nullable next to the extglob. A nullable local wildcard would falsely prove that path as a workspace, so DS-057 rejects sequences that combine standalone stars and extglobs.
- DS-057 therefore fails this valid lock closed with exit `10`; it does not silently hide a registry dependency, but the project cannot be scanned until the pattern is supported or rewritten.

## Acceptance criteria

- Implement suffix/remainder-aware positive and negative extglob matching compatible with npm minimatch for prefixed, suffixed, standalone-star, repeated-wildcard, nested, and empty-alternative boundaries.
- Preserve the existing pattern, candidate, expansion, nesting, AST, and match-operation limits; exhausting a bound must remain a parse error.
- Do not broaden cross-component extglobs or any unsupported syntax into a positive workspace match.
- Parse real npm-generated mixed-negative-extglob workspace locks without weakening the forged-link protections from DS-057.

## Verification

- Differential-test a bounded corpus against npm's bundled minimatch, including `pre!(bad).js`, `!(a)*`, `!(a)b`, `a!(b)c`, `*@(a|b)`, `@(a|b)*`, alternatives, nullable suffixes, and nested forms.
- Add a real npm 11 workspace fixture and a forged-link negative control proving valid descriptors are accepted while a nonmatching target exits `10`.
- Run the full workspace suite on Rust stable and MSRV plus exact Clippy.

## Resolution

- The dependency-free component compiler now performs an owned, bounded lowering pass after
  parsing. Every negative extglob receives a copy of its complete component suffix, including
  the remainders of enclosing extglobs, and that copy is lowered again in its new placement.
  This mirrors minimatch's `fillNegs` behavior without reusing root-only wildcard or dot state.
- Plain wildcard chunks retain their part boundaries. An exact `*` chunk becomes non-empty where
  minimatch applies `noEmpty`, while repeated `**` remains two nullable stars in a mixed
  component. Positive alternatives and copied negative suffixes carry their structural
  component-start placement so dot guards apply at the same boundaries as npm. Nullable first
  repetitions can enter minimatch's non-start continuation without escaping the single operation
  budget.
- Matching uses JavaScript UTF-16 code-unit width by default and switches to Unicode-scalar `/u`
  semantics only for the component containing a Unicode-requiring POSIX class, matching npm's
  public `matchOne` behavior. Character classes are parsed over UTF-16 units before that mode is
  selected; pending ranges followed by POSIX fragments become impossible classes, mixed
  `[:graph:]` fragments preserve minimatch's union and dot-source quirks, and equal ranges retain
  explicit-dot behavior. Brace expansion runs before class/extglob parsing, treats commas inside
  brackets and parentheses as brace delimiters, expands braces inside classes, and protects
  `${...}` interpolation text.
- The supported nested matrix includes negative containing positive
  (`!(@(foo|bar)).js`), positive containing negative (`@(!(foo)|bar).js`), and negative inside
  negative (`!(!(foo)).js`), including npm's observable broadening when a negative's final
  alternative ends in an extglob. Trailing-empty negatives such as `!(a|)` and `!()` become
  non-empty wildcards. Whole-component positive empty extglobs retain npm's literal fallback,
  while embedded `@()` follows minimatch's raw-regexp language.
- Existing pattern, candidate, component, brace-expansion, nesting, AST-node, and match-operation
  limits remain in force. Suffix-copy nodes are charged to the single AST budget before their
  combined vector is allocated, and recursive continuations and lookaheads share one match-work
  counter.
- Unsupported but npm-valid constructions fail closed rather than proving a workspace: extglobs
  crossing a path component; any unmatched extglob opener; a character class combining a non-BMP
  scalar with `-`; a repeated `+()` or `*()` body containing a nested all-empty `@()`; and a
  poisoned POSIX-range class whose npm fallback swallows a later `/u`-invalid literal. These
  boundaries avoid JavaScript surrogate-range, first-versus-cloned-body, and swallowed-remainder
  languages that cannot be represented by one lowered alternative safely.
- Forms for which npm 11 throws also fail during compilation. These include nested `@(?())`,
  `@(+())`, and `@(*())`; an empty `?()`/`+()`/`*()` immediately following a broadening negative;
  and illegal identity escapes in a component whose POSIX class activates `/u`. The rejection is
  component-local, so a POSIX class in one path component does not change another component's
  width or escape rules.
- A real npm 11 version 3 workspace fixture uses `packages/pre!(bad).js` with the valid
  `packages/pregood.js` descriptor and link. Process controls rewrite both the link's `resolved`
  target and the concrete descriptor to a structurally complete nonmatch, including the
  suffix-sensitive `packages/!(a)@(*)` versus `packages/a` false-proof trap; each forged lock
  exits `10` before provider access.

  embedded empty alternatives, copied-suffix placement, leading-dot candidates, component-local
  UTF-16/`/u` behavior, class lowering, brace ordering, npm-invalid forms, conservative syntax
  boundaries, and both AST and operation cap failures.
