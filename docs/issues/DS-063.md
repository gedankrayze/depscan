# DS-063: Support suffix-aware npm extglobs safely

- **Status:** Closed
- **Priority:** P1
- **Scope:** npm workspace minimatch compatibility

_Closed-record excerpts; original dates and versions apply._

## Evidence

- npm 11 accepts a version 3 lock whose root workspace pattern is `packages/pre!(bad).js` and emits the `packages/pregood.js` descriptor plus its link.

- The bounded Rust workspace matcher deliberately rejects a negative extglob combined with prefix or suffix tokens because a local span-only implementation can incorrectly prove attacker-selected paths as workspaces. For example, npm does not match `packages/ac` against `packages/!(a)*`, while a naive negative-token matcher does.

- Positive extglobs also have suffix-sensitive wildcard behavior: npm does not match `packages/a` against `packages/*@(a|b)` because the standalone `*` becomes non-nullable next to the extglob. A nullable local wildcard would falsely prove that path as a workspace, so DS-057 rejects sequences that combine standalone stars and extglobs.

## Historical resolution

- The dependency-free component compiler now performs an owned, bounded lowering pass after
  parsing. Every negative extglob receives a copy of its complete component suffix, including
  the remainders of enclosing extglobs, and that copy is lowered again in its new placement.
  This mirrors minimatch's `fillNegs` behavior without reusing root-only wildcard or dot state.

- Plain wildcard chunks retain their part boundaries. An exact `*` chunk becomes non-empty where
  minimatch applies `noEmpty`, while repeated `**` remains two nullable stars in a mixed
  component. Positive alternatives and copied negative suffixes carry their structural
  component-start placement so dot guards apply at the same boundaries as npm. Nullable first
  repetitions can enter minimatch's non-start continuation without escaping the single operation
  budget.

## Historical verification

- The focused matcher regressions cover prefixed and suffixed positive/negative extglobs,
  exact-star adjacency, repeated wildcards, all three nested-operator directions, trailing and
  embedded empty alternatives, copied-suffix placement, leading-dot candidates, component-local
  UTF-16/`/u` behavior, class lowering, brace ordering, npm-invalid forms, conservative syntax
  boundaries, and both AST and operation cap failures.
