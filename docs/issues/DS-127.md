# DS-127: Preserve the machine PATH registry type across MSI operations

- **Status:** Closed
- **Priority:** P2
- **Scope:** Windows MSI environment-component lifecycle

## Finding

Native verification on Windows 11 Pro x64 (build 26300, PowerShell 5.1) reproduced
a machine PATH registry-type change with the immutable v3.0.0 MSI. The existing
`HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Environment\Path` was
`REG_EXPAND_SZ`; installation changed it to `REG_SZ`. Repair and uninstall retained
`REG_SZ`, even though uninstall restored the PATH text exactly.

The package's generated WiX `Path` component appends `[Bin]` through an
`Environment` row and does not preserve the pre-existing registry type. Attribution
to a particular Windows Installer or WiX implementation detail remains unproven.
The original PATH contained no expandable references, so no expansion-related command
failure was observed during discovery.

## Evidence

- MSI SHA-256: `d90ec3f9b94815549c7f487e97f1fa7fb5caa485d23ab694a40b2df45f2d0c20`.
- Product code: `{0A3A60DA-99CB-4DC2-981A-845A51511704}`; per-machine scope.
- Install, missing-executable repair, and uninstall each returned `0`.
- The installed/repaired executable matched the independently authenticated ZIP;
  version/help, offline summary, schema 4/reproducible timestamp, and provider exit
  `30` checks passed. Product registration, default directory, executable, and PATH
  entry were removed; user PATH stayed unchanged. No reboot was required.
- The original machine PATH type was restored explicitly under an exact-value
  guard after testing. This manual cleanup is not a product fix.

See the [native MSI review](../reviews/2026-11-24-native-msi.md) for the protocol,
test-method limitations, and accepted evidence.

## Resolution

The fix is qualified locally for v3.0.1. Closure covers the code fix; publication
and public native acceptance are tracked separately in DS-128.

A native DLL captures only the original registry type, then restores that type over
the current PATH bytes after MSI's environment and old-product operations. Its
deferred/rollback exports write only the fixed machine PATH value; no registry path,
PATH snapshot, shell command or executable path comes from action properties.
Unsupported captured types and malformed retyped data fail closed. Missing values
are not recreated.

Major upgrades run after `InstallExecute`, preserving the existing component GUIDs;
the rollback action precedes environment changes. This ensures old-package removal
and rollback cannot undo type restoration. MSVC warnings and WiX validation are
errors. Source checks replace cargo-dist's managed MSI generation check; compiled
MSI checks enforce the privileged action flags and execution order.

The Windows CI job runs native registry fixtures, install/repair/uninstall, forced
rollback, successful/failed upgrades, both PATH types and expansion references.
Local Windows 11 tests also cover upgrade and rollback from the published MSI.
All fixed-package cycles preserve text/type automatically; legacy-package cleanup
is identified separately. See the linked review for final qualification evidence.

The immutable v3.0.0 asset remains affected; this source fix requires a new release.

## Acceptance criteria

Preserve existing PATH text, entry order, unrelated entries, user environment, and
registry type through installation, repair, upgrade, and uninstall. Add native MSI
lifecycle regression coverage, including expandable-reference cases on a disposable
host. Do not add unreviewed privileged custom actions or claim the immutable v3.0.0
MSI is fixed; any changed package requires a separately authorized release.
