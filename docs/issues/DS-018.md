# DS-018: Prevent sparse-index path panics on invalid crate names

- **Status:** Open
- **Priority:** P1
- **Scope:** crates.io provider / input validation

## Evidence

- `crates/depscan-providers/src/lib.rs:799-805` branches on UTF-8 byte length and slices `&name[0..1]`, `&name[0..2]`, and `&name[2..4]` directly.
- A non-ASCII or otherwise invalid crate name can make those offsets fall inside a character and panic.
- Parsed manifest/lock data is untrusted and currently reaches this code without crates.io name validation.

## Acceptance criteria

- Validate crates.io package-name syntax before sparse path generation.
- Generate prefixes using safe ASCII bytes/characters only; invalid names return a typed per-package error and never panic.
- Keep correct one-, two-, three-, and four-plus-character sparse-index paths.

## Verification

- Add table and property/fuzz tests for valid boundary names, empty strings, Unicode, path separators, control characters, and very long names.
- Assert every invalid input returns an error under `catch_unwind`/fuzz execution and emits no HTTP request.
