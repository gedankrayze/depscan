# DS-009: Support Yarn Berry lockfiles

- **Status:** Closed
- **Priority:** P1
- **Scope:** Yarn parser

## Evidence

- `crates/depscan-parsers/src/lib.rs:328-362` implements only the Yarn v1 line format (`version ...`).
- Audit fixture evidence: a Yarn Berry YAML-style lockfile produced zero packages.

## Acceptance criteria

- Detect Yarn v1 versus Berry syntax and parse both supported formats.
- For Berry, extract ident/name, resolved version, source/protocol, workspace exclusions, and directness without treating descriptors as versions.
- Unsupported future lock metadata versions return an actionable error rather than an empty clean scan.

## Verification

- Add Yarn v1 and current Berry fixtures with scoped packages, multiple descriptors, workspaces, and non-registry protocols.
- Assert a non-empty expected package snapshot and an error for an unsupported schema.

## Resolution

- Yarn format detection now requires either the Classic v1 marker or Berry `__metadata`; unrecognized input is rejected instead of becoming an empty clean result.
- Berry metadata versions 4 through 10 are decoded explicitly. Version 10 is the format written by the current stable Yarn 4.18.0 release, while later or malformed metadata returns a source-qualified parse error.
- Berry entries use their `resolution` locator for the registry identity and their `version` field for the resolved version. Scoped names and npm aliases are preserved, workspace locators are excluded, and non-registry locators remain visible with enrichment disabled.
- Classic v1 parsing now validates entry boundaries, quoted selector lists, versions, aliases, and mixed-source groups while retaining its handwritten format parser.
- Direct and development-only flags are derived from root and workspace manifest dependency groups. Production use wins when the same package also appears in a development group.
