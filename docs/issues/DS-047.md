# DS-047: Make offline sync publication capability-safe during directory swaps

- **Status:** Closed
- **Priority:** P1
- **Scope:** Offline OSV synchronization / concurrent filesystem boundary

_Closed-record excerpts; original dates and versions apply._

## Evidence

- DS-016 validates the sentinel-owned cache root and canonical `offline` child before lock acquisition and publication, and it uses open file handles for transfer and ZIP validation.

- Final temporary-file cleanup and publication still address the child by pathname. A process able to rename the `offline` directory and replace it with a symlink between validation and a pathname operation can create a time-of-check/time-of-use race.

- Detected swaps preserve temporary recovery files instead of following the changed namespace, but repeated path validation cannot make the remaining publication sequence race-free.

## Historical resolution

- Synchronization now opens the validated cache root and `offline` child as `cap_std` directory capabilities. The ownership sentinel is opened without following the final component, its identity is checked across the read, and root/child identities are retained for attachment checks.

- Lock creation, abandoned-temp enumeration and removal, archive and marker temporary creation, previous-archive reads, hard-link/copy rollback staging, final renames, restoration, and RAII cleanup are all relative to the held `offline` handle. No operation reconstructs an ambient child pathname after capability acquisition.

- Capability-owned temporary files keep the recognizable per-ecosystem suffixes needed for crash reclamation. Publication drops the open temporary handle and performs a same-directory relative rename; a marker failure restores the pre-staged archive, and a failed restore retains the last rollback copy instead of deleting it.
