# DS-093: Refresh the dist-pinned actions/checkout to the v7 line

- **Status:** Closed
- **Priority:** P2
- **Scope:** Release workflow action pins

## Evidence

- The 2026-08-21 review found hand-written workflows on `actions/checkout` v7.0.1 while the
  cargo-dist-generated `release.yml` (five sites) and `release-quality.yml` remain on v6.0.2 via
  the `[workspace.metadata.dist.github-action-commits]` pin in `Cargo.toml`. Renovate ignores
  both generated workflows, so only a manual dist-metadata bump plus `dist generate` updates
  them.

## Acceptance criteria

- The dist metadata pins checkout's reviewed v7 commit, the workflows are regenerated, and
  `scripts/verify-release-workflow.sh` still passes. Treat as a release-sensitive change
  (`dev-gate.sh release`, `dist generate --check`).

## Verification

- `dist generate --check`, `bash scripts/verify-release-workflow.sh`,
  `bash scripts/dev-gate.sh release`.

## Resolution

- The checkout pin moved to the already-reviewed v7.0.1 commit
  (`3d3c42e5aac5ba805825da76410c181273ba90b1`, the same SHA the hand-written and acceptance
  workflows trust) in all four coupled surfaces: the five `release.yml` sites, the
  `release-quality.yml` site, the `[workspace.metadata.dist.github-action-commits]` record,
  and the reviewed pin/count contract in `scripts/verify-release-workflow.sh`.
- `allow-dirty = ["ci"]` records that the workflow is generated-then-hand-hardened, so the
  reviewed pin edit plus the workflow verifier remains the sanctioned update path rather than
  replacing the hardened workflow with raw generated output.

## Local verification evidence

- `scripts/verify-release-workflow.sh` passes with the new pin (it enforces both the SHA count
  and the dist-metadata record). Release-mode gates pass: the full gate suite, then
  `cargo package --workspace --allow-dirty --locked` verifying all five crates (after purging
  a stale local packaging cache — see DS-095), then a clean
  `cargo build --release --locked -p depscan-cli`.
- During the 2.0.0 preparation, the checksum-verified cargo-dist 0.32.0 binary also passed
  `dist generate --check` and produced the reviewed 16-file plan for `v2.0.0`.
