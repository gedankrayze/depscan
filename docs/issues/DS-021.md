# DS-021: Preserve auditable suppression details

- **Status:** Open
- **Priority:** P1
- **Scope:** Core model / configuration / JSON and human reports

## Evidence

- `crates/depscan-cli/src/main.rs:121-126` parses suppression reason and expiry.
- `crates/depscan-cli/src/main.rs:186-197` reduces valid configured ignores to an ID set, discarding reason and expiry.
- `crates/depscan-cli/src/main.rs:261-284` removes the full vulnerability and stores only its ID in `ScanResult.suppressed`.
- This conflicts with the stable JSON contract requiring full suppressed findings marked as suppressed and prevents audit of justification/expiry.

## Acceptance criteria

- Model a suppression with the complete vulnerability, matched ID/alias, source (CLI/config), reason, optional expiry, and active/expired state.
- Active suppressions do not affect failure thresholds but remain present in all appropriate reports and counts.
- Expired suppressions are not applied and are loudly represented in diagnostics/report metadata.
- JSON schema remains versioned and receives an intentional compatibility decision if its shape changes.

## Verification

- Add tests for direct ID, alias, CLI ignore, configured reason/expiry, expired entries, and duplicate suppression rules.
- Snapshot JSON/table/summary/SARIF behavior and assert secrets or unrelated config fields are not exposed.
