# DS-021: Preserve auditable suppression details

- **Status:** Closed
- **Priority:** P1
- **Scope:** Core model / configuration / JSON and human reports

## Evidence

- `crates/depscan-cli/src/main.rs:121-126` parses suppression reason and expiry.
- `crates/depscan-cli/src/main.rs:186-197` reduces valid configured ignores to an ID set, discarding reason and expiry.
- `crates/depscan-cli/src/main.rs:261-284` removes the full vulnerability and stores only its ID in `ScanResult.suppressed`.
- This conflicts with the stable JSON contract requiring full suppressed findings marked as suppressed and prevents audit of justification/expiry.

## Acceptance criteria

- Model a suppression with the complete vulnerability, matched ID/alias, source (CLI/config), reason, optional expiry, and active/expired state.
- Active suppressions do not affect failure thresholds but remain present in all appropriate reports and counts.
- Expired suppressions are not applied and are loudly represented in diagnostics/report metadata.
- JSON schema remains versioned and receives an intentional compatibility decision if its shape changes.

## Verification

- Add tests for direct ID, alias, CLI ignore, configured reason/expiry, expired entries, and duplicate suppression rules.
- Snapshot JSON/table/summary/SARIF behavior and assert secrets or unrelated config fields are not exposed.

## Resolution

- JSON schema version `2` replaces suppressed advisory-ID strings with deterministic audit objects containing the complete vulnerability, active state, and every distinct matching rule's ID/alias, CLI/config source, reason, expiry, and active/expired state. The compatibility decision and migration are documented in `README.md`.
- Active matches are removed from vulnerability failure thresholds while remaining visible in table, JSON, SARIF (with accepted external suppression metadata), summary totals, and the core document. Expired matches remain actionable, produce stderr warnings, and render as explicit expired-ignore findings, including when another rule actively suppresses the same advisory.
- Standard TOML local dates and quoted `YYYY-MM-DD` strings are accepted for expiry. Repeated identical rules are canonicalized, while distinct direct/alias and CLI/config matches are retained.
- Process tests cover direct IDs, aliases, repeated CLI rules, config reason/expiry, expired rules, full finding retention, schema versioning, and exit behavior. Renderer tests cover all four formats and verify suppression/expired totals and SARIF metadata.
- Verified on Rust 1.97.1 with `cargo fmt --all -- --check`, 98 workspace all-target tests, and exact `cargo clippy --all-targets -- -D warnings`; the same 98 tests pass locked on the Rust 1.95.0 MSRV.
