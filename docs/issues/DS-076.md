# DS-076: Add an auditable Markdown report format

- **Status:** Closed
- **Priority:** P2
- **Scope:** Human-readable Markdown reporting across the CLI and composite GitHub Action

_Closed-record excerpts; original dates and versions apply._

## Evidence

- The CLI supports terminal tables, JSON, SARIF, and a one-line summary, but none of those formats
  is directly suitable for durable pull-request comments, job summaries, or repository audit files.

- The composite action validates report formats independently, so adding only a CLI enum would
  leave action consumers unable to request the new format.

- Package names, advisory summaries, provider diagnostics, and suppression reasons are external
  text and must not be allowed to inject Markdown tables, links, images, or raw HTML.

## Historical resolution

Implemented an explicit, opt-in Markdown report without changing the existing terminal or
redirected-output defaults. The renderer lives in its own bounded module, reuses the report's
canonical totals and dependency-status decisions, and emits summary, vulnerability,
dependency-status, suppression, and soft-failure sections. Dynamic table cells escape Markdown,
raw HTML, controls, and line breaks. A compact provenance line beneath the title identifies Gedank
Rayze DepScan, the compiled package version, and the canonical GitHub repository when the report is
shared independently. `.md` and `.markdown` infer the format, while the CLI and composite Action
also accept the typed `markdown` value directly.

The additive public report and CLI contract moved the workspace and internal dependency
requirements from `1.1.0` to `1.2.0`. Packaging all five crates through Cargo's temporary registry
proved that the CLI consumes the packaged `depscan-report` API rather than an already-published
older crate.
