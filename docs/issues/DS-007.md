# DS-007: Parse Bun text-lock locators correctly

- **Status:** Open
- **Priority:** P1
- **Scope:** Bun parser

## Evidence

- `crates/depscan-parsers/src/lib.rs:221-246` treats the first element of a Bun package array as the resolved version.
- In current Bun text locks that element is a locator such as `name@1.2.3`, not the bare version required by the package model and providers.

## Acceptance criteria

- Parse the supported Bun lock schema explicitly and extract package name, resolved version, source, dev/directness, and workspace semantics correctly.
- Reject malformed locator arrays with a useful parse error; never send a locator string as the OSV version.
- Preserve scoped package names and aliases.

## Verification

- Add fixture snapshots from current Bun lockfile formats, including scoped packages, workspaces, aliases, and malformed entries.
- Assert all produced versions parse as the intended version model and contain no package locator prefix.
