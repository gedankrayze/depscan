# DS-044: Strengthen CLI help and typed value parsing

- **Status:** Closed
- **Priority:** P1
- **Scope:** CLI usability / early validation

## Evidence

- Most arguments at `crates/depscan-cli/src/main.rs:48-90` have no doc comments/help text and use raw `String` values.
- Ecosystems, thresholds, formats, and durations are validated manually only after Clap parsing at `crates/depscan-cli/src/main.rs:355-402`, so shell completion/help cannot advertise allowed values and error behavior is inconsistent.
- Conflicts and requirements between offline/cache/output/log options are not expressed in the command model.

## Acceptance criteria

- Use typed Clap value enums/parsers for ecosystems, formats, thresholds, durations, and other closed sets, with correct value names and actionable errors.
- Provide concise help and long help describing defaults, repeatability, precedence, security implications, output/exit behavior, and best-effort ecosystem limits.
- Encode genuine conflicts/requirements in Clap and keep usage/config failures mapped to code `10` under DS-019.
- Generated completions include the allowed values.

## Verification

- Snapshot top-level/subcommand help and completions for representative shells.
- Add process tests for every invalid value, conflict, repeatable option, inferred format, and help/version exit.

## Resolution

- Replaced raw CLI strings with typed Clap values for the four ecosystems, four report formats, vulnerability and staleness thresholds, completion shells, and checked cache durations. Ecosystem parsing preserves the prior case-insensitive aliases while help/completions advertise only canonical values; `powershell` is now canonical and the former `power-shell` spelling remains a hidden compatibility alias.
- Cache durations now accept exactly a non-negative integer plus `s`, `m`, `h`, or `d`, use Chrono's checked constructors, and distinguish missing/bad units, negative input, integer overflow, and duration-range overflow without panicking.
- Root and subcommand help now document default command/path behavior, auto-detection and best-effort provenance limits, repeatability, format and config precedence, stdout/stderr separation, offline/cache semantics, withdrawn behavior, all exit codes, safe cache clearing, and the `--allow-tools` execution risk. Suppression help explicitly warns that configured reasons are report data rather than secret storage.
- Clap rejects quiet/verbose conflicts and missing cache/completion arguments before application work. Offline/no-cache/max-age, explicit format/output, and other meaningful combinations remain valid. Unknown output extensions now fail before provider access unless an explicit format is supplied.
- Failure policies use the typed thresholds directly, removing silent string fall-through behavior. Output inference is now explicit format, then recognized output extension, then TTY table/non-TTY summary when no output file is requested.
