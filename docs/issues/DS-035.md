# DS-035: Isolate partial OSV failures as per-package soft errors

- **Status:** Open
- **Priority:** P1
- **Scope:** Online enrichment / error model

## Evidence

- `crates/depscan-providers/src/lib.rs:371-372` aborts the entire query on any chunk failure.
- Hydration collects all futures into one `Result` at `crates/depscan-providers/src/lib.rs:393-405`, so one advisory hydration failure aborts every package.
- `crates/depscan-cli/src/main.rs:235-245` maps any OSV provider error to a total scan failure, despite the specification defining isolated package lookup failures as soft errors.

## Acceptance criteria

- Attribute query-page and hydration failures to affected packages/advisories while returning successful results for unaffected packages.
- Promote to hard provider failure only when the provider is wholly unusable and no usable cache/result exists, with a documented threshold/decision.
- Never represent a failed package query as a clean empty advisory list or cache partial results as complete.
- Surface soft errors in `ScanResult.errors` and all relevant reports.

## Verification

- Add multi-chunk/multi-advisory mocks where exactly one chunk, page, or hydration fails and assert unaffected results remain complete.
- Add a total-outage case asserting exit `30` and partial cases asserting report visibility without false-clean cache entries.
