# DS-035: Isolate partial OSV failures as per-package soft errors

- **Status:** Closed
- **Priority:** P1
- **Scope:** Online enrichment / error model

_Closed-record excerpts; original dates and versions apply._

## Evidence

- `crates/depscan-providers/src/lib.rs:371-372` aborts the entire query on any chunk failure.

- Hydration collects all futures into one `Result` at `crates/depscan-providers/src/lib.rs:393-405`, so one advisory hydration failure aborts every package.

- `crates/depscan-cli/src/main.rs:235-245` maps any OSV provider error to a total scan failure, despite the specification defining isolated package lookup failures as soft errors.

## Historical resolution

- `VulnProvider` now returns a typed `VulnQueryOutcome` containing both the trustworthy vulnerability map and `Package::key`-scoped enrichment errors. The CLI merges OSV and registry errors into each package's `ScanResult.errors`; JSON and table output retain their existing visibility, summary output now includes the soft-failure count, and SARIF emits `DEPSCAN-PROVIDER-ERROR` warning results with package and provider properties.

- Query-batch parsing separates whole-response failures from aligned per-result failures. A failed chunk affects only that chunk; a later pagination request affects only queries still carrying page tokens; and a malformed aligned result does not discard valid sibling results. Revision lists are published to the query cache only after every page for that package completes, so accumulated IDs from an incomplete query never become a clean cache entry.
