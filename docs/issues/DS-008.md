# DS-008: Retain nested npm v2/v3 packages

- **Status:** Closed
- **Priority:** P1
- **Scope:** npm `package-lock.json` parser

## Evidence

- `crates/depscan-parsers/src/lib.rs:179-193` strips one leading `node_modules/` component and then drops every key that still contains `node_modules/`.
- npm lockfile versions 2 and 3 can place distinct resolved versions at nested paths, so those transitive packages disappear from vulnerability scanning.

## Acceptance criteria

- Derive the package identity from the final `node_modules` segment, including scoped names.
- Retain distinct name/version instances at nested paths and deduplicate only identical package coordinates.
- Mark direct/dev metadata from lockfile/root manifests without losing nested transitives.

## Verification

- Add npm v2 and v3 fixtures with hoisted and nested duplicate package names at different versions, plus scoped nested packages.
- Snapshot normalized packages and assert every resolved coordinate is scanned.

## Resolution

- Package identities now come from the final `node_modules` segment, preserving scoped names and every nested resolved version while rejecting malformed location keys.
- Root descriptors, link records, and local workspace target descriptors are skipped; resolved dependencies beneath workspace targets remain scan candidates.
- Directness is matched to root/workspace manifests at the package's install parent, legacy v1 directness is restricted to the top-level tree, and lockfile `dev` metadata is preserved through coordinate-only deduplication.
- Fixture-backed inline snapshots cover lockfile versions 1, 2, and 3, including duplicate versions, identical-coordinate deduplication, scoped dependencies, development transitives, workspaces/links, malformed entries, and source-file provenance.
