# DS-053: Clarify atomic issue-and-fix commits

- **Status:** Closed
- **Priority:** P2
- **Scope:** Audit ledger / commit policy

## Evidence

- The ledger workflow required selecting one open issue and committing each completed issue separately, but did not say whether the issue record itself needed an earlier standalone commit.
- DS-049 through DS-052 each have one bounded, substantive, issue-tagged commit, but their issue record and verified fix were introduced atomically. A history-only audit could therefore interpret the workflow more strictly than the user's instruction to commit only after the selected issue is fixed.
- Requiring an issue-only precursor commit would add history churn without improving isolation, verification, or traceability.

## Acceptance criteria

- Explicitly permit an issue record and its bounded fix to land atomically after acceptance criteria and verification pass.
- Require the issue to be selected as `Open` or `In progress` in the working tree while implementation is underway; only the verified committed state may be `Closed`.
- Continue to require one separately reviewable fix scope per issue commit and the `DS-*` ID in the commit subject. A standalone issue-only commit remains optional.
- Verify that the issue files, ledger index, traceability matrix, and issue-tagged commit history remain complete and sequential.

## Resolution

- The ledger workflow now states the atomic issue-and-fix rule directly while retaining one-issue-per-commit isolation and evidence-before-closure requirements.
- This clarification preserves the existing DS-049 through DS-052 history: each commit is substantive, bounded to its named issue, and was created only after its implementation gates passed.

## Verification evidence

- The committed tree contains sequential `DS-001` through `DS-053` issue files, 53 matching ledger rows, and 53 matching traceability rows.
- Every issue ID has a matching issue-tagged commit subject; the atomic DS-049 through DS-053 commits are valid under the clarified rule.
- `git diff --check` passed before commit.
