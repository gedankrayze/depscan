# DS-117: Require fresh dependency checks and scoped post-push cleanup

- **Status:** Closed
- **Priority:** P2
- **Scope:** Contributor pre-push gate and post-push resource lifecycle

## Evidence and resolution

The incoming-PR preflight did not check crate freshness or new advisories. Added
locked stable-manifest, full-lockfile, and fresh advisory checks after PR triage.
Missing tools, registry failures, offline mode, outdated requirements, stale lock
resolutions, and audit warnings must fail the gate rather than reuse old evidence.

A real negative control found that combining Cargo's `--dry-run` with `--locked`
returns success even when updates exist. The gate deliberately omits `--dry-run`:
`cargo update --locked` fails with exit 101, while cargo-edit's locked upgrade
fails with exit 1 for outdated requirements. Both preserve candidate bytes.

AGENTS.md and the [maintenance guide](../maintenance.md) require post-push cleanup
after needed CI/artifact acceptance: unused task-owned images, artifacts, caches,
temporary files, and worktrees. Inventory, exact ownership/consumers, recoverable
managed-worktree archival, stash hashes, and retained release evidence are mandatory.
No blanket Docker prune, shared-cache deletion, unrelated worktree removal, volume
deletion, or immutable public-asset deletion is authorized by that rule.

## Verification

Eight maintenance/manifest tests and seven existing hook tests pass, together with
real stale-file controls, current-candidate freshness/audit, shell lint, automation
checks, and the final release gate. No remote push or destructive post-push cleanup
occurs in this task; unrelated resources and the stash are preserved.
