# DS-065: Keep platform-gated CLI tests warning-free on Windows

- **Status:** Closed
- **Priority:** P1
- **Scope:** CLI test compilation / native Windows quality gate

## Evidence

- The first protected `develop -> main` pull request ran the required native Windows quality job
  and failed during `cargo clippy --all-targets -- -D warnings`.
- `secure_fs` imported `Arc`, `Barrier`, and `thread` for tests that are compiled only on
  non-Windows targets. The CLI exit-code integration harness likewise imported `Stdio`, `thread`,
  `Duration`, and `Instant` for a process-race test compiled only on Unix debug builds.
- On Windows those helpers had no compiled use, so the workspace's warnings-as-errors contract
  rejected both the CLI test binary and the exit-code test harness before the native test suite
  could run.

## Acceptance criteria

- Gate platform-specific test imports with the same conditions as their consumers; do not add an
  unused-import allowance or weaken the exact Clippy command.
- Preserve the non-Windows secure-filesystem race tests and the Unix debug-only requirements
  process-race test unchanged.
- Pass the exact all-target Clippy gate locally and in the protected native Windows quality job.
- Pass formatting, diff, and focused CLI test gates before pushing the correction.

## Verification

- Run `cargo clippy --all-targets -- -D warnings`.
- Run the focused CLI secure-filesystem and exit-code test harnesses.
- Run `cargo fmt --all -- --check` and `git diff --check`.
- Record the successful native Windows quality run before closing.
