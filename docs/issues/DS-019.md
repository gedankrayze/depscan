# DS-019: Implement the specified exit-code taxonomy

- **Status:** Open
- **Priority:** P1
- **Scope:** CLI error classification

## Evidence

- `crates/depscan-cli/src/main.rs:150-156` maps every returned error to provider hard-failure code `30`.
- Validation and config errors originate at `crates/depscan-cli/src/main.rs:169-185` and `344-386`, so they also exit `30` instead of specified usage/config code `10`.
- Clap's default parser exits `2` for unknown options before this mapping; specified code `10` is never produced for that case.

## Acceptance criteria

- Typed CLI errors map deterministically to: `0` clean, `1` vulnerability threshold, `2` outdated threshold, `10` usage/config, `20` no supported project, and `30` provider hard failure.
- When vulnerability and outdated thresholds both fail, exit `1`.
- Parse errors, invalid paths, invalid values, and invalid config are classified intentionally and documented.
- Diagnostics stay on stderr and reports on stdout/output files.

## Verification

- Add process-level CLI tests for every exit code and precedence case, including unknown flags and malformed config.
- Assert stdout/stderr separation for each failure class.
