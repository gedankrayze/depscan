# DS-089: Reduce test-only conditional compilation woven through the sync service

- **Status:** Closed
- **Priority:** P2
- **Scope:** OSV sync readability / test architecture

## Evidence

- The 2026-08-21 code review found `OsvSyncConfig`
  (`crates/depscan-providers/src/osv/sync/download.rs`) carrying four `#[cfg(test)]` fields with
  matching `#[cfg(test)]` branches threaded through `service.rs` and `download.rs` (31 such
  sites outside `src/tests/` in the crate), which makes the sync happy path harder to read than
  its logic warrants.
- `crates/depscan-providers/src/tests/mod.rs` needs `#[path = "osv/mod.rs"] mod osv_cases;`
  workarounds because `use super::osv::*` already binds the natural module names.

## Acceptance criteria

- Test hooks consolidate behind one seam (a test-only trait impl, builder, or injected hook
  struct) so production functions read linearly; the `#[path]` gymnastics disappear or gain a
  brief comment explaining the collision.

## Verification

- `cargo test -p depscan-providers` and the architecture check.
- `bash scripts/dev-gate.sh full`

## Resolution

- The four test-only config fields consolidated into one `#[cfg(test)] OsvSyncTestHooks`
  struct behind a single field and a `Default` initializer, and the boundary checkpoints
  became an always-present `OsvSyncConfig::checkpoint(directory, boundary)` — in production a
  named revalidation point, under test also the injection-hook trigger. Chunk observation and
  stream progress moved behind always-present no-op helper methods. `OsvSyncBoundary` is now
  an unconditional enum since production names its checkpoints with it.
- Net effect: the sync happy path in `service.rs` and the streaming loop in `download.rs` read
  linearly with zero interleaved `#[cfg(test)]` blocks except the single forced-failure
  injection; conditional compilation in the sync production files dropped from seventeen
  interleaved sites to the hooks definition plus three helper bodies.
- The `#[path = "..."]` module declarations in the provider test tree gained the brief comment
  the issue asked for, explaining the name collision with the glob-imported production
  modules.

## Local verification evidence

- All 132 provider tests pass, including every boundary-injection swap-safety test, the chunk
  and progress observation tests, and the forced-rollback test, now driving the hooks through
  the consolidated seam. Architecture check and workspace clippy clean via the pre-commit
  gate.
