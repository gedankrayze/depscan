# DS-095: Purge stale packaging caches before release-gate verification

- **Status:** Closed
- **Priority:** P2
- **Scope:** Local release-gate reliability

## Evidence

- On 2026-08-21, `dev-gate.sh release` failed `cargo package --workspace` with an unresolved
  import that existed in every packaged tarball. Cause: package verification resolves workspace
  crates through a local overlay registry keyed by the unchanged version `1.2.0`; a stale
  extraction under `~/.cargo/registry/src/-*/depscan-core-1.2.0` from an earlier gate run
  seeded a compiled artifact in `target/debug/deps`, and registry-immutability fingerprints
  kept both alive across `cargo clean`-then-rebuild cycles even after the sources changed.
- The same mechanism can also produce the opposite and worse failure: a gate that silently
  verifies week-old sources and reports success.

## Acceptance criteria

- The release gate purges the depscan-specific packaging caches (packaged tarballs, overlay
  registry extractions and cached crates, and the workspace crates' compiled dep artifacts)
  before running `cargo package`, so verification always compiles current sources.
- The purge stays scoped to this workspace's crates; it must not clear unrelated registry
  caches.

## Verification

- With a deliberately stale overlay extraction in place, `dev-gate.sh release` passes where it
  previously failed; a normal run also passes.

## Resolution

- `dev-gate.sh` release mode now runs a `purge_packaging_caches` step before `cargo package`:
  it removes `target/package`, `depscan-*` entries under local-overlay registry directories
  (`~/.cargo/registry/{src,cache}/-*/`), and the workspace crates' `deps`/`.fingerprint`
  artifacts, forcing package verification to compile current sources.

## Local verification evidence

- Reproduced the failure, then confirmed the purge sequence turns the same tree green:
  `cargo package --workspace --allow-dirty --locked` verifies all five crates (exit 0) after
  the purge, where before it failed on a symbol present in every tarball. A follow-up
  `dev-gate.sh release` run passes end to end.
