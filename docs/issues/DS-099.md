# DS-099: Support Bun 1.4 lockfile versions and validation

- **Status:** Closed
- **Priority:** P1
- **Scope:** Bun text-lock parser, fixtures, specification parity, and product positioning

## Evidence

- [Bun 1.4](https://bun.com/blog/bun-v1.4) writes new text lockfiles as
  `lockfileVersion: 2` and writes version 3 when nested or version-scoped overrides are
  present. Bun continues to load versions 0 and 1.
- A Bun 1.4.0-generated version 2 lock reached DepScan's provider stage, while a generated
  version 3 lock failed with exit `10` because the parser explicitly accepted only versions
  0 through 2.
- Version 2 adds fail-closed validation for off-registry npm tarballs without supported
  integrity and unsafe Git checkout tags. The parser validated only tuple types and lengths.
- `configVersion` controls Bun's linker layout rather than the resolved dependency graph.
  DepScan reads `bun.lock` or `package.json` and never falls back to walking `node_modules`,
  so Bun's isolated global virtual store does not change its dependency source boundary.
- Bun 1.4 adds native audit remediation, duplicate checking, production pruning, license
  inventory, and dependency diff commands. Those complement rather than replace DepScan's
  four-ecosystem OSV, offline, SARIF, deterministic-report, and auditable-suppression scope.

## Acceptance criteria

- Preserve versions 0 and 1, accept Bun 1.4 versions 2 and 3, and continue to reject an
  unsupported future `lockfileVersion` without producing a false-clean report.
- Treat the resolved `packages` graph as authoritative. Nested and version-scoped overrides
  must retain their concrete resolved versions without reimplementing Bun's resolver.
- Validate optional `configVersion` as a non-negative integer without coupling dependency
  parsing to the hoisted or isolated installation layout.
- For version 2 and later, reject off-default-registry npm records without a supported SRI
  hash and reject unsafe Git resolved tags. Preserve Bun's unconditional GitHub-tag guard.
- Check in Bun 1.4.0-generated v2, nested-override v3, and version-scoped-override v3 fixtures,
  plus malformed security-boundary and future-version controls.
- Update the development-specification errata, README, issue ledger, and test matrix. Lead
  product positioning with the cross-ecosystem, offline, SARIF, and suppression boundaries.

## Verification

- `cargo test -p depscan-parsers --test bun_lock`
- Bun 1.4.0 lockfile generation plus a process-level scan of the generated v3 fixture
- `bash scripts/dev-gate.sh quick`
- `bash scripts/dev-gate.sh full`
- `git diff --check` and final architecture/diff review

## Resolution

- Added an explicit Bun lock-version model that preserves v0/v1, accepts v2/v3, and rejects
  v4. Optional `configVersion` is validated independently and does not change parsing.
- Version 3 reads concrete registry identities and versions from the resolved `packages` graph.
  Nested overrides retain both the unaffected and overridden resolutions, while version-scoped
  overrides retain the version Bun selected.
- Version 2 and 3 off-default-registry npm rows require a supported SHA-1/SHA-2 SRI value.
  Git tags are restricted to Bun's bounded safe-component grammar for v2/v3, and GitHub tags
  retain the same guard for every supported lock version.
- Added Bun 1.4.0-generated v2, nested-override v3, and version-scoped-override v3 fixtures,
  positive and negative integrity controls, Git/GitHub traversal controls, `configVersion`
  compatibility controls, and v4 future-schema sentinels.
- Updated the specification errata, supported-source contract, test matrix, issue ledger, and
  README positioning. Bun's native remediation and inventory commands are documented as
  complements to DepScan's cross-ecosystem policy and reports.

## Validation evidence (2026-08-24)

- Bun 1.4.0 generated all three current-format fixtures, and `bun install --lockfile-only
  --frozen-lockfile --ignore-scripts` accepted each one without rewriting it.
- `cargo test -p depscan-parsers --test bun_lock` passed all 5 tests; the schema-validation
  matrix passed all 6 tests after moving its future Bun sentinel from v3 to v4.
- A real CLI scan of the nested-override v3 fixture advanced through parsing and exited `30`
  only for the deliberately absent offline npm dump. The malformed off-registry fixture exited
  `10` before provider access with its package-qualified integrity error.
- `bash scripts/dev-gate.sh quick` passed.
- `bash scripts/dev-gate.sh full` passed under Rust 1.98.0: architecture, automation and CI
  policy verifiers, formatting, exact strict Clippy, 434 tests with one intentional live ignore,
  GitHub Action and release-workflow verifiers, and `git diff --check` were green.
