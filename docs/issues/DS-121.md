# DS-121: Do not mistake SemVer build metadata for prereleases

- **Status:** Closed
- **Priority:** P2
- **Scope:** Registry candidate selection and live self-scan correctness

## Evidence

The initial live scan covered 321 packages with zero vulnerabilities but one
registry soft failure: “crates.io has no stable version for wasip2.” The official
sparse index contains non-yanked stable releases such as `1.0.4+wasi-0.2.12` and
`2.0.1+wasi-0.2.12`. Candidate filtering used `version.contains('-')`, so hyphens
inside build metadata incorrectly excluded every stable WASI release.

## Resolution

Use the existing SemVer parser's prerelease component, not a string-wide hyphen
test. Sparse-index validation still rejects malformed versions before selection;
yanked exclusions and real prerelease policy are unchanged. Installed/selected
version strings preserve their complete build metadata.

Three dedicated tests cover stable metadata and genuine prereleases for both
SemVer ecosystems, latest non-yanked crate selection, and a mocked HTTP sparse-index
scan using real WASI-style version shapes. No network dependency is added to tests,
and existing frozen fixtures remain unchanged.

## Verification

All three focused tests, final release gate, exact strict Clippy, retained-MSRV
suite, and 263-file architecture check pass. Stable and MSRV suites each pass
460 tests with one intentional live-provider exclusion. A fresh-cache live scan
of 321 packages has zero provider errors and selects `2.0.1+wasi-0.2.12` for wasip2.
This is a correctness defect, not a newly discovered CVE.
