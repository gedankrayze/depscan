# DS-020: Render included withdrawn advisories consistently

- **Status:** Open
- **Priority:** P1
- **Scope:** CLI/report contract

## Evidence

- `crates/depscan-cli/src/main.rs:258-260` retains withdrawn advisories when `--include-withdrawn` is set, and threshold evaluation at `404-418` includes all retained vulnerabilities.
- Table, summary, SARIF, sorting, and totals independently filter withdrawn advisories at `crates/depscan-report/src/lib.rs:76`, `129`, `191`, `240`, and `263-269`.
- The command can therefore fail on a finding hidden from its human and SARIF output.

## Acceptance criteria

- `--include-withdrawn` controls one consistent model used by thresholding and every renderer.
- Included withdrawn advisories are visibly labeled as withdrawn in table, JSON, SARIF, and summary/totals.
- Without the flag, withdrawn advisories neither render nor affect exits.

## Verification

- Add renderer and process-level tests for the same withdrawn fixture with and without the flag across all four formats.
- Assert visible counts, labels, SARIF results, and exit codes agree.
