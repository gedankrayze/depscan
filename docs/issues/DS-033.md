# DS-033: Reject malformed crates.io sparse-index lines

- **Status:** Closed
- **Priority:** P1
- **Scope:** crates.io registry provider / response integrity

## Evidence

- `crates/depscan-providers/src/lib.rs:900-906` uses `filter_map` and silently drops every sparse-index line that is not valid JSON.
- A truncated or corrupt response can hide the installed/current release, yanked state, or latest version and still be cached as valid metadata.

## Acceptance criteria

- Decode every non-empty line with line-numbered validation and require the expected crate/version fields.
- Any malformed/truncated line invalidates the response and prevents cache write; it is not treated as an absent release.
- Bound response/line sizes and reject duplicate/conflicting version records safely.

## Verification

- Add mock responses with malformed middle/last lines, missing fields, invalid UTF-8, duplicate versions, oversized lines, and valid newline endings.
- Assert bad responses return a soft per-package provider error and are not cached.

## Resolution

- The crates.io provider now streams a response into a bounded buffer (64 MiB maximum), validates UTF-8 and every non-empty NDJSON line, and reports source line numbers for malformed data.
- Each entry must contain a matching crate name, valid SemVer `vers`, and boolean `yanked`; empty indexes, duplicates/conflicts, lines above 1 MiB, and wrong identities are rejected.
- Only a completely validated index is written as a versioned cache envelope. Legacy or invalid envelopes are bypassed, and a rejected response leaves neither a cache entry nor a temporary cache file.
- The CLI cache fixture now exercises the validated envelope, preserving process-level scan coverage.

## Verification evidence

- Wiremock cases cover invalid UTF-8, malformed middle and final lines, missing/wrong fields, invalid SemVer, wrong crate identity, duplicates, an oversized line, valid LF/CRLF data, and validated-cache reuse.
- `cargo fmt --all -- --check`
- `cargo test --workspace --all-targets` (76 tests)
- `cargo clippy --all-targets -- -D warnings`
