# DS-033: Reject malformed crates.io sparse-index lines

- **Status:** Open
- **Priority:** P1
- **Scope:** crates.io registry provider / response integrity

## Evidence

- `crates/depscan-providers/src/lib.rs:900-906` uses `filter_map` and silently drops every sparse-index line that is not valid JSON.
- A truncated or corrupt response can hide the installed/current release, yanked state, or latest version and still be cached as valid metadata.

## Acceptance criteria

- Decode every non-empty line with line-numbered validation and require the expected crate/version fields.
- Any malformed/truncated line invalidates the response and prevents cache write; it is not treated as an absent release.
- Bound response/line sizes and reject duplicate/conflicting version records safely.

## Verification

- Add mock responses with malformed middle/last lines, missing fields, invalid UTF-8, duplicate versions, oversized lines, and valid newline endings.
- Assert bad responses return a soft per-package provider error and are not cached.
