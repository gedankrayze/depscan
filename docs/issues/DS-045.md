# DS-045: Generate release automation and complete the target matrix

- **Status:** In progress — remote release verification requires publication authorization
- **Priority:** P2
- **Scope:** Release engineering / artifact coverage

## Evidence

- `Cargo.toml:54-58` contains cargo-dist metadata, but the audited repository had no generated release workflow.
- The configured targets at `Cargo.toml:58` include only x86_64 GNU Linux, x86_64 macOS, and x86_64 Windows; ARM64 targets are absent.
- The specification requires GitHub Release artifacts and a cargo-dist-or-equivalent workflow, not metadata alone.

## Acceptance criteria

- Generate and review a pinned release workflow that builds, signs/checksums, and publishes supported artifacts from tags with least-privilege permissions.
- Add supported ARM64 targets for Linux/macOS (and Windows if support/testing is available), with an explicit documented platform matrix.
- Release jobs run quality gates and packaging checks before publication and produce installers promised by metadata.
- Checksums and provenance/attestations are published and tied to the exact source tag.

## Verification

- Run the release tool's plan/check locally and execute a non-publishing workflow dry run where possible.
- Create a test tag/release, download at least one artifact per target family, verify checksum/provenance, run `depscan --help`, and smoke-scan a fixture.

## Resolution

- Pinned cargo-dist 0.32.0 and every external release action to a full commit. A checked-in cross-platform installer selects only the five supported runner OS/architecture combinations, downloads the corresponding official cargo-dist archive, verifies its reviewed SHA-256 value before extraction, and rejects every other runner. No release job pipes downloaded content into an interpreter or executes cargo-dist's generated install command. Release tags are accepted only as strict semantic versions, enter shell steps through environment variables, and are passed to cargo-dist and GitHub CLI as quoted arguments; generated dependency/install/dist command strings are not executed. The generated tag workflow is read-only by default; only the host job receives `contents: write`, `id-token: write`, and `attestations: write`. `scripts/verify-release-workflow.sh` fails on a floating action, dynamic or pipe-to-shell bootstrap, missing reviewed checksum, direct GitHub-expression command interpolation, broadened or misplaced write permission, missing quality dependency, inherited quality-job secrets, or changed attestation action/scope.
- Enabled explicit SHA-256 output and host-phase GitHub artifact attestations. The release plan publishes and attests a source archive, shell installer, Homebrew formula, aggregate checksum, per-archive checksums, and Windows MSI/checksum alongside the five binary target archives.
- Added native Intel and Apple-silicon macOS targets to the two existing static-musl Linux targets and x86-64 Windows target. Windows ARM64 remains explicitly excluded because cargo-dist 0.32.0 does not list it as supported; runner availability alone is not artifact support or test evidence.
- Added a reusable, read-only release quality gate. Release artifact jobs depend on formatting, all-target tests, exact strict Clippy, verified workspace packaging, a locked release build, and `depscan --help` succeeding on Rust 1.97.1.
- Added the missing `dist` Cargo profile, inheriting the optimized release profile. A native artifact dry run first reproduced the otherwise hidden `profile dist is not defined` failure; after the fix, cargo-dist built the Apple-silicon archive and SHA-256 file successfully.
- Generated and checked in the Windows MSI definition. The CLI package now inherits the workspace author metadata required by WiX.
- Documented the complete target and installer matrix, the Windows ARM64 exclusion, and checksum/attestation verification commands in the README.

## Local verification evidence

- Fresh downloads of all five official cargo-dist 0.32.0 runner archives matched the reviewed SHA-256 map, and each archive contained the expected executable path. The checked-in Unix installer independently downloaded and verified the Apple-silicon archive, extracted it only after authentication, and reported `cargo-dist 0.32.0`; executing the PowerShell path remains part of the pending Windows release-runner evidence.
- `dist generate --check`, `dist plan --tag v1.1.0 --output-format=json`, the release-workflow guard, `actionlint`, and `git diff --check` passed. The plan contained exactly the five documented targets and 17 source, installer, archive, MSI, and checksum artifacts.
- Rust 1.97.1 passed all 293 workspace/all-target tests and the exact `cargo clippy --all-targets -- -D warnings` command. `cargo package --workspace --locked --allow-dirty` packaged and verified all five crates after the release metadata changes.
- A non-publishing `dist build --artifacts=lies --tag v1.1.0` completed the entire artifact graph without creating a release. A real `dist build --artifacts=local --target=aarch64-apple-darwin --tag v1.1.0` produced an 8.3 MiB optimized executable in a 2.7 MiB archive. Its SHA-256 matched, the extracted binary's help succeeded, and a fresh-cache online scan of a copied Cargo fixture reported `2 packages | 0 vulns | 1 outdated`.
- No tag, GitHub Release, or remote branch was created because this review does not have publication authorization. Remote acceptance must restrict release-tag creation to authorized maintainers and verify that the tagged commit descends from protected `main`; it must then exercise cross-platform downloads, checksums, and GitHub attestations. None of those external controls or runs is inferred from the local workflow.
