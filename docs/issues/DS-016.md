# DS-016: Make offline dump sync streaming and resilient

- **Status:** Closed
- **Priority:** P1
- **Scope:** Offline OSV synchronization / filesystem integrity

## Evidence

- `crates/depscan-providers/src/lib.rs:175-184` applies a ten-second whole-request timeout to the shared client.
- `crates/depscan-providers/src/lib.rs:255-269` buffers byte downloads and performs no retry.
- `crates/depscan-providers/src/lib.rs:626-659` holds the entire dump in memory, writes it, and replaces the archive without first validating the ZIP.
- Audit runtime evidence: the npm OSV dump was 219,888,780 bytes, making the timeout and buffering material.

## Acceptance criteria

- Stream each response into a uniquely named temporary file with a realistic configurable transfer timeout.
- Retry transient connect/429/5xx/interrupted transfers with bounded exponential backoff and `Retry-After` support.
- Validate the complete ZIP and expected JSON entries before atomic replacement.
- Preserve the previous known-good dump and sync timestamp on any failure; clean abandoned temporary files.
- Enforce reasonable size/resource limits without rejecting current legitimate dumps.

## Verification

- Add an HTTP integration test for a slow/chunked large response, interrupted transfer, retry, corrupt ZIP, and successful atomic replacement.
- Assert peak memory does not scale with the full archive size and the prior archive survives every failure case.

## Resolution

- OSV dumps now stream into uniquely named, same-directory temporary files and restart from byte zero on a retry. The response body is copied by one generic chunk-at-a-time path and is never collected into a full-archive `Vec`. A deterministic tracked-chunk test sends both 4 MiB and 128 MiB streams while proving peak live body memory stays at one 64 KiB chunk; socket-level coverage also pauses a multi-megabyte response and observes the partial temporary file while the previous archive remains live.
- The specification's ten-second network rule remains the whole-request deadline for normal JSON and bounded registry requests. Dump transfers instead use ten seconds as both the connect and per-read idle deadline, plus a configurable overall attempt deadline (`depscan sync --transfer-timeout`, default `15m`), so a progressing large download can safely exceed ten seconds without allowing a stalled transfer to run indefinitely.
- The dump-only path preserves its connect/read-idle and interrupted-body handling while sharing DS-031's exact one-plus-three attempt budget, capped exponential backoff and jitter, both `Retry-After` representations, and injected clock/sleeper with ordinary HTTP requests.
- Downloads are capped at 2 GiB compressed. A live HEAD probe on 2026-08-19 found npm, the largest current dump, at 219,900,176 bytes (the other three were at most 33,431,576 bytes), leaving substantial growth room. Validation runs off the async runtime, caps the archive at 2,000,000 entries, each JSON entry at 64 MiB, and aggregate uncompressed data at 16 GiB. Both ZIP-declared and actually decompressed byte counts are enforced. Every non-directory entry must be an ID-named JSON file containing the OSV schema's universally required, typed `id` and `modified` fields; unknown optional fields remain forward-compatible. Complete parsing to EOF verifies trailing/truncated data and ZIP integrity before publication.
- Synchronization revalidates the cache ownership sentinel and canonical `offline` namespace, rejects preexisting or detected root/child/lock symlink swaps, and holds a per-ecosystem filesystem lock through download, validation, and publication. Transfer and ZIP validation retain open file handles rather than reopening attacker-changeable temporary paths. Under the lock, cleanup removes only depscan-owned abandoned names and preserves unrelated and near-match files. DS-047 tracks the stronger capability-relative publication needed to eliminate the remaining concurrent pathname race.
- Before either target rename, the previous archive is staged into a unique same-directory rollback path, using a hard link when available and a length-checked, synced copy otherwise. Failure to prepare that backup leaves both live files untouched. The validated archive and timestamp are then atomically published individually; a timestamp-publication failure restores the pre-staged archive without a post-failure copy. If even the restore rename fails, cleanup is disabled for the last recovery copy and its path is reported instead of discarding the old bytes. RAII removes ordinary handled-failure temporaries, while the next locked sync reclaims crash-abandoned ones.
- Tests cover bounded live chunk memory, slow/chunked streaming, observable partial-file writes, same-ecosystem serialization, exact stale-temp cleanup, root/offline symlink refusal, interrupted-transfer retry and exhaustion, 429/5xx retry with capped `Retry-After`, syntactically valid non-OSV JSON, corrupt ZIPs, forged declared sizes, configurable transfer expiry, rollback staging failure, the actual archive-then-marker rollback branch, failed-restore recovery retention, resource limits, successful replacement, and timestamp preservation. The pre-existing DS-015 cache revalidation and compare-and-swap tests remain unchanged and pass with this implementation.
