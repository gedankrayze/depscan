# DS-016: Make offline dump sync streaming and resilient

- **Status:** Open
- **Priority:** P1
- **Scope:** Offline OSV synchronization / filesystem integrity

## Evidence

- `crates/depscan-providers/src/lib.rs:175-184` applies a ten-second whole-request timeout to the shared client.
- `crates/depscan-providers/src/lib.rs:255-269` buffers byte downloads and performs no retry.
- `crates/depscan-providers/src/lib.rs:626-659` holds the entire dump in memory, writes it, and replaces the archive without first validating the ZIP.
- Audit runtime evidence: the npm OSV dump was 219,888,780 bytes, making the timeout and buffering material.

## Acceptance criteria

- Stream each response into a uniquely named temporary file with a realistic configurable transfer timeout.
- Retry transient connect/429/5xx/interrupted transfers with bounded exponential backoff and `Retry-After` support.
- Validate the complete ZIP and expected JSON entries before atomic replacement.
- Preserve the previous known-good dump and sync timestamp on any failure; clean abandoned temporary files.
- Enforce reasonable size/resource limits without rejecting current legitimate dumps.

## Verification

- Add an HTTP integration test for a slow/chunked large response, interrupted transfer, retry, corrupt ZIP, and successful atomic replacement.
- Assert peak memory does not scale with the full archive size and the prior archive survives every failure case.
