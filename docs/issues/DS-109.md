# DS-109: Exclude PyPI releases with no downloadable files

- **Status:** Closed
- **Priority:** P1
- **Scope:** Online/offline PyPI candidate selection

## Evidence

`select_pypi_release` and manifest matching treat an empty release file array as a
non-yanked candidate. With `1.0: [{yanked:false}]` and `9.0: []`, both choose 9.0
despite there being no distribution to install. This can also send the wrong
manifest coordinate to OSV and yield an apparently clean result. Malformed release
file containers are treated as eligible by the same predicate.

## Acceptance criteria

- Select only releases with at least one non-yanked file for latest and range matching.
- Fail visibly on malformed file-list metadata.
- Retain installed-yank reporting and partial-yank/prerelease behavior.
- Test matching, stable selection, no-candidate, and malformed controls.

## Resolution

- Shared candidate selection now requires at least one non-yanked file for both
  latest and constraint matching. Empty lists remain valid metadata but ineligible
  candidates; malformed lists/files/yanked flags fail visibly.
- Kept installed-version yank reporting independent of candidate eligibility.

## Verification

- Both `pypi_candidates` regressions pass for latest, range matching, no candidates,
  and malformed lists. Existing stable/prerelease, partial/all-yank, registry mock,
  and online/offline cache tests pass.
- The release gate and retained Rust 1.96.0 suite pass.
