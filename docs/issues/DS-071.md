# DS-071: Synchronize dump streaming at the client-write boundary

- **Status:** Closed
- **Priority:** P1
- **Scope:** OSV dump streaming test determinism / native Windows portability

## Evidence

- Native Windows jobs
  [96362737605](https://github.com/gedankrayze/depscan/actions/runs/32348643782/job/96362737605)
  and
  [96362750292](https://github.com/gedankrayze/depscan/actions/runs/32348647600/job/96362750292)
  both timed out while the slow-stream test polled for nonzero temporary-file metadata.
- The server's pause notification proves only that eight TCP chunks were flushed. It does not prove
  reqwest consumed them or that the client completed a temporary-file write.
- The readiness loop used `DirEntry::metadata()`, whose Windows implementation may reuse stale
  directory-enumeration attributes. Increasing its one-second polling timeout would retain the
  wrong synchronization boundary and make the test slower rather than deterministic.

## Acceptance criteria

- Add a test-only progress signal immediately after a successful client write to the already-open
  temporary file; do not reopen a server-controlled path or alter production publication logic.
- Rendezvous on both the incomplete server response and a completed client write before checking
  the previous archive/marker and temporary-file state.
- Retain exact final replacement, changed marker, one-request, bounded-chunk, and no-temporary-file
  assertions.
- Use one generous timeout only as deadlock containment, with a transfer deadline above it. Do not
  use sleeping metadata polls as the semantic oracle.
- Pass the focused provider test, provider and workspace suites, exact Clippy, formatting, and a
  native Windows quality job.

## Verification

- Run the exact slow-stream test and `cargo test -p depscan-providers --lib --locked`.
- Run `cargo test --workspace --all-targets --locked`.
- Run `cargo clippy --all-targets -- -D warnings`.
- Run `cargo fmt --all -- --check` and `git diff --check`.
- Record a successful native Windows full-suite rerun before closing.

## Resolution and evidence (2026-08-20)

- `OsvSyncConfig` now carries a test-only watch sender. The streaming loop publishes cumulative
  bytes only after `write_all` succeeds; production configuration and behavior are unchanged.
- The test awaits the server pause and retained watch state together, then proves partial progress,
  the held temporary-file name, and unchanged published files before resuming the response. Its
  single ten-second timeout guards that rendezvous, both task joins, final publication, and cleanup
  beneath thirty-second transfer/read/connect deadlines.
- The focused regression passes `1/1`, the provider library passes `129/129`, and the Rust 1.97.1
  workspace/all-target suite, exact all-target Clippy, formatting, and diff checks pass locally.
- Native Windows job
  [96373789695](https://github.com/gedankrayze/depscan/actions/runs/32352263513/job/96373789695)
  passed `sync_streams_a_slow_large_dump_before_atomic_replacement` within the `126/126` provider
  result. The client-write rendezvous, partial-state assertions, final publication, and cleanup all
  completed without relying on directory-enumeration metadata timing.
