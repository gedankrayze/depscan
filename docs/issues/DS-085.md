# DS-085: Replace panic-prone indexing with typed lookups

- **Status:** Open
- **Priority:** P2
- **Scope:** Latent panics behind data-shape invariants

## Evidence

- The 2026-08-21 code review found `RegistryClient` using `self.limits[&Ecosystem::Npm]`-style
  `HashMap` indexing (`crates/depscan-providers/src/registry/client.rs`, `npm`/`pypi`/`nuget`/
  `crates`). Safe today because the constructor populates all four keys, but a fifth `Ecosystem`
  variant turns this into a runtime panic with no compiler help.
- `crates/depscan-parsers/src/node/yarn/common.rs` combines
  `bound.by_name.get_mut(&name).expect(...)[index]` where the slice index was produced from an
  earlier `enumerate()` over a different borrow of the same map.

## Acceptance criteria

- Ecosystem limits use a lookup whose missing-key case is handled (or a typed per-ecosystem
  struct so the compiler enforces completeness).
- The yarn matcher carries its invariant through types or handles the miss without `expect` plus
  unchecked indexing.

## Verification

- Existing registry and yarn tests pass unchanged.
- `bash scripts/dev-gate.sh full`
