# DS-066: Make CLI contract tests exact across native path conventions

- **Status:** Closed
- **Priority:** P1
- **Scope:** CLI process-test portability / native Windows quality gate

## Evidence

- After DS-065 cleared strict Clippy, both native Windows quality jobs reached the full workspace
  suite and failed two CLI exit-code tests while the other 66 tests in that harness passed.
- The help snapshot expected the Unix invocation spelling `depscan`, but Clap correctly renders
  `depscan.exe` in each Windows usage line. Replacing only that launcher spelling in the local
  output reproduces the exact native Windows digest.
- The cache-path assertion searched for the requested path spelling, although `Cache::new`
  intentionally canonicalizes its root before `cache path` prints it. Windows canonicalization
  uses an extended path spelling, so substring comparison against the uncanonicalized input is
  not a portable contract.

## Acceptance criteria

- Preserve exact byte snapshots for both the Unix-style and native Windows help renderings.
- Compare `cache path` output as the exact canonical filesystem path, not as a substring of one
  platform-specific spelling.
- Do not change production CLI behavior or weaken any help, configuration-isolation, or cache
  assertion.
- Pass the full CLI exit-code harness and exact all-target Clippy locally and in the protected
  native Windows quality job.

## Verification

- Run `cargo test -p depscan-cli --test exit_codes --locked`.
- Run `cargo clippy --all-targets -- -D warnings`.
- Run `cargo fmt --all -- --check` and `git diff --check`.
- Record a successful native Windows full-suite rerun before closing.
