# DS-110: Bound decompressed online JSON responses

- **Status:** Closed
- **Priority:** P2
- **Scope:** HTTP JSON adapter for registry and OSV requests

## Evidence

`HttpClient::request_json` calls `response.json()` without a body-size bound. OSV
batch/hydration and npm/PyPI/NuGet metadata use this path. Request deadlines bound
elapsed time but not bytes arriving before the deadline. Existing byte limits apply
only to sparse-index/registration calls and offline dumps.

## Acceptance criteria

- Bound the decompressed body for both GET and POST JSON before deserialization.
- Reject oversized bodies once, without retries or response-body/credential disclosure.
- Preserve retry behavior for interrupted transfers, timeouts, and retryable statuses.
- Test known-length, chunked, gzip-expanded, exact-limit, and POST responses.

## Resolution

- Added a shared bounded response-body reader used by JSON and existing limited
  byte requests. GET and POST JSON cap decompressed bytes at 64 MiB before parsing.
- Rejects content-length and streamed/gzip expansion beyond the limit without
  retries; errors retain sanitized request context and never include body content.
- Preserved timeout/status/connect retry policy and typed transfer failures.

## Verification

- All four `http_body` tests pass: GET/POST known-length rejection, chunked limits,
  gzip expansion, exact-limit success, interrupted-body failure, and redaction.
- Existing backoff, Retry-After, timeout, nonretryable-status, and bounded-byte
  controls pass within the 139-test provider suite. Release and MSRV gates pass.
