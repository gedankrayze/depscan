# DS-039: Implement NuGet prerelease precedence correctly

- **Status:** Closed
- **Priority:** P1
- **Scope:** Core NuGet version logic

## Evidence

- `crates/depscan-core/src/lib.rs:308-328` compares the full prerelease suffix lexicographically.
- NuGet SemVer precedence compares dot-separated identifiers numerically where numeric; for example `rc.10` must sort after `rc.2`, which plain string comparison does not guarantee.
- The same hand-written logic does not fully define metadata, normalization, or legacy four-part interactions.

## Acceptance criteria

- Use a proven NuGet-version implementation or a complete tested model for SemVer 2 plus legacy four-part versions.
- Implement numeric/alphanumeric prerelease identifier precedence, stable-over-prerelease, metadata rules, normalization, and range compatibility.
- Invalid versions return an error/unknown outcome rather than silently substituting zero components.

## Verification

- Add official NuGet ordering/range cases, including `rc.2 < rc.10`, mixed identifiers, metadata, leading zeros/invalid forms, stable releases, and four-part versions.

## Resolution

- Added a typed `NuGetVersion` model based on NuGet's documented SemVer 2 differences and legacy `System.Version` compatibility: one-to-four release components, release-component normalization, a fourth revision component, case-insensitive prerelease labels, numeric/alphanumeric identifier precedence, stable-over-prerelease ordering, and ignored build metadata.
- Registry selection now excludes malformed and prerelease versions before ordering. Staleness returns `Unknown` for an invalid installed or latest version, while matching NuGet OSV ranges parse the same type and fail with a typed error on malformed boundaries.
- Added table-driven cases derived from Microsoft NuGet documentation and the official `NuGet.Versioning` comparer tests, including `rc.2 < rc.10`, numeric-before-alphanumeric labels, label prefixes, case folding, metadata equality, normalized leading zeroes, invalid numeric prerelease zeroes, arbitrary-size numeric prerelease identifiers, stable precedence, and legacy four-part ordering. An OSV range regression verifies the same comparator at introduced/fixed boundaries.
