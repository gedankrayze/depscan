# DS-060: Make requirements include reads capability-safe

- **Status:** Closed
- **Priority:** P1
- **Scope:** Python requirements parser / concurrent filesystem integrity

_Closed-record excerpts; original dates and versions apply._

## Evidence

- The parser performs pathname checks separately from use: it calls `symlink_metadata` and `canonicalize`, checks containment, and later reopens the canonical path with `File::open`.

- The opened handle is checked only for being a regular file. It is not proven to be the same file whose in-root identity was validated.

- A concurrent final-component, parent-directory, or scan-root replacement can redirect the later open outside the validated root. Parsed bytes then become package coordinates that can reach registry and OSV requests.

- This violates the README and DS-017 contract that every recursive requirements include is a regular non-symlink contained within the canonical scan root.

- Existing tests cover static escapes, symlinks, cycles, and limits, but not concurrent namespace replacement.

## Historical resolution

- Requirements parsing now opens the detected file's parent once as a retained `cap-std` directory capability, proves its held identity against the canonical scan-root attachment, and resolves all recursive paths relative to retained capabilities. Requested-root and canonical absolute spellings map back to the same held root; other absolute paths and lexical `..` escapes fail closed.

- Every final requirements component is opened with no-follow semantics, checked as a regular file from that handle, read through that same handle, and then revalidated through freshly replayed root, directory-chain, and final-name capabilities before its bytes are parsed. Intermediate directory symlinks remain compatible only when capability-relative resolution proves they stay inside the root.

- Held identities use overlapping `st_dev`/`st_ino` handles on Unix and full `FILE_ID_INFO` volume plus 128-bit file IDs on Windows. The same identity model closes hardlink cycle aliases and detects regular root, parent, and final-name replacements without relying on ambient pathname equality.

## Historical verification

- On macOS, 19 focused requirements parser tests pass, including regular and symlink root/parent swaps, regular and symlink final swaps at file-open/before-read/after-read boundaries, hardlink cycles, requested-root absolute aliases, contained intermediate symlinks (including a nested sibling target that requires root-capability fallback), outside symlink rejection, and all retained DS-017 limits and diagnostics.

- Both focused requirements CLI process tests pass. The race test also proves a wrong nonce is inert and that rejected outside-derived input does not create the initially absent `DEPSCAN_CACHE_DIR`.
