# DS-060: Make requirements include reads capability-safe

- **Status:** Open
- **Priority:** P1
- **Scope:** Python requirements parser / concurrent filesystem integrity

## Evidence

- The parser performs pathname checks separately from use: it calls `symlink_metadata` and `canonicalize`, checks containment, and later reopens the canonical path with `File::open`.
- The opened handle is checked only for being a regular file. It is not proven to be the same file whose in-root identity was validated.
- A concurrent final-component, parent-directory, or scan-root replacement can redirect the later open outside the validated root. Parsed bytes then become package coordinates that can reach registry and OSV requests.
- This violates the README and DS-017 contract that every recursive requirements include is a regular non-symlink contained within the canonical scan root.
- Existing tests cover static escapes, symlinks, cycles, and limits, but not concurrent namespace replacement.

## Acceptance criteria

- Hold a capability for the validated requirements root throughout recursive parsing.
- Resolve and open the root file and every include relative to held capabilities; do not reopen a previously checked ambient pathname.
- Open final components without following symlinks, validate regular-file metadata from the opened handle, and read from that same handle.
- Preserve contained absolute includes and relative-to-including-file semantics without allowing parent or root replacement to redirect access.
- A replacement after opening must either leave reads bound to the original handle or produce exit `10`; outside bytes must never become package or provider fields.
- Preserve cycle detection, source provenance, include-chain diagnostics, and the existing depth, file-count, and total-byte limits.

## Verification

- Add deterministic barrier tests for final-file, include-parent, and scan-root swaps at resolution, open, and read boundaries.
- Exercise both symlink and regular-directory replacements; assert an outside sentinel is neither parsed nor exposed.
- Add a CLI process regression proving an unsafe swap exits `10` before any outside-derived provider request.
- Retain all DS-017 static containment and resource-bound tests.
- Run native platform coverage on Linux, macOS, and Windows, then the full workspace suite on Rust stable and MSRV plus exact Clippy.
