# DS-080: Bound multiplicative retry amplification across cache and HTTP layers

- **Status:** Closed
- **Priority:** P2
- **Scope:** Provider retry policy

## Evidence

- The 2026-08-21 code review found the cache-commit loop (`CACHE_COMMIT_ATTEMPTS = 3` in
  `RegistryClient::metadata_with_limit`, `crates/depscan-providers/src/registry/client.rs`)
  wrapping the HTTP retry loop (`settings.attempts = 4` in
  `crates/depscan-providers/src/http/client.rs`), so a single package lookup can issue up to 12
  HTTP requests. The same shape exists in `registry/sparse_client.rs` and `osv/online.rs`.

## Acceptance criteria

- A single logical lookup has one documented worst-case request budget; cache-commit conflicts
  (a local CAS concern) do not multiply network retry attempts.
- DS-031's exact retry and `Retry-After` semantics are preserved.

## Verification

- Provider mock tests asserting the worst-case request count for a conflicted cache commit.
- `bash scripts/dev-gate.sh full`

## Resolution

- The registry metadata and crates.io sparse-index lookups now separate the single network
  fetch from cache convergence. With cache reads enabled — the default, and the path that runs
  under 64-way scan concurrency — one logical lookup performs exactly one fetch: a commit
  conflict adopts a fresh concurrent winner (exactly as the fast path trusts fresh cache) or
  retries the local CAS against a stale winner, never refetching. The documented worst case is
  the DS-031 HTTP attempt budget, and a new mock test
  (`conflicting_fresh_winner_is_adopted_without_a_second_request`) fails on any second request.
- Under `--no-cache` a conflict still refetches (bounded by the commit-attempt budget), because
  the winner can be neither served nor clobbered with an older response; the pre-existing
  `cache_bypass_still_prevents_out_of_order_publication` race test pins that requirement and
  passes unchanged.
- The OSV batch-query conflict path retains its bounded re-query deliberately, now documented
  in code: the re-query re-enforces the revision-regression check against the server rather
  than trusting a concurrent local write, the concurrent-refresh race test pins the behavior,
  and batch queries make the bounded extra round-trips cheap relative to per-package paths.

## Local verification evidence

- All 131 provider `--all-targets` tests pass, including the new single-request conflict test,
  the cache-bypass out-of-order race test, and the OSV concurrent-refresh race test; workspace
  clippy clean via the pre-commit gate.
