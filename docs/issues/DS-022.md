# DS-022: Support the full CLI surface in configuration

- **Status:** Closed
- **Priority:** P1
- **Scope:** CLI configuration

## Evidence

- `crates/depscan-cli/src/main.rs:48-84` defines the scan option surface.
- `crates/depscan-cli/src/main.rs:112-126` supports only the two failure thresholds and ignores.
- The specification requires every flag-settable scan option to be config-settable with command-line flags taking precedence.

## Acceptance criteria

- `depscan.toml` can express ecosystems, dev/direct filters, format/output, thresholds, offline/cache settings, withdrawn policy, ignores, tool permission, and log settings where meaningful.
- CLI values deterministically override config values, including booleans and repeatable lists.
- Unknown/mistyped config keys fail with exit `10` rather than being silently ignored.
- Defaults, merge rules, and security-sensitive `allow-tools` behavior are documented.

## Verification

- Add configuration deserialization and process tests for every field, default, CLI override, list merge/replace decision, unknown key, and invalid value.
- Snapshot `--help`/configuration documentation for parity.

## Resolution

- `depscan.toml` now has a strict, kebab-case schema for ecosystem selection, development/direct filters, report format and output, both failure thresholds, offline/cache behavior, withdrawn advisories, suppressions, external-tool authorization, and quiet/verbose levels. Unknown top-level or suppression keys, wrong TOML types, invalid enums/durations, and conflicting configured log levels fail with exit `10` before provider access.
- Scan configuration is loaded and fully validated into one prepared request before tracing starts. Scalar precedence is fieldwise CLI value, configured value, then default; format follows CLI format, configured format, then output/TTY inference. A present enable-only CLI switch sets true, CLI ecosystem entries replace the configured array, CLI and configured ignores combine with provenance, and any CLI quiet/verbose occurrence replaces the configured logging group.
- Configured logging initializes the subscriber before deferred config-origin diagnostics are emitted. The default command and explicit `scan` command use the same preparation path, while malformed scan configuration cannot affect cache, completion, or sync help commands.
- Relative configured output resolves from the scan root. Auto-discovered output is rejected when its validated parent escapes the root or the final target is already a symlink. An implicit project config cannot self-authorize `allow-tools`; permission requires the CLI flag or an explicitly selected trusted config. DS-048 records the stronger capability-relative file access needed to close concurrent pathname-swap races.
- README and root/scan help document the complete schema, defaults, list/group behavior, fieldwise precedence, output boundary, and external-tool trust decision. Byte snapshots lock the updated help and completion contracts.
