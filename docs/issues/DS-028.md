# DS-028: Build the required fixture, provider, version, and E2E test matrix

- **Status:** In progress
- **Priority:** P1
- **Scope:** Test architecture / CI confidence

## Evidence

- Only eight unit tests exist: `crates/depscan-core/src/lib.rs:510-535`, `crates/depscan-parsers/src/lib.rs:792-817`, `crates/depscan-providers/src/lib.rs:914-930`, and `crates/depscan-report/src/lib.rs:298-310`.
- `crates/depscan-providers/Cargo.toml:27-29` declares `wiremock`, but no provider HTTP mock tests exist.
- `crates/depscan-parsers/Cargo.toml:19-21` declares `insta`, but the audited tests do not provide the specification's real-world per-format fixture/snapshot matrix.
- CI's "Dogfood CLI help" at `.github/workflows/ci.yml:30-33` only runs `--help`; it does not scan the project or validate HTTP/exit/report behavior.

## Acceptance criteria

- Parser snapshots cover every supported lock/manifest variant, workspaces, malformed input, and all parser issues in this ledger.
- Version tests cover SemVer, Cargo, NuGet four-part/prerelease, PEP 440 oddities, and OSV ranges.
- Provider mocks cover success, soft/hard failure, retry, pagination, ETag/cache revalidation, malformed responses, and all registries.
- E2E fixture projects cover each ecosystem and every output/exit contract; one opt-in ignored live suite is suitable for scheduled CI.
- CI dogfoods an actual offline/mocked self-scan without relying on external services per PR.

## Verification

- Record a test inventory mapping every specification requirement and `DS-*` issue to at least one meaningful test.
- Run `cargo test --workspace --all-targets`, strict Clippy, and the process-level E2E suite on Linux, macOS, and Windows.
- Run the opt-in live suite in its scheduled job and retain API/result evidence without exposing cache or secrets.

## Resolution

- Added realistic, standalone npm, uv/Python, NuGet, and Cargo projects under `fixtures/e2e`. The process matrix invokes the built CLI against every project in strict offline mode and validates normalized identity, preserved display spelling, resolved version, direct/development provenance, source path, unknown offline freshness, visible soft errors, and exit `0` in table, JSON, SARIF, and summary output. It also proves the report-only command does not modify any fixture byte.
- Added an offline self-scan of the real workspace and replaced CI's help-only dogfood step with that process test on Linux, macOS, and Windows. All PR test execution remains independent of public services.
- Made native registry base URLs injectable within provider tests. Wiremock now proves the exact npm, PyPI, NuGet, and crates.io paths, npm `Accept` header, common `User-Agent`, successful selection, and fail-closed malformed-document behavior. A separate contract test pins production timeout, retry, OSV concurrency, and per-ecosystem registry concurrency budgets.
- Added `docs/test-matrix.md`, mapping every specification section, supported parser source, version family, provider behavior, process output/exit contract, resource bound, and DS-001 through DS-048 to meaningful executable or artifact evidence.
- Added an explicitly ignored four-ecosystem live process suite and a least-privilege weekly/manual workflow. It emits only aggregate evidence and does not persist caches, raw API bodies, credentials, or secrets.
