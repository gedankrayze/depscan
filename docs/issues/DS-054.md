# DS-054: Resolve canonical NuGet identities from registration metadata

- **Status:** Closed
- **Priority:** P0
- **Scope:** NuGet registry enrichment / online OSV query planning / identity preservation

_Closed-record excerpts; original dates and versions apply._

## Evidence

- [DS-003](DS-003.md) separated NuGet's lowercase internal and flat-container identity from the spelling sent to OSV, but it assumed that the spelling read from a project file was the canonical package ID.

- NuGet package references are case-insensitive, so a project may legitimately spell `Newtonsoft.Json` as `newtonsoft.json`; source-preserved casing is audit data, not registry-authoritative identity.

- A live OSV querybatch probe returned no advisory for `newtonsoft.json@12.0.1`, while the canonical `Newtonsoft.Json@12.0.1` coordinate returned `GHSA-5crp-9r3c-p9vr`.

- NuGet's flat-container version index contains only versions. The registration resource exposes the canonical package ID as `catalogEntry.id` for the concrete version being queried.

## Historical resolution

- Registry enrichment now carries optional provider identity independently of `LatestVersions`. The online NuGet provider obtains that identity from the registration leaf for the concrete OSV target version while continuing to use lowercase flat-container and cache coordinates.

- Registration responses are fetched and parsed fail-closed under a 16 MiB decompressed limit. Linked pages are confined to the configured registration origin and lowercase package prefix; the selected leaf must have the requested NuGet version and a canonical `catalogEntry.id` whose normalized identity matches the source package.

- Online query planning writes the canonical ID only to its ephemeral OSV package clone. The original package name, display spelling, result key, exact version or manifest constraint, and range provenance remain unchanged in the report. Missing canonical metadata produces an explicit OSV-unresolved error and no uncanonicalized request.

- Offline planning retains ecosystem-normalized NuGet matching and has no registration metadata requirement.
