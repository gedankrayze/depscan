# DS-108: Emit valid optional SARIF properties and artifact URIs

- **Status:** Closed
- **Priority:** P1
- **Scope:** SARIF renderer

## Evidence

`insert_vulnerability_rule` writes `helpUri: null` for a valid advisory with no
references. It also copies the first reference even when it is not an absolute URI.
All result locations write native filesystem paths as URI references, leaving
spaces, `#`, `%`, and Windows backslashes unencoded. The
[OASIS schema](https://github.com/oasis-tcs/sarif-spec/blob/main/sarif-2.1/schema/sarif-schema-2.1.0.json)
requires a string URI for `helpUri` and a valid URI reference for artifact locations.

## Acceptance criteria

- Omit unavailable/invalid help URIs and retain a valid reference when available.
- Encode native file paths as valid relative or absolute file URIs in every result kind.
- Add regressions for absent references, malformed references, Unicode, reserved path
  characters, and native Windows separators.

## Resolution

- Omitted absent help links, selected a parseable absolute reference when present,
  and used the advisory ID when its short description is empty.
- Applied one URI encoder to all vulnerability, suppression, freshness, and provider
  error locations. Relative reserved characters, Unicode, Unix absolute paths,
  Windows drive/UNC paths, and literal Unix backslashes are handled explicitly.

## Verification

- Both `sarif::tests` regressions and all 16 report tests pass in stable/MSRV gates.
- An optimized CLI scan with a no-reference, empty-summary advisory and a source
  directory containing spaces and `#` passes the official SARIF 2.1.0 JSON schema
  using Draft7Validator with FormatChecker enabled. The probe's outbound proxies
  were pointed at a closed local port; registry/advisory state came from seeded
  fresh cache entries, not public provider availability.
