# DS-079: Move remaining blocking filesystem IO in async provider paths off the runtime

- **Status:** Closed
- **Priority:** P2
- **Scope:** Offline registry provider and OSV sync service

## Evidence

- The 2026-08-21 code review found blocking `std::fs` calls directly inside `async fn` bodies in
  `crates/depscan-providers/src/registry/offline.rs` (`VersionProvider::latest` reads dump
  metadata and contents with `fs::symlink_metadata`/`fs::read_to_string`) and interleaved with
  awaits in `crates/depscan-providers/src/osv/sync/service.rs` (`CapabilityTempFile::new`,
  `dir.revalidate()`, marker `write_all`/`sync_all`, and `publish_osv_pair` run on the runtime
  thread while neighbouring operations in the same function are correctly wrapped in
  `spawn_blocking`).
- DS-077 fixed the shared cache-store primitives; these sites bypass the cache store and perform
  their own filesystem IO.

## Acceptance criteria

- Offline registry reads and the OSV sync write/rename/marker sequence run under
  `spawn_blocking` (or equivalent), with critical ordering preserved.
- The choice of what stays inline is deliberate and documented where non-obvious.

## Verification

- `cargo test -p depscan-providers`
- `bash scripts/dev-gate.sh full`

## Resolution

- `RegistryOffline::latest` now runs its metadata checks, dump read, and parse under
  `spawn_blocking`, mirroring `OsvOffline::query`; a join failure maps to
  `ProviderError::Offline`.
- In the sync service, the three expensive filesystem clusters moved to the blocking pool: the
  archive temporary-file creation, the marker temporary creation with its write and fsync, and
  the `publish_osv_pair` rename/fsync sequence. The `dir.revalidate()` and
  `validate_marker_target` probes deliberately stay inline — they are bounded metadata syscalls
  on an already-open handle, and keeping them on the async side preserves the exact
  boundary-hook ordering the swap-safety tests inject failures into; a comment in the service
  records this.

## Local verification evidence

- All 130 provider tests pass, including every capability-swap boundary-injection test, and the
  offline provider e2e suite passes; workspace clippy clean via the pre-commit gate.
