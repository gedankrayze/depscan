# DS-036: Parse Poetry constraints without inventing packages

- **Status:** Closed
- **Priority:** P1
- **Scope:** Poetry manifest parsing

## Evidence

- `crates/depscan-parsers/src/lib.rs:539-550` concatenates each `[tool.poetry.dependencies]` key and string value.
- The reserved `python = "^3.11"` interpreter constraint is therefore emitted as a PyPI package named `python`.
- At lines `553-568`, caret constraints are not parsed with Poetry semantics and can be sent onward as an unresolved/incompatible registry query.

## Acceptance criteria

- Exclude Poetry's reserved Python/interpreter constraint and handle dependency tables, extras, optional flags, markers, groups, git/path/url sources, and caret/tilde constraints explicitly.
- Convert supported Poetry constraints to a correct internal constraint model used by DS-029; unsupported forms produce a visible degraded/error state.
- Never query PyPI/OSV for a pseudo-package derived from project metadata.

## Verification

- Add Poetry fixtures for `python`, caret/tilde/wildcard constraints, extras, tables, groups, optional, markers, and non-registry sources.
- Assert exact package identities and matching release sets.

## Resolution evidence

- `pyproject.toml` parsing now delegates to focused Poetry modules instead of concatenating table keys and values. PEP 508 `project.dependencies`, `project.optional-dependencies`, PEP 735 dependency groups, legacy Poetry dependency tables, and Poetry named groups are decoded explicitly; includes retain production/development scope and cycles fail visibly.
- Poetry caret, tilde, wildcard, exact, and PEP 440 constraints preserve their raw manifest spelling and pass an equivalent normalized PEP 440 expression to DS-029's `set_normalized_manifest_constraint`. Tests call the public `latest_matching_version` evaluator and cover both matching releases and exclusive upper boundaries.
- The reserved interpreter constraint, extras, optional flags, Python constraints, and markers are treated as metadata. Git, path, URL, custom-source, and globally ambiguous custom-repository coordinates are retained but made non-enrichable; a process-level offline test proves those packages require neither OSV nor registry provider state.
- Malformed PEP 508/Poetry declarations, source-policy errors, group cycles, conditional dependency arrays, and `allow-prereleases` values whose candidate policy cannot yet be represented return source-qualified errors instead of guessed packages.
- On 2026-08-19, after rebasing onto `develop`, Rust 1.97.1 passed `cargo fmt --all -- --check`, all 255 workspace/all-target tests, and the exact `cargo clippy --all-targets -- -D warnings` gate. Rust 1.95.0 passed the same 255 locked workspace/all-target tests with `cargo +1.95.0 test --workspace --all-targets --locked`.
