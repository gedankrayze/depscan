# DS-036: Parse Poetry constraints without inventing packages

- **Status:** Open
- **Priority:** P1
- **Scope:** Poetry manifest parsing

## Evidence

- `crates/depscan-parsers/src/lib.rs:539-550` concatenates each `[tool.poetry.dependencies]` key and string value.
- The reserved `python = "^3.11"` interpreter constraint is therefore emitted as a PyPI package named `python`.
- At lines `553-568`, caret constraints are not parsed with Poetry semantics and can be sent onward as an unresolved/incompatible registry query.

## Acceptance criteria

- Exclude Poetry's reserved Python/interpreter constraint and handle dependency tables, extras, optional flags, markers, groups, git/path/url sources, and caret/tilde constraints explicitly.
- Convert supported Poetry constraints to a correct internal constraint model used by DS-029; unsupported forms produce a visible degraded/error state.
- Never query PyPI/OSV for a pseudo-package derived from project metadata.

## Verification

- Add Poetry fixtures for `python`, caret/tilde/wildcard constraints, extras, tables, groups, optional, markers, and non-registry sources.
- Assert exact package identities and matching release sets.
