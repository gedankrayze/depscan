# DS-100: Prepare the v2.0.1 maintenance release

- **Status:** Closed
- **Priority:** P1
- **Scope:** Workspace, action, documentation, and release-version contract

## Evidence

- The latest public release is immutable `v2.0.0` at protected-main commit
  `9a75f609714fd81a3564ca9bc30dddff510eb05c`.
- `develop` contains the NuGet parser compatibility update, `noyalib` 0.0.28, and Bun 1.4
  lockfile-version support that are not present in `v2.0.0`.
- Live preflight found no remote `v2.0.1` tag or GitHub release. The repository's existing
  publication contract distributes GitHub release binaries and does not currently publish a
  `depscan-cli` crate on crates.io.

## Acceptance criteria

- The workspace and all four internal dependency requirements use `2.0.1`, and the lockfile
  records that version for all five workspace packages.
- The composite action, README examples, installer diagnostics, Markdown attribution test, and
  tag-bound release acceptance workflow use `v2.0.1`/`2.0.1` consistently.
- Release verification derives the expected acceptance tag from the workspace version so later
  releases cannot silently retain a stale hard-coded tag contract.
- The release workflow verifier, cargo-dist generation check and reviewed asset plan pass,
  followed by `bash scripts/dev-gate.sh release` on the complete candidate tree.
- Publication targets the reviewed protected-main commit only after protected CI and the
  incoming-PR gate pass. Tag, release, asset and native acceptance evidence is recorded after
  publication rather than claimed during preparation.

## Resolution

- Aligned the workspace, internal crate requirements, five lockfile package records, composite
  action, README download/action examples, installer diagnostics, Markdown attribution test, and
  release-acceptance workflow to `2.0.1`/`v2.0.1`.
- Made the release verifier derive the expected acceptance tag from the workspace version and
  require both tag environment entries and both checkout refs to agree with it.
- The GitHub Action and release-workflow verifiers, Cargo metadata, focused Markdown test, Rust
  architecture gate, and `git diff --check` pass. The checksum-verified cargo-dist 0.32.0 binary
  passes `dist generate --check`; its `v2.0.1` plan announces `depscan-cli 2.0.1` and matches the
  reviewed sorted 16-file release asset contract exactly.
- `bash scripts/dev-gate.sh release` passes on the complete candidate containing DS-098, DS-099,
  and the dependency updates. Evidence includes the exact strict Clippy command, all 434 local
  tests passing with the single documented live-provider test intentionally ignored, all five
  crates packaging and verifying, and an optimized `depscan-cli 2.0.1` build.
- The live preflight confirmed `v2.0.1` is unused. Protected-branch CI, immutable tag publication,
  release assets, attestations, and native acceptance remain post-commit remote evidence and are
  not claimed by this preparation issue.
