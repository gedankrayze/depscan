# DS-062: Remove direct use of maintenance-seeking `urlencoding`

- **Status:** Closed
- **Priority:** P2
- **Scope:** Provider URL construction / dependency maintenance

## Evidence

- `urlencoding = "2.1.3"` is a direct workspace dependency and a direct dependency of `depscan-providers`.
- Provider URL construction uses it for NuGet flat-container and registration paths, registration-prefix validation, npm paths, and PyPI paths.
- The published 2.1.3 manifest declares `maintenance = "looking-for-maintainer"`; the locally cached crates.io index lists it as the newest release.
- The maintained `percent-encoding` crate is already locked through the `url` and Reqwest dependency paths.
- `cargo tree -i urlencoding --locked` shows both `depscan-providers` and `pep508_rs`. Removing the direct provider edge will not remove the lock entry while `pep508_rs` still depends on it.
- Existing endpoint tests use simple ASCII package names and do not lock scoped npm, reserved-character, or Unicode encoding behavior.

## Acceptance criteria

- Replace provider use with `percent-encoding` and one centralized path-segment helper.
- Preserve the current byte contract exactly: leave only ASCII alphanumerics plus `-._~` unescaped and percent-encode UTF-8 bytes with uppercase hexadecimal, including `/`, `%`, and `@`.
- Remove `urlencoding` from workspace and provider direct dependencies and declare the maintained replacement explicitly.
- Ensure `depscan-providers` no longer appears beneath `urlencoding` in the reverse dependency tree. Document that the transitive `pep508_rs` edge may remain.
- Preserve all npm, PyPI, NuGet flat-container, registration-index, and registration-prefix URL behavior.

## Verification

- Add encoding-table tests covering unreserved characters, spaces, `%`, `/`, `@scope/package`, control bytes, and non-ASCII UTF-8.
- Add exact request-path tests for scoped npm and representative PyPI/NuGet names.
- Re-run NuGet registration URL-confinement tests.
- Verify `cargo tree -i urlencoding --locked` excludes providers and `cargo tree -i percent-encoding --locked` includes it.
- Run provider tests, the full workspace suite on Rust stable and MSRV, `cargo audit`, and exact Clippy.

## Resolution

- Provider URL construction now uses one `encode_path_segment` helper backed by
  `percent_encoding::utf8_percent_encode`. Its explicit encode set preserves only RFC 3986
  unreserved ASCII bytes (`A-Z`, `a-z`, `0-9`, `-._~`); reserved characters, controls, and
  non-ASCII UTF-8 bytes are emitted as uppercase percent triplets.
- npm, PyPI, NuGet flat-container, NuGet registration-index, and registration-page prefix
  construction all use that helper. URL path delimiters remain outside the encoded segment, and
  linked NuGet registration pages are still confined to the exact encoded package prefix and
  registry origin.
- The workspace and `depscan-providers` direct dependency declarations now name
  `percent-encoding` 2.3.2. The provider lock edge moved accordingly. `urlencoding` 2.1.3 remains
  locked only because `pep508_rs` still depends on it transitively through `depscan-parsers`.
