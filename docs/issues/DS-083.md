# DS-083: Prepare the published API surface for growth before the next release

- **Status:** Closed
- **Priority:** P1
- **Scope:** Published crate API (semver)

## Evidence

- The 2026-08-21 code review found no `#[non_exhaustive]` on growth-prone public enums in the
  published crates: `Ecosystem` and `SourceKind` (`crates/depscan-core/src/ecosystem.rs`),
  `ParseError` and `ProviderError` (`crates/depscan-core/src/errors.rs`), the finding and OSV
  enums in `crates/depscan-core/src/finding.rs` and `osv.rs`, and `OutputFormat`
  (`crates/depscan-report/src/lib.rs`). Every new ecosystem or lockfile kind is currently a
  semver-major break.
- The primary constructor types of `depscan-providers` (`HttpClient`, `OsvClient`, `OsvOffline`,
  `RegistryClient`, `RegistryOffline`) derive `Clone` but not `Debug`; `ParserSet`
  (`crates/depscan-parsers/src/lib.rs`) derives nothing. `CacheStats` lacks
  `Clone`/`Copy`/`PartialEq`; `OsvSyncOptions` exposes a public field without
  `#[non_exhaustive]`.

## Acceptance criteria

- Public enums expected to grow are `#[non_exhaustive]` (or documented as intentionally closed),
  and internal `match` sites are adjusted deliberately rather than with blanket wildcards.
- Conventional derives (`Debug` at minimum) exist on public types; changes land before the next
  crates.io publication because they are themselves breaking.

## Verification

- `cargo package --workspace --locked` and `cargo doc` review of the public surface.
- `bash scripts/dev-gate.sh full`

## Resolution

- `#[non_exhaustive]` landed where wildcarding is the natural consumer posture: `ParseError`,
  `ProviderError`, `OutputFormat`, and the `OsvSyncOptions` struct (which gained a
  `with_transfer_timeout` builder so downstream construction survives the seal; the CLI now
  uses it).
- `Ecosystem` and `SourceKind` stay deliberately exhaustive, with the policy documented on the
  enums: DS-085 made the ecosystem limit table a compile-time checklist, and sealing these
  would replace that guarantee with silent wildcard arms in the workspace's own downstream
  crates. Adding an ecosystem or source kind is a semver-major event on purpose. `Severity`
  and `Staleness` are closed by nature.
- `Debug` now exists on every primary provider constructor type (`HttpClient` via a manual impl
  around its runtime trait object, `OsvClient`, `OsvOffline`, `RegistryClient`,
  `RegistryOffline`, `RegistryLimits`) and on `ParserSet` (manual, reporting the parser count);
  `CacheStats` gained `Clone`/`Copy`/`PartialEq`/`Eq`.
- These are breaking changes to published crates; together with DS-088's `f64` CVSS surface the
  next crates.io publication must be a major version bump.

## Local verification evidence

- Full workspace `--all-targets` suite passes (21 suites); the one downstream exhaustive
  `ParseError` match (a parser schema test) was updated to the wildcard posture the seal is
  designed to enforce. Workspace clippy clean via the pre-commit gate.
