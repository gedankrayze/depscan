# DS-083: Prepare the published API surface for growth before the next release

- **Status:** Open
- **Priority:** P1
- **Scope:** Published crate API (semver)

## Evidence

- The 2026-08-21 code review found no `#[non_exhaustive]` on growth-prone public enums in the
  published crates: `Ecosystem` and `SourceKind` (`crates/depscan-core/src/ecosystem.rs`),
  `ParseError` and `ProviderError` (`crates/depscan-core/src/errors.rs`), the finding and OSV
  enums in `crates/depscan-core/src/finding.rs` and `osv.rs`, and `OutputFormat`
  (`crates/depscan-report/src/lib.rs`). Every new ecosystem or lockfile kind is currently a
  semver-major break.
- The primary constructor types of `depscan-providers` (`HttpClient`, `OsvClient`, `OsvOffline`,
  `RegistryClient`, `RegistryOffline`) derive `Clone` but not `Debug`; `ParserSet`
  (`crates/depscan-parsers/src/lib.rs`) derives nothing. `CacheStats` lacks
  `Clone`/`Copy`/`PartialEq`; `OsvSyncOptions` exposes a public field without
  `#[non_exhaustive]`.

## Acceptance criteria

- Public enums expected to grow are `#[non_exhaustive]` (or documented as intentionally closed),
  and internal `match` sites are adjusted deliberately rather than with blanket wildcards.
- Conventional derives (`Debug` at minimum) exist on public types; changes land before the next
  crates.io publication because they are themselves breaking.

## Verification

- `cargo package --workspace --locked` and `cargo doc` review of the public surface.
- `bash scripts/dev-gate.sh full`
