# DS-112: Distrust compromised eMudhra certificate chains

- **Status:** Closed
- **Priority:** P1
- **Scope:** TLS dependencies and deterministic certificate-verification regressions

_Closed-record excerpts; original dates and versions apply._

## Evidence

The 2026-10-23 audit of `develop` and immutable `v2.0.3` resolves
`rustls-webpki 0.103.14` (RUSTSEC-2026-0382) and `webpki-root-certs 1.0.9`
(RUSTSEC-2026-0383). Their patched floors are 0.103.16 and 1.0.10 respectively.
The compromised intermediate keys permit impersonation when a client's configured
trust anchors allow a chain through them; this is exposure, not evidence of exploitation.

DepScan's default reqwest Rustls client uses the platform verifier. Linux loads
system roots and verifies with WebPKI without automatic revocation checking.
macOS/Windows use native certificate verification. The old bundled root crate is
a WASM-only edge, not part of the five native release dependency paths.

## Historical resolution

- Resolved stable `rustls-webpki 0.103.16` and `webpki-root-certs 1.0.11`, plus
  `rustls-platform-verifier 0.7.1`. Added an explicit production verifier floor
  and a WASM-only root-store floor so existing downstream locks cannot retain
  the affected versions. Native root-bundle access remains test-only.

- Added three deterministic TLS tests in a dedicated test module. Public-only
  fixture data is pinned to its upstream source commits and attributed in its
  README. No OS trust store is modified and tests make no network requests.

- All 14 direct, cross-signed, and no-CT incident chains must fail specifically
  with `CertDistrusted`, even when all four old roots are explicitly trusted.
  All four incident root fingerprints must be absent from the current bundle.

- An unrelated valid chain must verify with its anchor and fail without it.
  The incident and control use fixed timestamps inside their respective validity
  windows, so expiration or an empty trust store cannot stand in for the fix.

## Historical verification

- A separate owned temporary probe with exact `rustls-webpki 0.103.14`, the same
  14 chains, all four old trust anchors, server-auth usage, and incident timestamp
  `1792756800` accepted **14/14** chains. The updated regression rejects **14/14**
  with the explicit distrust error and accepts the valid control.

- All three focused TLS tests pass. The quick checkpoint and frozen full gate
  pass, including exact `cargo clippy --all-targets -- -D warnings`, architecture,
  automation, formatting, action/release verifiers, and patch hygiene.
