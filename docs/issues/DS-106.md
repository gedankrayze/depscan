# DS-106: Preserve Pipfile.lock sources and custom package categories

- **Status:** Closed
- **Priority:** P1
- **Scope:** Pipenv lock parser

## Evidence

`python.rs::parse_pipfile_lock` ignores `_meta.sources` and each package's `index`,
`git`, `file`, and `path` when a version exists. Such packages become public PyPI/OSV
coordinates, which can disclose private names and attach unrelated public findings.
It skips source-only packages entirely and visits only `default`/`develop`, omitting
custom categories such as `docs`. Pipenv documents these fields and categories in
[its Pipfile reference](https://pipenv.pypa.io/en/latest/pipfile.html).

## Acceptance criteria

- Enrich only source-proven PyPI packages; retain other records without exposing URLs.
- Include custom categories conservatively, with unknown development classification.
- Validate resolved PEP 440 pins and malformed category/source metadata.
- Cover public/private/missing/ambiguous indexes, source-only entries, custom
  categories, and same-coordinate public occurrences with parser regressions.

## Resolution

- Extracted Pipenv parsing into a cohesive `python/pipfile.rs` module, reusing
  Python name/version/index validation. All Rust files remain within 400 lines.
- Resolved index eligibility from uniquely named metadata sources. Missing,
  unknown, private, or ambiguous index evidence cannot become public coordinates.
- Retained source-only records with a nonregistry placeholder instead of a URL.
  Parsed all custom categories with conservative unknown scope/directness.
- Preserved deduplication so a separately proven public occurrence remains eligible.

## Verification

- All five `pipfile_provenance` tests pass, covering indexes, source-only records,
  categories, malformed pins/shapes, duplicate source names, and public duplicates.
- Existing schema-context, Python provenance, and CLI filter tests pass without
  frozen fixture or snapshot rewrites. Release and MSRV gates pass.
