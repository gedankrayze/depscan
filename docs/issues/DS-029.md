# DS-029: Resolve manifest ranges for `latest_matching`

- **Status:** Closed
- **Priority:** P1
- **Scope:** Registry providers / degraded manifest-only freshness

## Evidence

- `crates/depscan-providers/src/lib.rs:851-862` sets `latest_matching` to the registry's unfiltered `latest_stable` whenever `resolved_from_range` is true.
- No provider passes the original npm/Cargo/Python/NuGet range through its ecosystem constraint evaluator.
- A manifest constrained to `^1.2` can therefore report an incompatible 2.x release as the newest matching version.

## Acceptance criteria

- Preserve the original manifest constraint separately from a resolved version.
- Compute `latest_matching` by filtering registry releases with the ecosystem's real constraint semantics (npm SemVer, Cargo requirements, PEP 440 specifiers, and NuGet ranges/floating versions).
- `latest_stable` remains the unconstrained current stable; the two fields are never conflated.
- Invalid/unsupported ranges produce a visible per-package error and `None`, not an invented match.

## Verification

- Add per-ecosystem table tests with a latest stable outside the declared range, prereleases, exclusions, and invalid ranges.
- Add provider fixtures asserting distinct `latest_stable` and `latest_matching` values.

## Resolution evidence

- `Package::manifest_constraint` now preserves both the exact manifest spelling and a separately normalized evaluator form. Manifest parsers populate it for npm, Cargo, PEP 440, and NuGet constraints; resolved lockfile coordinates remain unchanged.
- `depscan-core::latest_matching_version` evaluates npm ranges with `js-semver` 0.3.0, Cargo requirements with `semver::VersionReq`, Python specifiers with `pep440_rs::VersionSpecifiers`, and NuGet intervals/floating patterns with four-part and prerelease-aware NuGet precedence. Invalid or unsupported constraints return `VersionConstraintError` rather than a partial or unconstrained match.
- Each registry provider filters its actual published-version set, excluding yanked PyPI/crates.io releases, while retaining the provider's independent unconstrained `latest_stable`. The fixture matrix in `crates/depscan-providers/tests/fixtures/registry-ranges.json` proves distinct values for all four ecosystems and a visible invalid-range provider error.
- Table output labels manifest-only resolutions and prints the source constraint, `latest_matching`, and `latest_stable`. JSON schema version 4 retains raw and normalized constraint provenance; renderer tests cover both fields and the two distinct latest-version values.
- On 2026-08-19, after rebasing onto DS-030, Rust 1.97.1 passed `cargo fmt --all -- --check`, all 236 workspace/all-target tests, and `cargo clippy --all-targets -- -D warnings`. Rust 1.95.0 passed the same 236 locked workspace/all-target tests with `cargo +1.95.0 test --workspace --all-targets --locked`.
