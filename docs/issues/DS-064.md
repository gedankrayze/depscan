# DS-064: Use full-width held-handle identity at filesystem trust boundaries

- **Status:** Closed
- **Priority:** P1
- **Scope:** Shared filesystem identity / CLI config and output / provider cache and offline dump integrity

## Evidence

- The CLI's capability-safe config reads and confined output publication, plus provider cache-root,
  ownership-sentinel, sync, and offline-dump revalidation, compare identities with
  `same_file::Handle`.
- On Windows, `same-file` 1.0.6 identifies objects with the 64-bit file index returned by
  `GetFileInformationByHandle`. Its own implementation notes that ReFS uses 128-bit identifiers
  and that distinct objects can therefore compare equal when only the narrower index is used.
- DS-060 independently introduced a retained-handle identity using the full 128-bit
  `FILE_ID_INFO` value. Leaving separate implementations would let security boundaries drift and
  would preserve the narrower comparison in config, report, cache, and offline paths.
- Equality is security-sensitive here: a false match can accept a replacement pathname attachment
  after validation and before bytes are consumed or a temporary output is published.

## Acceptance criteria

- Centralize one workspace-internal, held-handle identity primitive used by parsers, CLI, and
  providers without changing DS-060 requirements include semantics.
- On Unix, compare device and inode obtained from an owned open handle. On Windows, compare the
  volume serial number and every byte of the 128-bit `FILE_ID_INFO` identifier.
- Retain the owned handle inside every identity and keep expected and candidate identities alive
  together during comparison so platform identifiers cannot be reused between observations.
- Fail closed when identity acquisition fails or when the target platform cannot provide the
  required identity.
- Replace all direct security uses of `same_file::Handle`; remove the direct dependency when only
  `walkdir`'s transitive use remains.
- Preserve current capability-relative, no-follow, regular-file, diagnostic, and atomic-output
  behavior across CLI and provider boundaries.

## Verification

- Add shared-primitive tests for distinct files, hard-link aliases, both borrowed and owned
  constructors, and full-width Windows key comparison.
- Add deterministic regular-object replacement tests covering CLI config reads, CLI output
  publication, provider cache-sentinel validation, and offline root/directory/archive/marker
  reads. Retain symlink controls. A platform may deny the replacement; if it succeeds,
  revalidation must reject it.
- Prove there are no direct `same_file` source or manifest uses and that `cargo tree -i same-file`
  reports only the `walkdir` transitive dependency.
- Cross-check the shared primitive and parser consumer for `x86_64-pc-windows-msvc`; run native
  Linux, macOS, and Windows runtime coverage before closing.
- Run the full locked workspace suite on Rust stable and MSRV, exact Clippy, formatting, diff, and
  dependency-audit gates.

## Resolution

- Added a doc-hidden `depscan-core::FileIdentity` primitive with no `Clone` implementation. Both
  constructors retain an owned standard file handle; equality compares private platform keys
  only while the expected and candidate handles overlap.
- Unix keys use `st_dev` plus `st_ino`. Windows keys use the volume serial number plus all 16 bytes
  returned by `GetFileInformationByHandleEx(FileIdInfo)`. The single required unsafe call is
  isolated behind a reviewed safety contract while all other unsafe code in the crate remains
  denied. Other targets return `Unsupported` rather than weakening identity.
- Requirements parsing now imports the shared primitive with its capability-resolution and
  attachment-replay behavior unchanged. CLI config/output and provider cache/offline boundaries
  use the same primitive and preserve their existing no-follow and held-capability checks.
- Direct `same-file` workspace, CLI, and provider dependencies were removed. Its lockfile entry
  remains only because the parser's `walkdir` dependency uses it transitively.
