# DS-064: Use full-width held-handle identity at filesystem trust boundaries

- **Status:** Closed
- **Priority:** P1
- **Scope:** Shared filesystem identity / CLI config and output / provider cache and offline dump integrity

_Closed-record excerpts; original dates and versions apply._

## Evidence

- The CLI's capability-safe config reads and confined output publication, plus provider cache-root,
  ownership-sentinel, sync, and offline-dump revalidation, compare identities with
  `same_file::Handle`.

- On Windows, `same-file` 1.0.6 identifies objects with the 64-bit file index returned by
  `GetFileInformationByHandle`. Its own implementation notes that ReFS uses 128-bit identifiers
  and that distinct objects can therefore compare equal when only the narrower index is used.

- DS-060 independently introduced a retained-handle identity using the full 128-bit
  `FILE_ID_INFO` value. Leaving separate implementations would let security boundaries drift and
  would preserve the narrower comparison in config, report, cache, and offline paths.

## Historical resolution

- Added a doc-hidden `depscan-core::FileIdentity` primitive with no `Clone` implementation. Both
  constructors retain an owned standard file handle; equality compares private platform keys
  only while the expected and candidate handles overlap.

- Unix keys use `st_dev` plus `st_ino`. Windows keys use the volume serial number plus all 16 bytes
  returned by `GetFileInformationByHandleEx(FileIdInfo)`. The single required unsafe call is
  isolated behind a reviewed safety contract while all other unsafe code in the crate remains
  denied. Other targets return `Unsupported` rather than weakening identity.

- Requirements parsing now imports the shared primitive with its capability-resolution and
  attachment-replay behavior unchanged. CLI config/output and provider cache/offline boundaries
  use the same primitive and preserve their existing no-follow and held-capability checks.

- Direct `same-file` workspace, CLI, and provider dependencies were removed. Its lockfile entry
  remains only because the parser's `walkdir` dependency uses it transitively.

## Historical verification

- On macOS, all 30 `depscan-core` tests pass, including distinct replacements, hard-link aliases,
  and both constructors. All 10 focused CLI secure-filesystem tests pass, including config and
  output regular-file replacement denial-or-detection.

- Provider regressions pass for cache-sentinel regular replacement and for both symlink and valid
  regular replacements of the offline cache root, offline directory, archive, and marker.
  Successful swaps fail closed; denied swaps leave the original safe content usable. The original
  cache state and external offline archive and marker bytes are preserved or restored.
