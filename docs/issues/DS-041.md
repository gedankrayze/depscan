# DS-041: Error when an explicitly requested config file is missing

- **Status:** Closed
- **Priority:** P1
- **Scope:** CLI configuration discovery

## Evidence

- `crates/depscan-cli/src/main.rs:344-350` returns default configuration whenever the selected path does not exist.
- This treats an explicit `--config /path/to/missing.toml` the same as an absent implicit root `depscan.toml`, silently dropping the user's intended security thresholds and ignores.

## Acceptance criteria

- Absence of the implicit default config remains allowed.
- An explicit `--config` that is missing, inaccessible, not a regular file, or unsafe to read returns a usage/config error (`10`) naming the path.
- Configuration origin is available in verbose diagnostics.

## Verification

- Add process tests for absent implicit config, missing explicit config, directory path, permission/read failure, symlink policy, and valid explicit config.

## Resolution

- Explicit configuration paths are inspected without following symlinks and must resolve to readable regular files; every failure names the path and exits with code `10` before provider construction.
- Only a missing implicit `<scan-root>/depscan.toml` falls back to defaults. Verbose diagnostics identify whether configuration was explicit or implicit without logging its contents.
- Process coverage exercises the absent implicit default, missing explicit file, directory, read/decoding failure, symlink rejection, and a valid explicit file, including preflight assertions that no provider endpoint is reached.

- `cargo fmt --all -- --check`
- `cargo test --workspace --all-targets` (including 20 CLI process tests)
- `cargo clippy --all-targets -- -D warnings`
