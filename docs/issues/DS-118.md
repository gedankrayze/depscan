# DS-118: Keep issue records below a 500-word soft cap

- **Status:** Closed
- **Priority:** P2
- **Scope:** Historical issue compaction and documentation-size feedback

## Evidence and resolution

The user requested compact existing records as well as new issues. Thirty-nine
closed records exceeded 500 words; the longest contained 1,473. Condensed each
in place using verbatim finding, resolution, and verification excerpts. IDs,
status, priority, and scope are unchanged.

Every compacted record links to its complete original at immutable v2.0.4 commit
`f0464982b972b6303b1609e8d2807e298bcb097e`. The [review index](../reviews/2026-11-10-issue-compaction.md)
records original/current counts and offline retrieval. Old timestamps, pending
publication boundaries, matrices, run IDs, and verbose evidence remain recoverable
without duplicating long reports in the active issue ledger.

Added a 500-word soft-cap checker and contributor guidance. It warns without
failing CI, preserving room for justified security detail. The navigation index
is not an individual issue and is excluded.

## Verification

All 121 individual records are below 500 words; original IDs/statuses and immutable
references are preserved. The corrected count table, 500/501-word boundary tests,
automation checks, and final release gate pass. Historical excerpts do not claim
new runtime proof. No complete historical record is deleted from Git.
