# DS-107: Respect pnpm tarball and Git source provenance

- **Status:** Closed
- **Priority:** P1
- **Scope:** pnpm resolved-package adapter

## Evidence

`node/pnpm.rs` creates enrichable npm packages from semver-shaped package keys but
ignores `resolution.tarball`, `resolution.repo`, and `resolution.type`. An entry
whose version-shaped key points to a private tarball or Git source is consequently
queried against public npm and OSV under an unproven identity.

## Acceptance criteria

- Inspect resolution metadata and disable public enrichment for nonregistry sources.
- Accept canonical public npm tarballs only when name/version and URL agree, reusing
  the existing npm source validator.
- Reject malformed resolution metadata without echoing credentials.
- Retain directness/scope classification and cover public/private/Git controls.

## Resolution

- Reused the npm canonical-tarball validator for pnpm resolution metadata.
  Private/mismatched tarballs and explicit Git/directory sources are retained
  without enrichment. Absent resolution evidence is conservative, not a guess.
- Validated source-field shapes using diagnostics that name the field, not its URL.
  Existing importer/alias/peer directness and scope logic is unchanged.

## Verification

- Both `pnpm_provenance` tests and the existing pnpm v6/v9 importer/scope tests pass.
- An optimized-CLI probe with a credential-bearing private URL plus malformed
  resolution type exits 10, emits no partial report, and leaks no credentials or
  private hostname in its diagnostic.
- Release and Rust 1.96.0 all-target gates pass.
