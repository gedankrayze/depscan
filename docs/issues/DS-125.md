# DS-125: Remove the unmaintained Chrono dependency

- **Status:** Closed
- **Priority:** P2
- **Scope:** Dependency maintenance and timestamp compatibility

## Finding

The fresh RustSec database at `43b5554d9d64ca91c8d0839b7150d4f8ee490cdc`
flags Chrono 0.4.45 under
[RUSTSEC-2026-0543](https://rustsec.org/advisories/RUSTSEC-2026-0543.html).
The advisory is informational/unmaintained, issued 2026-11-17, applies to all
versions, and lists no patched upgrade. It recommends maintained alternatives
Jiff or time; it does not establish a runtime exploit in DepScan.

Chrono is a direct dependency of the core, provider, report, and CLI crates,
with no external reverse dependency in the resolved graph. It represents scan/OSV
timestamps, suppression dates, cache freshness, and CLI duration/date parsing,
including test helpers. Current upstream candidates Jiff 1.0.2 (Rust 1.85) and
time 0.3.55 (Rust 1.88) support the retained Rust 1.96.0 minimum.

## Resolution

With explicit user approval, replace Chrono with Jiff 1.0.2 (`std`/`serde`, no
timezone database). Core owns a concrete UTC `Timestamp` and exports shared date
and fixed-duration types. Callers across four crates use these types; Chrono is
absent from the resolved graph. Public Rust time types change; schema 4 and the
CLI version remain unchanged pending a separately authorized release.

Preserve UTC Z/offset encoding, 0/3/6/9 fractional digits, revision cache keys,
pre-epoch Unix-second flooring, date-only expiry, real-clock suppression policy,
and inclusive TTL boundaries. Validate RFC 3339 offsets before parsing. Leap
seconds, fractions beyond nine digits, and years outside Jiff's supported range
now fail explicitly instead of normalizing or truncating. Existing cache entries
with unsupported timestamps are non-reusable; invalid provider timestamps fail
validation. Frozen fixtures are unchanged.

## Verification and scope

Dedicated core regressions cover wire precision, offsets, arithmetic, rejected
inputs, year bounds, and expiry serialization; provider tests retain fractional
revision identities and nanosecond cache boundaries. Existing CLI tests cover
wall-clock expiry independent of reproducible report time. No advisory ignore or
audit bypass has been added. Fresh requirements/full-lock checks and
`cargo audit --deny warnings` pass (315 dependencies, same database revision).
The native macOS ARM64 release gate and retained Rust 1.96.0 checks/suite pass:
468 tests on each toolchain, one opt-in live test ignored, strict Clippy, packaging,
and optimized CLI. The fresh-cache live self-scan has no vulnerabilities/provider
errors. Require current-head hosted platform checks before integration and record
exact evidence on the delivery PR.
