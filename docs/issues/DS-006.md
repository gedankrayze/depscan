# DS-006: Remove vulnerable `quick-xml` release

- **Status:** Closed
- **Priority:** P0
- **Scope:** Dependency security / .NET XML parser

## Evidence

- `Cargo.toml:42` allows `quick-xml` 0.36 and `Cargo.lock:1374-1375` resolves 0.36.2.
- `crates/depscan-parsers/src/lib.rs:624-648` reaches XML attribute iteration in affected code during `.csproj`/props/config parsing.
- Audit runtime evidence: `cargo audit` reported `RUSTSEC-2026-0194` and `RUSTSEC-2026-0195` as High against this lockfile.

## Acceptance criteria

- Upgrade to a current, non-vulnerable stable `quick-xml` release and migrate APIs without weakening parsing.
- Add malicious/regression XML fixtures for both advisories where applicable.
- No known advisory remains in the dependency graph, and self-scan severity/exit behavior is correct after DS-002.

## Verification

- Run `cargo audit` and record a clean result.
- Run .NET parser regression fixtures, the full workspace test suite, and strict Clippy.
- Run `cargo tree -i quick-xml` and confirm only the intended patched version is present.

## Resolution

- Upgraded `quick-xml` from 0.36.2 to 0.41.0, the current crates.io release and the first version patched for RUSTSEC-2026-0194 and RUSTSEC-2026-0195.
- Kept duplicate-attribute checks enabled and made malformed attributes fail closed. A NuGet XML regression places a duplicate after 42 earlier attributes, exercising quick-xml 0.41's linear-time hashed duplicate-check path through depscan's real `attributes()` call.
- Confirmed RUSTSEC-2026-0195 is not reachable in depscan because the NuGet parser uses plain `Reader`, not `NsReader` or `NamespaceResolver`. A 300-namespace-declaration regression succeeds through that plain-reader path, above `NsReader`'s default 256-declaration limit.
- `cargo audit` reported no vulnerabilities, and `cargo tree -i quick-xml` showed only `quick-xml v0.41.0` through `depscan-parsers`.
- Formatting, all 31 workspace tests, and strict Clippy passed with Rust 1.97.1 on 2026-08-19; the required default-toolchain `cargo clippy --all-targets -- -D warnings` gate also passed.
- A fresh-cache self-scan with `--fail-on high` exited `0` and returned no advisories for `quick-xml` 0.41.0.
