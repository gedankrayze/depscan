# DS-001: Repository hygiene and branch governance

- **Status:** Closed
- **Priority:** P1
- **Scope:** Repository / CI governance

## Evidence

- The initial audit found every project file untracked, including `.idea/` and an approximately 3.5 GB `target/` directory; no root `.gitignore` existed.
- `.gitignore:1-24` now describes Rust, JetBrains, and macOS exclusions without hiding source, fixtures, lockfiles, workflows, or issue records.
- `renovate.json:1-5` sets `baseBranches` to `develop`.
- `.github/workflows/pr-policy.yml:3-28` evaluates pull requests into `main` from the trusted base-repository workflow and rejects them unless the head branch is exactly `develop` in the same repository.

## Acceptance criteria

- A root `.gitignore` excludes build artifacts, IDE metadata, and OS metadata without excluding source, fixtures, lockfiles, or issue records.
- Renovate is configured to open/update dependency PRs only against `develop`.
- Repository policy makes `develop` the only accepted source branch for PRs targeting `main`.
- The policy check is configured as required protection for `main`, or an equivalent repository ruleset enforces it.
- `develop` CI runs the normal Rust quality gates, and the governance files are committed without generated artifacts.

## Verification

- Run `git status --short --ignored` and confirm `target/` and `.idea/` are ignored while source and `Cargo.lock` remain trackable.
- Validate `renovate.json` against the Renovate schema and confirm `baseBranches` is exactly `["develop"]`.
- Exercise the PR policy with one PR from `develop` to `main` (allowed) and one from another branch to `main` (rejected).
- Record the repository ruleset/required-check URL or CLI output here before closing.

## Local resolution

- The root `.gitignore` excludes Rust build trees, backup/PDB files, JetBrains metadata, and macOS metadata without ignoring `Cargo.lock`, source, fixtures, workflows, or issue records.
- `renovate.json` extends Renovate's recommended preset and sets the sole `baseBranches` entry to `develop`. Frozen `fixtures/**` inputs are excluded, and Renovate's separate vulnerability-alert PR mode is disabled so it cannot rewrite deliberately vulnerable regression locks; ordinary dependency updates remain enabled.
- `pr-policy.yml` uses `pull_request_target` only for pull requests targeting `main`, so a proposed change cannot replace the policy workflow that evaluates it. The read-only job checks metadata only, never checks out or runs pull-request code, accepts only `gedankrayze/depscan:develop`, and rejects both same-repository feature branches and fork branches named `develop`.
- Normal Rust CI now runs on pushes to both `develop` and `main`, as well as pull requests.
- Every external action in the CI, live-provider, static-artifact, and release workflows is pinned to a full commit. Checkout credentials are not persisted in worktrees that compile or execute repository code. The pinned Rust action revisions resolve to the documented 1.97.1 and 1.95.0 branches; Renovate can maintain these digest pins on `develop`.

## Verification evidence and external boundary

- `actionlint` passes every checked-in workflow, including the pull-request policy. Renovate 39.264.1's `renovate-config-validator` accepts `renovate.json`, and `jq` assertions confirm the sole `develop` base, frozen-fixture exclusion, and disabled alert-driven PR mode.
- A workflow scan finds no external `uses:` reference lacking a 40-character commit digest. Official `git ls-remote` resolution on 2026-08-19 confirmed the pinned checkout v4.3.1 and Rust 1.97.1/1.95.0 revisions.
- Local positive/negative policy simulations accept only the same-repository `develop` source. `git check-ignore` accepts `target/` and `.idea/` while `git check-ignore -q Cargo.lock`, representative source, fixture, workflow, and issue paths all return non-ignored; `git ls-files -ci --exclude-standard` is empty.
- On 2026-08-20 an authorized atomic bootstrap created public `develop` and `main` branches at commit `4ea2907d22e508b0d4969addc1bcea525686d8c1`, and `main` became the default branch. Both remote refs were read back at that exact commit before protection was installed.
- [`main` branch protection](https://github.com/gedankrayze/depscan/settings/branches) now requires a pull request, a strict up-to-date branch, `Require develop as source branch`, all three native `quality` jobs, and `MSRV`. Every required check is bound to GitHub Actions app id `15368`, rather than trusting its name alone. Protection applies to administrators, dismisses stale reviews, requires resolved conversations, and disables force pushes and deletion.
- Repository Actions defaults are read-only, Actions cannot approve pull requests, immutable-SHA pinning is required, and only GitHub-owned actions plus `dtolnay/rust-toolchain@*` are allowed. The tracked workflows use no other third-party action.
- Repository secret scanning and secret-scanning push protection are enabled. They remain active
  alongside read-only default workflow permissions and disabled Actions pull-request approval.
- Vulnerability alerts remain enabled. Automated Dependabot fixes were disabled after their initial main-targeting PRs [#1](https://github.com/gedankrayze/depscan/pull/1), [#2](https://github.com/gedankrayze/depscan/pull/2), and [#3](https://github.com/gedankrayze/depscan/pull/3) were closed and their branches deleted.   `fixtures/e2e/npm/package-lock.json`, `fixtures/e2e/python/pyproject.toml`, or

  the project never installs or executes them, no published crate includes them, and none is a
