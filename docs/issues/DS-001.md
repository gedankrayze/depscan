# DS-001: Repository hygiene and branch governance

- **Status:** Closed
- **Priority:** P1
- **Scope:** Repository / CI governance

_Closed-record excerpts; original dates and versions apply._

## Evidence

- The initial audit found every project file untracked, including `.idea/` and an approximately 3.5 GB `target/` directory; no root `.gitignore` existed.

- `.gitignore:1-24` now describes Rust, JetBrains, and macOS exclusions without hiding source, fixtures, lockfiles, workflows, or issue records.

- `renovate.json:1-5` sets `baseBranches` to `develop`.

- `.github/workflows/pr-policy.yml:3-28` evaluates pull requests into `main` from the trusted base-repository workflow and rejects them unless the head branch is exactly `develop` in the same repository.

## Historical resolution

- The root `.gitignore` excludes Rust build trees, backup/PDB files, JetBrains metadata, and macOS metadata without ignoring `Cargo.lock`, source, fixtures, workflows, or issue records.

- `renovate.json` extends Renovate's recommended preset and sets the sole `baseBranches` entry to `develop`. Root and crate-local regression fixtures are excluded, as are the cargo-dist-generated release workflows whose action pins are updated only through the reviewed generator. Renovate's separate vulnerability-alert PR mode is disabled so it cannot rewrite deliberately vulnerable regression locks; ordinary dependency updates remain enabled.

- `pr-policy.yml` uses `pull_request_target` only for pull requests targeting `main`, so a proposed change cannot replace the policy workflow that evaluates it. The read-only job checks metadata only, never checks out or runs pull-request code, accepts only `gedankrayze/depscan:develop`, and rejects both same-repository feature branches and fork branches named `develop`.

- Normal Rust CI now runs on pushes to both `develop` and `main`, as well as pull requests.

## Historical verification

- `actionlint` passes every checked-in workflow, including the pull-request policy. Renovate 39.264.1's `renovate-config-validator` accepts `renovate.json`, and `jq` assertions confirm the sole `develop` base, frozen-fixture exclusion, and disabled alert-driven PR mode.

- A workflow scan finds no external `uses:` reference lacking a 40-character commit digest. Official `git ls-remote` resolution on 2026-08-19 confirmed the pinned checkout v4.3.1 and Rust 1.97.1/1.95.0 revisions.

- Local positive/negative policy simulations accept only the same-repository `develop` source. `git check-ignore` accepts `target/` and `.idea/` while `git check-ignore -q Cargo.lock`, representative source, fixture, workflow, and issue paths all return non-ignored; `git ls-files -ci --exclude-standard` is empty.
