# DS-040: Reject malformed or unsupported lockfile schemas instead of returning empty

- **Status:** Closed
- **Priority:** P1
- **Scope:** All ecosystem parsers / false-clean prevention

## Evidence

- Multiple parsers return `Ok(dedup(out))` even when their expected top-level structures are absent: npm at `crates/depscan-parsers/src/lib.rs:173-198`, Bun at `221-246`, pnpm at `291-315`, Python at `431-457`, Pipfile at `459-480`, NuGet lock at `604-622`, and Cargo lock at `718-743`.
- A syntactically valid but wrong/new schema can therefore produce zero packages, causing a misleading no-project/clean outcome instead of a parse error.

## Acceptance criteria

- Each parser validates its format discriminator/schema version and required top-level structures before accepting a document.
- Distinguish a legitimately empty dependency set from a malformed, wrong-format, or unsupported-version file.
- Errors include source path, detected/expected format, and safe context; no parser panics on arbitrary input.

## Verification

- Add malformed, wrong-format, empty-valid, missing-section, and future-schema fixtures for every supported source kind.
- Assert exact error class and ensure CLI never reports malformed sources as a clean scan.

## Resolution

- Lock parsers now validate the document root, format discriminator, supported schema version, and required resolved-package collection before extracting coordinates. npm accepts package-lock versions 1 through 3, Bun accepts 0 through 2, pnpm accepts the implemented 6.0 and 9.0 layouts, Pipfile.lock requires spec 6, NuGet accepts versions 1 through 3, and Cargo accepts legacy version 1 plus explicit versions 1 through 4. The existing fail-closed uv version 1 and Poetry 1.0 through 2.1 decoders remain the Python lock boundary.
- A present but empty package/dependency collection remains a valid empty lock. Missing collections, wrong root shapes, malformed required fields and entries, and unsupported future versions return `ParseError::Invalid` with the source path plus detected/expected format context. Legitimate workspace, path, VCS, URL, and other non-registry records retain their existing non-enrichable/best-effort behavior rather than becoming invented registry coordinates.
- Added a checked-in fixture matrix for npm, Bun, pnpm, uv, Poetry, Pipfile, NuGet, and Cargo. Every format has valid-empty, wrong-format, missing-section, malformed, and future-schema cases; realistic non-empty fixtures are re-run through the same boundary, and pnpm 6.0 numeric metadata is covered explicitly.
- A process-level matrix copies an invalid lock for all eight detected source kinds, verifies exit code `10`, no stdout report, source-qualified diagnostics, and failure before provider access. A malformed or unsupported lock can no longer become a clean or unsupported-project result.
