# DS-040: Reject malformed or unsupported lockfile schemas instead of returning empty

- **Status:** Open
- **Priority:** P1
- **Scope:** All ecosystem parsers / false-clean prevention

## Evidence

- Multiple parsers return `Ok(dedup(out))` even when their expected top-level structures are absent: npm at `crates/depscan-parsers/src/lib.rs:173-198`, Bun at `221-246`, pnpm at `291-315`, Python at `431-457`, Pipfile at `459-480`, NuGet lock at `604-622`, and Cargo lock at `718-743`.
- A syntactically valid but wrong/new schema can therefore produce zero packages, causing a misleading no-project/clean outcome instead of a parse error.

## Acceptance criteria

- Each parser validates its format discriminator/schema version and required top-level structures before accepting a document.
- Distinguish a legitimately empty dependency set from a malformed, wrong-format, or unsupported-version file.
- Errors include source path, detected/expected format, and safe context; no parser panics on arbitrary input.

## Verification

- Add malformed, wrong-format, empty-valid, missing-section, and future-schema fixtures for every supported source kind.
- Assert exact error class and ensure CLI never reports malformed sources as a clean scan.
