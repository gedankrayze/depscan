# DS-114: Refresh the complete product dependency graph

- **Status:** Closed
- **Priority:** P2
- **Scope:** Latest stable crate requirements and compatible transitive resolutions

## Evidence

The 2026-10-23 manifest review identifies newer stable requirements for the
capability crates, clap/completions, reqwest, serde_json, js-semver, sha2, toml,
thiserror, Tokio, and the insta test dependency. A fresh `cargo update --dry-run`
also identifies 90 package-resolution changes within the existing Rust 1.96.0
support floor. A root-only outdated check is insufficient evidence for transitive
freshness, so both manifest and full-lockfile checks are required.

## Acceptance criteria

- Check incompatible as well as compatible stable manifest releases.
- Refresh the full graph to the newest versions allowed by supported upstream constraints and MSRV.
- Keep prereleases, frozen scanner fixtures, product version/schema, and release pins out of scope.
- Document unavoidable older transitive versions rather than force incompatible overrides.
- Preserve dependency feature restrictions and pass strict Clippy, tests, MSRV checks,
  architecture/automation checks, and a fresh zero-finding/zero-warning advisory audit.

## Resolution

- Raised 13 existing direct requirement floors: cap-fs-ext/cap-std/cap-tempfile
  4.0.3, clap 4.6.7, clap_complete 4.6.11, reqwest 0.13.5, serde_json 1.0.154,
  js-semver 1.0.1, sha2 0.11.1, toml 1.1.8, thiserror 2.0.21, Tokio 1.54.1,
  and insta 1.49.0. Existing feature restrictions are preserved.
- Refreshed the full lockfile online. The version sets of 89 package names changed;
  obsolete `tinyvec_macros` was removed. Important transitive updates include
  aws-lc-rs 1.18.2, aws-lc-sys 0.46.0, hyper 1.12.0, hyper-rustls 0.27.10,
  rustls-native-certs 0.8.5, rustls-platform-verifier 0.7.1, WebPKI 0.103.16,
  tokio-rustls 0.26.6, tokio-util 0.7.20, and bundled roots 1.0.11.
- Declared the security floors and the test-only shared PKI types explicitly.
  Native production graphs do not gain a bundled trust store; WASM retains its
  patched bundled-root edge. Product version 2.0.3, schema, Rust 1.96.0 support
  floor, release/action pins, and every existing scanner fixture are unchanged.

## Latest-possible boundary

- `cargo upgrade --dry-run --incompatible allow` checks stable major/minor as
  well as compatible releases and reports **46 package entries already latest**,
  with no proposed manifest changes. Prereleases are deliberately excluded.
- A fresh online `cargo update --dry-run` reports **0 packages** to change at
  the highest Rust 1.96.0-compatible resolution. No resolver output is treated
  as proof until its command has completed.
- Older parallel versions remain where upstream requirements demand them:
  wiremock uses base64 0.22.1, cap-tempfile uses rand 0.9.5, fs-set-times uses
  io-lifetimes 2.0.4, and upstream Windows crates require several binding lines.
  These are not forcibly replaced with incompatible globals or local forks.
- The installed `cargo outdated` cannot resolve the renamed `webpki` dependency
  (it prints `Update for webpki could not be found!` despite exiting zero).
  Its result is **not** accepted as freshness evidence; the two fresh registry-backed
  dry runs above cover manifest and full-graph updates instead.
