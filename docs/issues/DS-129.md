# DS-129: Install snapshot exclusions during project setup

- **Status:** Closed
- **Priority:** P2
- **Scope:** Local contributor setup and Git snapshot hygiene

## Finding

Old unreachable Git snapshots captured Rust `target/` outputs while their trees had
no `.gitignore`. Compacting the object store reduced `.git` from approximately
1.1 GiB to 29 MiB. Current ignore rules protect ordinary snapshots, but local
`info/exclude` protection was installed only in one checkout and was absent from
new clones.

## Change

Use the marked build artifact section of `.gitignore` as the sole pattern source.
A checked-in setup helper installs missing patterns into Git's local exclusion
file while preserving existing bytes and using an exclusive lock and atomic
replacement. Linked worktrees resolve the common repository's file. Every local
gate and the trusted Codex session hook runs setup; contributors can also invoke
it directly. Hook setup failures remain visible in session context.

Git does not execute code on clone. The tracked `.gitignore` protects the initial
checkout; the extra local protection activates at setup, first gate, or trusted
session startup. Ignore rules cannot stop explicit force-adds or tracked outputs.

## Verification

Both `bash scripts/dev-gate.sh quick` and `bash scripts/dev-gate.sh full` pass.
The full gate includes exact strict Clippy, 468 passing Rust tests (one opt-in
live test ignored), 25 repository automation tests, and action/release contract
verifiers. Snapshot tests use a fresh clone and temporary index after removing
`.gitignore`; source files remain captured while root/nested outputs stay absent.
Tests cover existing exclusion bytes, repeated setup, shared worktree metadata,
lock contention, refused external symlinks, and valid hook success/failure output.
This preparation evidence is local macOS; subsequent integration CI is recorded
on the develop-to-main PR. This maintenance change does not publish a release.
