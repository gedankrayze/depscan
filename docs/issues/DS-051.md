# DS-051: Reject malformed OSV advisory shapes without false-clean results

- **Status:** Closed
- **Priority:** P1
- **Scope:** OSV hydration / cache validation / offline dumps / provider error semantics

_Closed-record excerpts; original dates and versions apply._

## Evidence

- Hydrated advisory validation required only a matching `id`, a parseable `modified` timestamp, and an `affected` value that was not a non-array. A missing `affected` field therefore became an empty array and could count as a successful non-match.

- Core affected-range evaluation filtered entries by package identity before deserialization. An affected entry with a missing or non-string package ecosystem/name could be silently skipped rather than rejected as untrustworthy provider data.

- Cached hydration documents were reused after checking only `id` and `modified`; malformed security fields could bypass the network validator entirely.

- Offline dump validation checked only `id`, `modified`, and filename alignment before treating the document as scan input.

## Historical resolution

- Added one OSV document validator shared by network hydration, cache reads and compare-and-swap publication, sync validation, offline dump reads, and advisory conversion. Unknown extension fields remain forward-compatible, while every known field consumed by depscan is type-checked.

- `id`, `modified`, optional `published`, and optional `withdrawn` now have explicit validation. `withdrawn` accepts only an RFC 3339 string; absence is the only active-state representation.

- `affected` is required as an array. Every entry must have a real package object with non-empty ecosystem and name strings; known version, range, event, severity, and ecosystem/database-specific fields are validated before identity filtering can occur.

- Query-hit evaluation separately requires a matching affected entry with at least one explicit version or range. This keeps a legitimate empty `querybatch` result usable while preventing empty, wrong-package, and non-evaluable advisory hits from becoming clean results.

## Historical verification

- Provider tests cover every consumed-field shape, missing/null `affected`, malformed package identities, empty/wrong-package/non-evaluable query hits, invalid `withdrawn` values, cache bypass/replacement, network cache non-publication, and mixed valid/hydration/evaluation failures.

- CLI process tests prove malformed cached data exits `30` when it is the sole result, remains a visible soft `osv` error beside a trustworthy package, and malformed offline `affected`, package identity, `null` withdrawal, and boolean withdrawal records cannot produce a clean report.

- `cargo +1.97.1 test --workspace --all-targets --locked`: 321 passed, 0 failed, and the opt-in live-network matrix was the sole ignored test (322 listed tests total).
