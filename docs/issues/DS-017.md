# DS-017: Contain recursive requirements includes to the scan root

- **Status:** Closed
- **Priority:** P1
- **Scope:** Python requirements parser / untrusted filesystem input

## Evidence

- `crates/depscan-parsers/src/lib.rs:482-504` joins `-r`/`--requirement` paths to the parent file without canonicalizing or enforcing containment.
- A repository-controlled requirements file can read arbitrary accessible files outside the requested project, and parsed content can then become network query fields.
- The cycle guard uses the non-canonical joined path (`crates/depscan-parsers/src/lib.rs:486-488`), allowing alias/symlink cycles.

## Acceptance criteria

- Canonicalize the scan root, parent, and included file and reject any include outside the root, including `..` and symlink escapes.
- Use canonical identities for cycle detection and impose bounded include depth/file count/total bytes.
- Return an actionable parse error identifying the rejected include without exposing unrelated file contents.

## Verification

- Add fixtures for valid nested includes, `../` escape, absolute path, symlink escape, alias cycle, deep chain, and resource-limit exhaustion.
- Assert no outside file is opened and no provider request is emitted from rejected input.

## Resolution

- Requirements parsing now anchors the detected root file to its canonical parent and resolves every `-r` and `--requirement` target relative to the canonical including file. Only regular, non-symlink files whose canonical identities remain under that root are opened.
- Canonical identities back an active recursion stack, so alias cycles fail with the complete include chain while a shared file may be included again after its earlier expansion returns.
- Expansion is bounded to 32 include levels, 256 file reads, and 8 MiB of cumulative input. Each file is size-checked before reading and read through a bounded stream so concurrent growth cannot bypass the byte limit.
- Rejected paths, missing/non-file targets, cycles, and resource exhaustion return configuration/parse exit `10` with the include chain. Diagnostics name the rejected path but never include file contents.
