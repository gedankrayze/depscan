# DS-059: Bind Cargo direct and development metadata to exact locked identities

- **Status:** Closed
- **Priority:** P1
- **Scope:** Cargo.lock directness, development reachability, and filtering

## Evidence

- Cargo manifest declarations retain version and source information, but `cargo_direct_dependencies` discards it and collapses every declaration to one `package_name -> dev_only` flag.
- `parse_cargo_lock` applies that name-level flag to every locked package with the same name, regardless of version, source, or dependency-graph position.
- A root development dependency on `dup@1` plus a production dependency whose graph contains `dup@2` therefore marks both locked records direct and development-only. `--no-dev` can hide the production-transitive `dup@2`, while `--direct-only` incorrectly retains it.
- `Package::new` marks both classifications known, so conservative filtering cannot protect the misclassified coordinate.
- Existing Cargo coverage contains unique package names and reduces assertions to a map keyed only by name, so it cannot detect this same-name/multiple-version case.

## Acceptance criteria

- Parse and validate Cargo.lock package identities and dependency references using name, version, and source where required.
- Join workspace/root manifest declarations to exact resolved lock targets; do not transfer direct or development metadata to a different same-name coordinate.
- Compute production and development reachability conservatively; production/build reachability wins when a coordinate is reachable from both production and development roots.
- Mark only actual workspace/root dependency targets direct. Same-name transitive versions remain transitive.
- If an identity or scope cannot be resolved unambiguously, use `direct_known = false` and/or `dev_known = false` instead of guessing.
- Preserve existing Git, path, and alternate-source enrichment restrictions.

## Verification

- Add a realistic lock fixture with root development `dup@1`, a production parent leading to `dup@2`, and exact dependency references.
- Assert `dup@1` is direct/development-only, `dup@2` is transitive/production, and a coordinate reached through both scopes is production.
- Cover renamed, workspace-inherited, Git/path, and ambiguous same-name references.
- Add process-level offline assertions for the exact `--direct-only` and `--no-dev` package sets.
- Run the full workspace suite on Rust stable and MSRV plus exact Clippy.

## Resolution

- Cargo lock parsing now retains an internal source-aware identity for every node and resolves only canonical `name`, `name version`, and `name version (source)` references. Package sources are URL-normalized with Cargo-compatible Git, registry, sparse, and path handling; duplicate identities, dangling or ambiguous references, exact self-edges, malformed reference spelling, and invalid replacement graphs fail closed. Legacy root-only v1 locks, compact v2 references, v1/v2 default-Git edge encoding, precise Git commits, encoded v4 selectors, and `replace` traversal are handled explicitly. Only the exact canonical crates.io lock source remains enrichable, and replaced public placeholders do not make an alternate replacement enrichable.
- Every discovered root/workspace member must map to one exact source-less lock node before the aggregate graph is classified. Duplicate project identities fail closed; if any member identity is absent, every lock record retains unknown directness and scope. Exact member outgoing edges are direct, their reachable descendants are transitive, and disconnected records remain unknown. Source-aware classifications are merged to report coordinates only after graph traversal, preserving the `Direct > Unknown > Transitive` lattice.
- Manifest declarations label only the exact outgoing edges of their declaring member. Normal, build, optional, and non-development target declarations seed production; development and target-development declarations seed development. Production reachability wins, then unknown, then development. Incoming scope never flows through a workspace member's mixed lock adjacency; each member independently seeds its own edges, and every member remains a known production project root. Named registries, unverified paths, patches/replacements, source collisions, invalid requirements, and other non-exact declaration bindings retain unknown scope rather than guessing.
- Regression coverage uses realistic member nodes and exact lock edges with duplicate names across versions and sources, renamed and inherited declarations, Git/path/registry identities, production and development descendants, mixed-scope coordinates, member boundaries, disconnected records, replacements, malformed graphs, and legacy lock encodings. The offline process regression checks the baseline, `--direct-only`, `--no-dev`, and combined package sets, including conservative retention of unknown records. The Cargo E2E expectation now correctly classifies `regex-syntax` as development-only through its non-member development parent.

## Validation evidence

- The complete parser suite and focused Cargo lock-identity, CLI filter/configuration, and offline E2E regressions passed on Rust 1.97.1.
- Rust 1.97.1 passed `cargo test --workspace --all-targets --locked`: 395 tests passed and the one opt-in live-provider test was intentionally ignored.
- Rust 1.95.0 passed `cargo test --workspace --all-targets --locked` with the same 395 passing tests and one intentional ignore.
- The exact required `cargo clippy --all-targets -- -D warnings` command passed. `cargo fmt --all -- --check` and `git diff --check` also passed before commit.
