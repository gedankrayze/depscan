# DS-030: Enforce offline dump age and use cached registry metadata

- **Status:** Closed
- **Priority:** P1
- **Scope:** Offline mode / cache policy

_Closed-record excerpts; original dates and versions apply._

## Evidence

- Sync writes `*.synced-at` at `crates/depscan-providers/src/lib.rs:650-656`, but `OsvOffline::query_blocking` at lines `526-613` never reads or validates it.

- `crates/depscan-cli/src/main.rs:225-250` constructs a cache policy, then unconditionally replaces all offline freshness results with an empty map instead of reading usable cached registry entries.

- `--max-cache-age` therefore does not guard OSV dump age, and offline scans cannot return registry freshness even when cached metadata exists.

## Historical resolution

- `OsvOffline` now reads the `*.synced-at` marker paired with every required ecosystem archive against one captured UTC time. Missing, malformed, future-dated, symlinked, and non-file markers fail visibly and direct the operator to `depscan sync`; the offline directory is also required to be a real directory inside the selected cache.

- With no explicit age limit, an archive older than seven days remains usable but emits a structured warning. `--max-cache-age` replaces that warning-only default with a hard maximum: an older dump is rejected before any advisory entry is evaluated.

- `RegistryOffline` has no HTTP client and reads only the existing content-addressed registry cache. It reuses the same npm, PyPI, NuGet, and crates.io response validation and version-selection functions as the online provider. The normal six-hour registry TTL applies by default, while an explicit `--max-cache-age` selects the older-data tolerance for an air-gapped scan.
