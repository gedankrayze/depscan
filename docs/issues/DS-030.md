# DS-030: Enforce offline dump age and use cached registry metadata

- **Status:** Open
- **Priority:** P1
- **Scope:** Offline mode / cache policy

## Evidence

- Sync writes `*.synced-at` at `crates/depscan-providers/src/lib.rs:650-656`, but `OsvOffline::query_blocking` at lines `526-613` never reads or validates it.
- `crates/depscan-cli/src/main.rs:225-250` constructs a cache policy, then unconditionally replaces all offline freshness results with an empty map instead of reading usable cached registry entries.
- `--max-cache-age` therefore does not guard OSV dump age, and offline scans cannot return registry freshness even when cached metadata exists.

## Acceptance criteria

- Parse and validate each dump's age; warn above the default seven-day age and enforce the documented `--max-cache-age` behavior.
- Missing, future, or malformed timestamps are handled visibly and safely.
- Offline registry lookup reads cache only, performs no network requests, respects maximum age, and reports stale/missing entries as `Unknown` with an explicit reason.
- Offline mode has a network-deny integration test.

## Verification

- Test fresh, stale, missing, malformed, and future dump markers with a controlled clock.
- Preseed fresh/stale registry cache entries and assert offline results and warnings without any mock-server request.
