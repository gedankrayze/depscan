# DS-074: Modularize CLI architecture and isolate CLI tests

- **Status:** Closed
- **Priority:** P2
- **Scope:** `depscan-cli` command ownership, security boundaries, file size, and test organization

## Evidence

- `src/main.rs` had grown to 1,439 lines and combined the binary bootstrap, command model,
  configuration, scan orchestration, policy evaluation, command dispatch, and unit tests.
- `src/secure_fs.rs` was a 1,062-line security-sensitive aggregation of root capabilities,
  configuration reads, output publication, path validation, race hooks, and tests.
- The 3,413-line exit-code harness and the 725-line tool-fallback harness mixed unrelated process
  contracts in single files. The 490-line E2E matrix combined fixtures, execution helpers, and cases.

## Acceptance criteria

- Keep `main.rs` as a small binary bootstrap while giving configuration, scan orchestration,
  policies, command dispatch, external-tool capture, vulnerability planning, and secure filesystem
  concerns explicit module ownership.
- Split secure configuration reads, output publication, path validation, and race tests into
  focused audit boundaries without weakening capability-relative behavior.
- Move unit tests out of production files and split integration harnesses by behavior while
  preserving process contracts, byte snapshots, platform gates, and the ignored live boundary.
- Keep every CLI Rust file at or below 400 lines, with any future exception explicit and reviewed.
- Pass the CLI and workspace all-target suites, exact Clippy, formatting, and diff checks.

## Verification

- Run `cargo +1.97.1 test -p depscan-cli --all-targets --locked`.
- Run `cargo +1.97.1 test --workspace --all-targets --locked`.
- Run `cargo clippy --all-targets -- -D warnings`.
- Run `cargo fmt --all -- --check` and `git diff --check`.
- Audit every Rust file below `crates/depscan-cli` and reject files over 400 lines.

## Resolution and evidence (2026-08-20)

- `main.rs` is now an 11-line bootstrap. Command arguments and dispatch, configuration,
  orchestration, policy evaluation, and unit tests live under `src/app/`.
- Secure filesystem code now has separate root-capability, configuration-read, output-publication,
  path-validation, and test modules. External-tool capture/executable handling and vulnerability
  resolution likewise have focused production and test boundaries.
- Exit-code cases are grouped by configuration, filtering, validation, reporting, requirements,
  providers, and CLI contracts. Tool fallback and E2E fixtures are separate from their cases.
- The crate now contains 43 Rust files; the largest is 395 lines and no file needs an exception to
  the 400-line ceiling. The CLI all-target suite passes with 22 unit tests, 88 non-live integration
  tests, and one intentional live-provider ignore. Exact all-target Clippy, formatting, and diff
  checks pass.
