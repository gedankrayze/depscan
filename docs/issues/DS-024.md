# DS-024: Make workspace crates publishable

- **Status:** Closed
- **Priority:** P1
- **Scope:** Cargo packaging / `cargo install`

## Evidence

- `crates/depscan-cli/Cargo.toml:14-17`, `crates/depscan-parsers/Cargo.toml:10`, and `crates/depscan-providers/Cargo.toml:10` declare internal path dependencies without a version.
- Audit runtime evidence: `cargo package` failed because publishable path dependencies require version metadata.
- The specification promises a `cargo install` path.

## Acceptance criteria

- Every published internal dependency declares a compatible version alongside `path`, or non-published crate boundaries are redesigned intentionally.
- Package include/exclude metadata ships all required README/license/source assets and no local/generated artifacts.
- A clean packaged CLI can resolve only registry artifacts and install successfully.

## Verification

- Run `cargo package --workspace` (or the documented publishable subset) with verification enabled.
- Inspect each `.crate` file list and install the packaged CLI into a temporary `CARGO_HOME` without workspace path access.
- Run the installed binary's `--help` and a fixture smoke scan.

## Resolution

- Declared all five workspace members as crates.io packages with inherited repository, homepage, README, dual-license, keyword, category, author, MSRV, and publish metadata. Each package also has a crate-specific description.
- Centralized the four internal crate coordinates in `[workspace.dependencies]`. Every coordinate now carries both the local development `path` and the compatible `1.1.0` registry requirement; member manifests inherit those definitions, so release-version updates have one source of truth. Cargo's normalized package manifests contain only registry version requirements and no internal dependency paths.
- Added explicit package allowlists. Library archives contain their source, while parser and CLI archives also contain the integration tests and fixtures they need; Cargo's required manifest/lock metadata, the shared README, and a complete dual-license file are included automatically or explicitly. Build output, repository audit documents, IDE state, and other workspace-local files are absent.
- Added a combined root `LICENSE` containing the complete MIT and Apache-2.0 texts and included an identical copy in every crate archive. The SPDX expression remains `MIT OR Apache-2.0`, and the packaged README's relative license link therefore resolves inside every archive.
- Documented both registry and source-checkout installation. The registry package remains `depscan-cli` and installs the user-facing `depscan` executable.
- `CARGO_HOME=<empty-disposable-directory> cargo +1.97.1 package --workspace --locked` packaged and verified all five unpublished crates through Cargo's generated temporary registry without warnings: core 9 files, parsers 80, providers 7, report 7, and CLI 8. The empty Cargo home ensured that no earlier local build of the same unpublished version could be reused. Tar inspection confirmed that every archive contains `Cargo.toml`, `Cargo.lock`, `README.md`, `LICENSE`, and only its allowed source/test assets; normalized internal dependencies contained `version = "1.1.0"` and no `path` key.
- Copied those five `.crate` files into a disposable registry and installed `depscan-cli =1.1.0` with `--locked` into an empty temporary `CARGO_HOME`. The install log downloaded all four internal libraries from that registry, then built and installed `depscan`; it had no workspace path dependency. The installed binary's root help succeeded, and an online scan of a copied Rust fixture reported `2 packages | 0 vulns | 1 outdated`.
- Rust 1.97.1 formatting and all 218 locked all-target tests passed, as did the exact `cargo clippy --all-targets -- -D warnings` gate. Rust 1.95.0 passed the same 218 locked all-target tests.
