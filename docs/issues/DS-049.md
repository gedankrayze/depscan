# DS-049: Deliver the M6 composite GitHub Action

- **Status:** In progress — the first public release and per-runner release-download matrix remain pending
- **Priority:** P2
- **Scope:** GitHub Actions / release distribution

## Evidence

- Development specification milestone M6 explicitly includes a thin composite GitHub Action; the repository had no root `action.yml` or `action.yaml`.
- The specification's open question chooses only whether the wrapper lives in this repository or a separate one, not whether M6 delivers it.
- A wrapper that accepts a free-form argument string or executes an unverified download would add a CI command-injection or release-integrity boundary.

## Acceptance criteria

- Publish a root composite action that invokes depscan through typed, separately quoted inputs and never evaluates a caller-provided shell command.
- Select only release-supported runner OS/architecture pairs, download from an exact semantic-version tag, verify the paired SHA-256 record before extraction, and reject every unsupported or malformed case.
- Keep package-manager tool execution outside the wrapper's surface; preserve depscan's exit status so finding and provider failures fail the action.
- Run a checked-in `uses: ./` smoke with a test-supplied local binary before publication.
- Make the zero-auth release assets public. If the repository remains private instead, implement and review an authenticated GitHub API download path without forwarding credentials to redirect hosts.
- After the first public release, run the action without the local-binary override on each supported runner family and record the downloaded version, checksum verification, provenance attestation, report, and exit behavior.

## Resolution

- Added root `action.yml` with typed path, ecosystem, format, output, failure-threshold, cache, filtering, and offline inputs. Input values enter fixed environment variables and `run-depscan.mjs` builds a child-process argument array with `shell: false`; no arbitrary argument or tool-execution input exists.
- Added closed Unix and Windows installer matrices for the five release targets. Both require an exact `vMAJOR.MINOR.PATCH` tag, validate a one-record checksum file naming the selected archive, verify the archive against that release checksum before extraction, verify the embedded CLI version, and export the exact verified executable through `DEPSCAN_ACTION_INSTALLED_BINARY` in `GITHUB_ENV`.
- Added an Ubuntu `uses: ./` CI smoke that supplies the locally built release binary, creates a valid offline Cargo fixture cache, runs the composite action, and verifies the produced summary.
- Added a release/CI guard that requires the action's default tag and README example to equal `v` plus the workspace version, rejects direct input interpolation/evaluation, and syntax-checks the runner scripts.
- Documented a minimal read-only workflow and the remaining first-release boundary in the README.
- Kept browser downloads credential-free by design. The repository is now public, satisfying the
  zero-auth visibility prerequisite; the first published release and its real asset-download matrix
  remain the closure boundary.

## Verification

- Validate action metadata and scripts, run the argument-vector driver against the real local CLI with values containing whitespace/metacharacters, and prove invalid typed values fail before the child starts.
- Run `actionlint`, shell syntax/static checks, the local composite-action smoke equivalent, and the normal Rust stable/MSRV/Clippy gates.
- Do not close this issue until a public published tag exercises checksum-verified downloads on Linux, macOS, and Windows.
