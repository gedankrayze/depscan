# DS-067: Compare Cargo fixture provenance under one canonical root

- **Status:** In progress
- **Priority:** P1
- **Scope:** Cargo parser integration-test portability / native Windows quality gate

## Evidence

- After DS-066 cleared the CLI assertions, both native Windows full-suite copies reached the Cargo
  manifest integration harness and failed the same three workspace tests at
  `package.source_file.strip_prefix(root).unwrap()`; the other ten tests in that harness passed.
- Manifest parsing may return canonical source provenance, while Cargo.lock provenance may retain
  its caller spelling. The snapshot helper compared those paths with a fixture root built from
  `CARGO_MANIFEST_DIR` without first normalizing both operands.
- Windows canonical paths use an extended prefix, so canonical and caller-spelled paths can
  identify the same directory but cannot be compared lexically with `strip_prefix`.

## Acceptance criteria

- Canonicalize the expected fixture root and every returned source path before relativizing them.
- Preserve the exact source-provenance snapshots and workspace/member equivalence assertions.
- Serialize already-relativized fixture components with a stable `/` delimiter so the same JSON
  snapshot remains exact on Unix and Windows without rewriting parser provenance.
- Do not change parser behavior or weaken a path comparison to string containment.
- Pass the complete Cargo manifest integration harness and exact all-target Clippy locally and in
  the protected native Windows quality job.

## Verification

- Run `cargo test -p depscan-parsers --test cargo_manifest --locked`.
- Run `cargo clippy --all-targets -- -D warnings`.
- Run `cargo fmt --all -- --check` and `git diff --check`.
- Record a successful native Windows full-suite rerun before closing.
