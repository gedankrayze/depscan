# DS-094: Assert toolchain pin consistency across workflows

- **Status:** Closed
- **Priority:** P2
- **Scope:** CI policy verification

## Evidence

- The 2026-08-21 review counted nine workflow references encoding Rust 1.97.1 (pinned
  `dtolnay/rust-toolchain` commits and comments) beside `rust-toolchain.toml`. A toolchain bump
  must touch all of them; nothing currently fails when one site is missed, and Renovate ignores
  two of the workflows.

## Acceptance criteria

- `scripts/verify-ci-policy.sh` (or a sibling verifier already run by CI and the dev gate)
  fails when any workflow's toolchain version comment disagrees with `rust-toolchain.toml`,
  including an intentional exception list for the MSRV job's 1.95.0 pin.

## Verification

- Verifier passes on the current tree; a branch experiment changing one comment fails it.

## Resolution

- `scripts/verify-ci-policy.sh` now derives the channel from `rust-toolchain.toml` and the
  MSRV from `Cargo.toml`, requires at least one pinned `dtolnay/rust-toolchain` use, and fails
  when any pin's version comment matches neither value. The check runs in CI's automation
  policy step and in every dev-gate mode. The version comment is the audited half of each
  SHA pin (Renovate keeps SHA and comment in step), so comment consistency is the right
  tripwire for a missed bump.

## Local verification evidence

- Current tree passes (exit 0). Mutating one workflow comment to `1.96.0` fails with exit 1
  naming the offending line; restoring it returns exit 0. The MSRV job's `1.95.0` pin is
  accepted via the derived exception.
