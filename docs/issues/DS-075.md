# DS-075: Enforce repository-wide Rust module boundaries

- **Status:** Closed
- **Priority:** P2
- **Scope:** Core/report modularity, repository file-size policy, and unit-test placement

## Evidence

- After the provider, parser, and CLI phases, `depscan-core/src/lib.rs` still contained 1,005
  lines, `depscan-report/src/lib.rs` contained 916 lines, and core OSV/constraint implementations
  remained above the intended module ceiling.
- Core NuGet, file-identity, and Poetry-constraint unit tests still lived inline with production
  implementations.
- The earlier 400-line audits were manual and crate-specific, so a future aggregation could pass
  compilation, tests, and Clippy without preserving the intended architecture.

## Acceptance criteria

- Keep core and report public APIs at their crate roots while extracting cohesive domain,
  rendering, version, scan-document, provider-trait, and error modules.
- Place executable unit tests in dedicated `tests.rs` or `tests/` modules.
- Reject every Rust file below `crates/` that exceeds 400 lines; maintain no exception list.
- Enforce both rules in normal pull-request CI and release quality, and guard that workflow wiring.
- Pass the full workspace all-target suite, exact Clippy, formatting, workflow, and diff checks.

## Verification

- Run `bash scripts/check-rust-architecture.sh`.
- Run `cargo +1.97.1 test --workspace --all-targets --locked`.
- Run `cargo clippy --all-targets -- -D warnings`.
- Run `cargo fmt --all -- --check`, `scripts/verify-release-workflow.sh`, and `git diff --check`.

## Resolution and evidence (2026-08-20)

- `depscan-core` now exposes its existing API from a 36-line façade backed by focused ecosystem,
  package, finding, scan-document, error, provider-trait, version, constraint, NuGet, OSV, and
  identity modules. Its 30 tests remain green.
- `depscan-report` now exposes its existing render API from a 60-line façade backed by table,
  summary, SARIF, totals, and shared-formatting modules. Its 10 tests remain green.
- Inline executable tests were removed from the remaining production implementations. The
  architecture script checks all Rust files below `crates/`, rejects files above 400 lines and
  tests outside dedicated test modules, and has no allowlist.
- The audit covers 245 Rust files; the largest is 395 lines. Pull-request CI runs the structural
  check once on Linux, release quality runs it once before packaging, and the release workflow
  verifier prevents either invocation from disappearing silently.
- Rust 1.97.1 and the Rust 1.95.0 MSRV each pass 421 tests with one intentional live-provider
  ignore. The exact all-target Clippy command, formatting, action/workflow verifiers, actionlint,
  ShellCheck, RustSec audit (308 dependencies against 1,217 advisories), and all five publishable
  crate package/verification gates pass. Negative probes prove both policy failure modes.
