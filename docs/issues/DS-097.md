# DS-097: Align the unreleased breaking API surface to version 2.0.0

- **Status:** Closed
- **Priority:** P1
- **Scope:** Workspace, action, documentation, and release-version contract

## Evidence

- The latest public release is immutable v1.2.0 at protected-main commit
  `cf5549d40a021dfaf0a5b47e3470bf15025c6f95`.
- Unreleased DS-083, DS-087, and DS-088 changes seal or remove public API and change the public
  CVSS score type from `f32` to `f64`. Their issue resolutions explicitly require the next
  crates.io publication to use a new major version.
- The unreleased workspace still identified itself as 1.2.0 in Cargo metadata, internal registry
  requirements, the lockfile, composite action, installers, README, Markdown self-attribution,
  and tag-bound acceptance workflow.

## Acceptance criteria

- The workspace package version and every internal published-crate requirement are 2.0.0, and
  Cargo.lock contains the same version for all five workspace packages.
- The CLI/action/report-facing version surfaces, README examples, installer diagnostics, and
  release-acceptance tag are v2.0.0/2.0.0 with no stale v1.2.0 production contract.
- Historical issue evidence, dependency fixtures, version-comparison tests, and repository-hook
  attack examples may retain 1.2.0 where it is data rather than the current product version.
- GitHub Action and release-workflow verifiers pass, followed by `bash scripts/dev-gate.sh release`.
- No v2.0.0 tag or release is created during preparation. Publication remains separately
  authorized and must target the reviewed protected-main tip.

## Resolution

- Updated the workspace package and four internal dependency requirements to 2.0.0; Cargo
  regenerated only the five workspace package versions in Cargo.lock.
- Updated the composite-action default, README download/action examples, Unix and Windows
  installer diagnostics, Markdown report version expectation, release-acceptance tag/ref/input,
  and the release verifier's exact tag guards to v2.0.0.
- Extended the action verifier so the README download example and both installer diagnostics must
  stay aligned with the workspace version, rather than relying on review to catch future drift.
- Preserved historical v1.2.0 release evidence and fixture/version-comparator inputs that do not
  claim to be the current product version.

## Verification evidence

- `scripts/verify-github-action.sh`, `scripts/verify-release-workflow.sh`,
  `scripts/verify-ci-policy.sh`, `scripts/verify-agent-automation.sh`, Actionlint, ShellCheck,
  the focused report suite, the Rust architecture gate, and `git diff --check` pass on the
  frozen local ticket tree.
- `bash scripts/dev-gate.sh release` passes under Rust 1.98.0, including formatting, the exact
  `cargo clippy --all-targets -- -D warnings` contract, the complete workspace/all-target test
  suite, all five crate package/verification passes, and an optimized `depscan-cli` 2.0.0 build.
- The verified cargo-dist 0.32.0 binary passes `dist generate --check`; its exact
  `dist plan --tag v2.0.0 --output-format=json` announces `depscan-cli` 2.0.0 and matches the
  reviewed 16-file release asset contract byte-for-byte. The remote `v2.0.0` tag is unused.
- Live read-only preflight confirms immutable releases are enabled and the active `v*` tag
  ruleset rejects update/deletion without bypass actors. No tag, release, commit, push, merge, or
  repository-setting mutation occurred during this preparation. Native protected-branch CI and
  an eventual tag-driven release remain separate evidence owned by DS-096 and DS-093.
