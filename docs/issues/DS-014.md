# DS-014: Follow OSV per-query pagination

- **Status:** Closed
- **Priority:** P1
- **Scope:** Online OSV provider

## Evidence

- `crates/depscan-providers/src/lib.rs:286-313` reads only `results[].vulns` and ignores `results[].next_page_token`.
- The query builder has no page-token field, so packages with more results than one page can be reported incompletely.

## Acceptance criteria

- Follow each result's `next_page_token` until exhausted while preserving the package/result association.
- Deduplicate advisory IDs across pages and protect against repeated tokens/infinite loops.
- Page failures fail the affected batch visibly and do not cache a partial advisory list as complete.
- Pagination respects concurrency and request limits.

## Verification

- Add `wiremock` tests for independent tokens on multiple packages, duplicate IDs, repeated-token defense, and a later-page failure.
- Assert the cached query result contains the complete deduplicated ID set only after all pages succeed.

## Resolution

- Batch response parsing now validates and retains each result's optional `next_page_token`, and continuation requests contain only the queries that still have pages, with their individual `page_token` values as required by the [OSV querybatch pagination contract](https://google.github.io/osv.dev/post-v1-querybatch/#pagination).
- Advisory IDs are accumulated in deterministic sets per original query, so duplicates within or across pages are removed without losing package/result association. Requests remain at or below the 1,000-query batch limit and share the provider's 16-request semaphore with hydration.
- Repeated tokens fail visibly, and a 1,000-page per-query ceiling also prevents an endless sequence of unique tokens. Query cache writes happen only after every continuation page for that batch succeeds, so a malformed/repeated token or later HTTP failure cannot publish a partial ID list as complete.
- Wiremock coverage exercises two independently paginated packages, shrinking continuation batches, cross-page duplicates, complete cache contents, repeated tokens, invalid token shapes, and a later-page HTTP failure with no query cache entry.
- Verified with 120 workspace all-target tests on Rust 1.97.1 and locked Rust 1.95.0, plus exact `cargo clippy --all-targets -- -D warnings` and formatting checks.
