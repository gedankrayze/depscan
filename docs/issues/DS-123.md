# DS-123: Refresh const-oid and compatible PKI types

- **Status:** Closed
- **Priority:** P2
- **Scope:** Compatible dependency maintenance; develop delivery only

## Finding

After v2.0.5 publication, the fresh pre-push check detected const-oid 0.10.3
and correctly rejected the stale lockfile. The user authorized the update,
regression checks, commit, and delivery through `develop`. During qualification,
the same check found the new compatible rustls-pki-types 1.16.0 release; the
standing latest-dependency rule requires including it before pushing.

The native dependency path is `depscan-providers` → `sha2 0.11.1` →
`digest 0.11.3` → `const-oid`. The OID feature is enabled through SHA-2's
default features. Upstream 0.10.3 adds the RFC 6211 Algorithm Protection OID
and rejects BER arcs above `u32` instead of truncating them; see the
[tagged changelog](https://github.com/RustCrypto/formats/blob/const-oid/v0.10.3/const-oid/CHANGELOG.md).
Its Rust 1.85 minimum and rustls-pki-types' Rust 1.60 minimum remain below
DepScan's Rust 1.96.0 support floor.

## Resolution

Update const-oid and rustls-pki-types versions/checksums in the root lockfile,
and raise the existing rustls-pki-types workspace requirement to 1.16.0.
Keep features, product version 2.0.5, schema 4, and frozen scanner fixtures
unchanged. No new tag or release is part of this delivery.

## Verification

Cargo's precise update, package metadata, and reverse feature graph establish
the selected version, checksum, MSRV, and production dependency edge. Regression
coverage includes the existing incident-chain/root-fingerprint/valid-chain TLS
controls, the complete deterministic Rust suite, formatting, exact strict Clippy,
and repository policy/action/workflow verifiers. Fresh stable-requirement,
complete-lockfile, and advisory checks precede the authorized source push.

Exact local results and current-head hosted native/MSRV/static/release-quality
checks are recorded on the delivery PR. Both existing stashes remain preserved;
the historical DS-001 governance stash is inspected without applying it.
Closure covers the qualified dependency refresh, not a new public release.
